# 资讯日更 · 端到端演示（真实跑通记录）

> 本文件由 `scripts/demo_daily_news.py` 真实调用运行面 `:8080` 与管理后台 `:8081` 自动生成。
> 用工作流引擎跑通一个 `daily_news` 实例，对齐 [`资讯日更_全流程.md`](../../../资讯日更_全流程.md) 的十阶段与「主编审 → Van审」双闸。

## 跑法与环境

- 运行面 `:8080`（agent bearer token，文件存储后端 = 阿里云 OSS 公共读）
- 管理后台 `:8081`（人类 JWT，用于签发各角色运行面 token）
- 工作流 `daily_news`：10 阶段、`dispatch_mode=manual`、中枢=主编(`editor`)；每阶段默认双闸：**闸1 主编审（`editor` 普通闸）→ 闸2 Van审（`van`，主编代录）**。
- 产出为贴合各阶段的占位文件，真实上传 OSS（下方 `download_url` 均为永久公共直链，可直接打开）。
- 交付路径含**任务ID（=run_id）**：`csw/资讯日更/{日期}/r{run_id}/{阶段序号-阶段}/资讯日更_责任方_日期_r{run_id}_v{版本}.zip`——同一天可触发多次（`subject` 唯一约束已放宽），靠 run_id 区分、各自独立留底。

## 规则（摘自全流程）

- 阶段间线性：公众号 03–06 整段过审后才进小红书 07–10；公众号成品 = 母内容源，小红书是二次拆解。
- 每段产出 → 主编审 → Van审；不过即**退回（告知方向+位置，不代改）并升版本重做**。
- 主编是唯一对接 Van 的人，只审核/合成/派工；Van 人工无 token，其闸由主编代录。
- 合流阶段（05 公众号成品 / 09 小红书成品，责任=主编）由引擎**自动派工给主编自己**。

## 六、本次跑通验证到的引擎护栏

- **双闸顺序**：每段固定 闸1 主编审（`editor` 本人）→ 闸2 Van审（`van`，`relayed_by_hub`，主编代录）；越级无法通过。
- **退回升版本**：03 闸2 Van审 reject（必填方向+位置）→ task `returned` → 文案重做提交 v2 → 双闸通过；版本 v1→v2 单调递增、各版留底。
- **合流自动派工**：05 / 09（`is_merge`，责任=主编）就绪即由引擎自动派工给主编，日志中无「主编派工」行。
- **上游自动预填**：每段派工单的上游链接由引擎据依赖阶段已通过产出自动填入（即上一段的 OSS download_url）。
- **内容寻址去重**：产出按 sha256 寻址，不同产出 = 不同 OSS 对象（本次 11 个），相同内容则去重为同一对象。
- **OSS 公共直链**：`download_url` 为永久公共 URL，无需鉴权 / 签名即可下载（抽样 HTTP 200 验证）。
- **全部阶段 passed → run done**：10 / 10 passed，实例自动置 `done`。

> 注：演示由脚本自动连续执行，故 timeline 时间集中在 1–2 秒内；真实运行中各段跨时较长。
