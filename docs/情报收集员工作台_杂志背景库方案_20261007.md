# 情报收集员工作台 · 杂志背景库方案

日期：2026-10-07（10-07 晚按 review 改第 2 版）｜状态：方案已定，未动工（动工时间由用户决定）｜涉及：`~/project/csw-kb`（刊译台）、`csw-task/csw-collector`（工作台后端）、`csw-task/csw-collector-web`（工作台前端）

把刊译台加工好的日文杂志图文（扫描 PDF → 中文译文 + 商品表 + 裁图）导入工作台知识库，作为**杂志背景**一类材料，支持文字检索与以图搜图。刊译台不再导入 llm_wiki。

### 2.3 批量导入的处理

| 问题 | 处理 |
|---|---|
| 导入白名单 | 刊译台 `import_roots` 现为 `/data/magazines`。**把 `/opt/goout` 加进白名单直接读**，不复制 24 GB（根分区已用 74%、剩 227 GB；产出仍写 `/data/kanyitai`，`/data` 剩 4.8 TB）。`/opt/goout` 只读，不在里面写任何东西 |
| 刊名与期号 | 文件名不足以给出刊期（别册只有 Vol 号）。建一份 `catalog.csv`（`book_key` → 系列、期号、刊期、是否合本），正刊从文件名自动生成，别册刊期留空待补（留空时 `published_at` 为空，不阻塞入库）。`book_key` **沿用刊译台按文件名派生的键**（`GO OUT 2025.03.pdf` → `GO-OUT-2025.03`，`tasks.book_key` UNIQUE），清单里系列 / 期号 / 刊期与 `book_key` 都带 |
| 已处理的两本 | 2016.07、2016.08 不重跑，直接从现有产出生成清单（省约 280 万 tokens）；它们的 `book_key` 是 `GoOut-16-07日本` / `goout-16-08日本`，`catalog.csv` 照此登记 |
| ARCHIVE 合本（4 本 705 页） | 内容与各期重复。**跳过（已定）**，单期全部入库后再看是否补（补的话标 `is_archive`，检索时同一商品优先显示单期） |
| 超过 200 页（3 本） | 刊译台原先硬性拒收超过 200 页的 PDF（`s1_import.rs` `MAX_PAGES`）。非合本里超限的有 GO OUT 2023.12（275 页）、CAMP GEAR BOOK Vol.09（232 页）、GO OUT LIVIN' Vol.17（231 页）。**已定：上限改为 500 页**（2026-10-07 改代码，未部署）；自建 mineru-api 处理 200 页以上的实际表现，在首本超限书解析时观察 |
| 超过 200 MB（21 本，不含合本） | 刊译台原先拒收超过 200 MB 的 PDF（`MAX_BYTES`），2025 年正刊多在 350–449 MB。**已定：上限改为 700 MB**（2026-10-07 改代码，未部署）；大文件上传 AutoDL 更慢，计入 §2.2 解析段瓶颈 |
| 2019.12 只有 jpg | 用 img2pdf 按文件名顺序合成 PDF，放 `/data/magazines/`，再走正常流程 |
| 处理顺序 | （已定）由近到远：2026 → 2025 → … → 2014，别册穿插在对应年份后。近年的对当下选题更有用，批次中途停也不亏 |
| 解析段瓶颈 | PDF 上传 AutoDL 约 13 小时：评估刊译台 `upload_downscale` 降采样上传，或把 PDF 预先分批传到 AutoDL 数据盘 |
| 模型代理 | 4.5 天连续调用，代理曾三次整段 503、且有按用户并发上限；刊译台用单独密钥（决策 17），不挤占主编 05:30 正式轮。10-07 探测时单独密钥首次请求也回了 429 `gateway_concurrency_limit`，说明网关限额可能按账号而非按密钥——首本批量时在 05:00–07:30 观察主编侧是否受影响，受影响则加时窗把 `max_model_tasks` 降为 0 |

## 3. 架构

```
刊译台（centos9 /data/kanyitai）                       工作台（centos9 /opt/csw-collector）
  s1–s7 不变                                             kb sync（五路，各报各的）
  s8 上传 OSS ──公网──▶ cws-file/kb/magazine/            ├ sync_magazine：读本机清单 → kb_docs + kb_doc_images + 全文
     写 manifest.jsonl（本机 + OSS 各一份）  ──本机文件──▶ └ 回填任务（让路）：读本机图 → 融合向量 → 纯图向量
  读 ingested.json 显示入库状态   ◀──本机文件──  入库后写 {book}/ingested.json
                                                         检索：杂志文字检索 · 以图搜图 · 品牌页 · MCP
                                                         图片展示：OSS 公开地址
```

- **契约是清单**，工作台不读刊译台的库；反向只有一个 `ingested.json`（条数、融合 / 纯图向量进度、时间），刊译台读文件，不调工作台 HTTP（免账号与 CSRF）。
- 清单放在 OSS 公开前缀下，含全文译文与商品表；按决策 4 可接受（内部使用），这里明说。
- **算向量读本机文件**（两服务同机），不从 OSS 下载，不产生流出费。
- 对象名用图片内容的 blake3：`kb/magazine/{h[:2]}/{h}.jpg`，与 LanceDB `images` 表主键同值；重复上传幂等，跨期重复的广告图只存一份。

## 4. 清单格式 `manifest.jsonl`

每本一份，位置：本机 `{产出目录}/{book_key}/manifest.jsonl`，OSS `kb/magazine/manifests/{book_key}.jsonl`。**清单最后写**：有清单 = 这一本的图已全部上传。每行一张裁图：

| 字段 | 说明 |
|---|---|
| `book_key` | 刊译台文件名派生键，如 `goout-16-08日本`、`GO-OUT-2025.03`；整本对账与清理的键 |
| `magazine` / `issue` / `issue_date` | 刊名、期号、刊期（如 `2016-08-01`） |
| `image_id` | 刊译台 image id（`task_id:pdf_index:seq`，主键稳定） |
| `pdf_index` / `printed_page` / `bbox_pt` | 页与位置 |
| `section_title_zh` | 所属栏目 |
| `category` / `has_content` / `skipped` | 刊译台的图分类与标记 |
| `description` / `md_zh` | 图片描述、中文译文 |
| `products` | 商品数组（brand、name、price_jpy、tax_included、specs） |
| `image_blake3` / `image_url` / `local_path` / `width` / `height` | 裁图；`image_blake3` 参与工作台 `content_hash`（换图触发重算） |
| `page_blake3` / `page_url` / `page_local_path` | 整页图（2400px） |
| `manifest_version` / `generated_at` | 契约版本与生成时间 |

## 9. 护栏（必须有单测）

1. 判断路径（`materials` / 默认检索）召回不到 `magazine_item`；且库里塞 10 万条杂志后，四类检索的 top-K 不丢（验证 LanceDB `only_if` 在当前版本是前过滤）。
2. 以图搜图命中经 `kb_doc_images` 能回到条目与 OSS 地址。
3. `kb purge --book` 后 `kb_docs`、`kb_fts`、`kb_doc_images`、`docs` 表向量一致；被其他书引用的 `images` 向量保留。
6. 杂志检索对同一本书能返回多条（`post_id` 为空，不被 `dedupe_by_post` 合并）。
7. 重新解析一本书后 `sync_magazine` 对账删掉旧 ref_id，不残留。
4. 清单缺失或未写完的书不入库；坏行跳过并计数，不让整份失败。
5. 回填任务在正式轮开始后不再取新批。
