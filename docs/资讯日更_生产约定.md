# 资讯日更 · 生产约定（草案）

状态：**草案，待 Van 一次确认**｜起草：2026-09-15｜依据：《新流程改造_整体优化方案_20260915》§9.2 的建议默认值、《角色与新流程优化方案 v1.1》§1、§9

> 这一页是全体角色与引擎共同读取的**唯一业务约定**。run 触发时的 `inputs` 固定字段与本页一一对应；改本页即改约定，改约定须走一次 Van 确认并更新版本号。
> 标 **[待确认]** 的值是建议默认，Van 确认后去掉标记；未确认前按建议值试运行，但不得据此报告「已具备启动条件」。

版本：v0.1（草案）

## 1. 更新日与资讯窗口

| 项 | 约定 |
|---|---|
| 更新日 | 周一至周五 |
| 资讯窗口 | 周一覆盖最近 72 小时，周二至周五覆盖最近 24 小时 |
| 窗口截止 | **每日 07:00**（北京时间）。周一从周五 07:00 起算，周二至周五从前一天 07:00 起算 |
| 截止后新消息 | 原则上进入下一期；重大例外由主编在选题方案里单独说明 |
| 披露时间 | 以原始披露时间判窗口，转载时间不算；晚抓到的旧内容不得改成当天新闻 |

## 2. 当期数量

| 项 | 约定 |
|---|---|
| 主选 | **6 则 [待确认]** |
| 备选 | **2 则 [待确认]** |
| 每则正文 | 300–500 字，三段：品牌背景 / 核心信息 / 编辑判断 |
| 数量不足 | 在选题方案节点一次说明缺口、已查范围、推荐可用项；已批准条目照常推进，不用旧闻或弱题凑满；改数量或范围由 Van 一次决定 |
| 调整 | 第一周按实测容量调整一次，之后按月复盘调整 |

## 3. 晨间时间表

| 时间（北京） | 交付 / 动作 | 责任 | 引擎对应 |
|---|---|---|---|
| 05:50–06:00 | 检查调用、采集入口、任务队列、发布历史同步 | 调度组件、开发值守、chief | run 触发前自检 |
| 06:00–06:40 | 采集与研究逐条交错，形成短名单 | collector、researcher | `intake` / `shortlist` |
| 06:40–07:00 | 补齐关键事实、历史查重、窗口最后增量 | collector、researcher | 同上 |
| 07:00–07:15 | 主编看图、审价值与整期组合，送选题方案 | chief | `topic` 合流 + 主编自审 |
| **07:15–07:30** | **Van 确认选题 [待确认]** | Van、chief | `topic` Van 闸 |
| 07:30–08:15 | 写作；配图、素材、版式并行；逐条完成即交主编 | writer、collector、designer | `write` / `material` / `design_prep` |
| 08:15–08:35 | 主编整期审核，总标题 / 摘要 / 导读收口 | chief、writer | `fulltext` 合流 |
| 08:35–08:50 | 一轮必要修订或主编定点编辑 | writer、chief | `fulltext` edit 版本 |
| 08:50–09:00 | 完整审核稿与同版图片送达 | chief、notifier | `fulltext` 转审 |
| **09:00–09:15** | **Van 全文审核 [待确认]** | Van | `fulltext` Van 闸 |
| 全文批准后 25 分钟内 | 组版、核对、在授权内保存草稿并回读 | publisher、chief | `wx_layout` → `wx_save` |

**替代排程 [待确认]**：若 Van 无法在 07:15–07:30 到场，选题批准前移到**前一晚 21:00–22:00**，早间只批全文；不采用沉默通过。

**两个时点分开计**：09:00 完整审核稿送达与草稿箱送达是两个目标。Van 在 09:00 后审核时，草稿交付按批准后 25 分钟计；人审等待与内部延误分别标注。

## 4. 人审决定（Van 日常只有这三处）

| 决定 | 对象 | 引擎记录 |
|---|---|---|
| 选题 | 选题方案（含整期组合与缺口） | `topic` 任务 Van 闸，`decision_type=topic_approve`，逐条 `items_json` |
| 完整文案 | 09:00 完整审核稿 | `fulltext` 任务 Van 闸，`decision_type=fulltext_approve` |
| 小红书文本 | 小红书改编稿（仅当期纳入小红书时） | `xhs_text` 任务 Van 闸 |

「保留」「就这条」= 允许写作与素材整理（`approved_write`）；「再看看」「继续研究」= 只开研究（`approved_research`）。措辞不明时主编只问一次受影响范围。

其余环节（原始资料、机械组包、格式核验、模板复用、后台操作）不再请求 Van 审批；首次模板、Van 主动要求的视觉修改、影响表达的重要改版仍交 Van 确认。

## 11. 引擎与 skill（权威来源）

| 项 | 约定 |
|---|---|
| 唯一引擎 | 生产引擎 `https://tasks.aworld.ltd`（agent 侧 `CSW_TASK_BASE_URL`）。任何角色不得构建、运行或连接引擎副本（包括隔离演练端口与临时库）；演练用生产引擎里只带 `local_drill` 授权的 run |
| 流程定义 | `daily_news` v2（十三阶段）。改流程只经管理后台或 `csw-workflow` skill（wfctl）：先草稿、过校验、由 Van 或操作员确认后才激活，修改原因入审计 |
| skill 版本 | `csw-task` skill v3.0.0 起；引擎在 `task` / `my-tasks` 响应里回显最低版本，低于则不开工。skill 以仓库版本只读分发，profile 内禁止改写 |
| 群播报 | 由引擎单写（通知组件）；agent 不发流转播报。通知组件故障时由主编按 skill §5.2 人工补发 |
| 授权 | 以引擎 `run_authorizations` 为准，须附 Van 原话；§6 的默认值在 Van 确认前按「只开本地演练」执行 |
| 进度 | 以引擎进度投影（`GET /runs/{id}/progress`）为准；群内进度卡由引擎在阶段通过等节点发送 |
