# 资讯日更 · 生产约定

状态：**生效 v1.0**（Van 2026-09-15 确认）｜起草：2026-09-15｜依据：《新流程改造_整体优化方案_20260915》第二版、《0915 改造方案核对反馈》、《角色与新流程优化方案 v1.1》§1、§9

> 这一页是全体角色与引擎共同读取的**唯一业务约定**。run 触发时的 `inputs` 固定字段与本页一一对应；改本页即改约定，改约定须走一次 Van 确认并更新版本号。
> 标 **[试行]** 的值按首期三个工作日（9/17、9/18、9/21）实测后修正一次，修正写进变更记录；试行值不是已测得的产能。

版本：v1.0

## 1. 更新日与资讯窗口

| 项 | 约定 |
|---|---|
| 更新日 | 周一至周五 |
| 资讯窗口 | 周一覆盖最近 72 小时，周二至周五覆盖最近 24 小时 |
| 窗口截止 | **每日 07:00**（北京时间）。周一从周五 07:00 起算，周二至周五从前一天 07:00 起算 |
| 截止后新消息 | 07:00 后出现的资讯不进当期主选，记入次日候选；确有必要时主编在选题方案里单列一条「追加建议」，Van 一句话即可追加为条目决定；已批条目照常生产（Van 2026-09-15 确认） |
| 披露时间 | 以原始披露时间判窗口，转载时间不算；晚抓到的旧内容不得改成当天新闻 |

## 2. 当期数量

| 项 | 约定 |
|---|---|
| 主选 | 6 则（可调整的过渡方案，不是永久数量要求） |
| 备选 | 2 则；备选进入正文前须在当期选题批准范围内（备选转主选也是一次条目决定） |
| 每则正文 | 300–500 字，三段：品牌背景 / 核心信息 / 编辑判断 |
| 数量不足 | 晨间选题环节由主编在选题方案里写「缺量说明」四要素：差多少（主选、备选各已有几条合格、各缺几条）；为什么缺（按实际候选归类：有价值资讯偏少 / 采集漏项 / 近期已发布 / 审美或价值不符 / 证据或图片不足）；怎样补（补查来源或方向、责任人、完成时间）；补不齐怎么办（已查范围、剩余缺口、明确建议，由 Van 决定是否接受减量）。已批条目照常推进，不用旧闻或弱题凑数；未经 Van 确认不扩大窗口、不降低标准 |
| 调整 | 调整须记录原因、新目标、生效范围（单期 / 一周 / 长期），经 Van 确认后写进变更记录；某一期缺量不等于降低长期目标 |

## 3. 晨间时间表（首期倒排，[试行]）

| 时间（北京） | 交付 / 动作 | 责任 | 引擎对应 |
|---|---|---|---|
| 前一晚 21:00 起 | run 触发；情报逐条滚动采集、逐条初筛（查近发、读反馈）；模板与头尾图版本确认 | collector、researcher、designer | `intake` / `shortlist` / `design_prep` |
| 06:00–06:40 | 继续滚动；主编开始整理候选与整期组合草稿 | collector、researcher、chief | 同上 |
| 06:40–07:00 | 关键事实补齐、最后增量；07:00 资讯截止 | collector、researcher | 同上 |
| 07:00–07:15 | 处理截止后的最后增量；主编定稿选题方案（含缺量说明、效果记录）送审 | chief | `topic` 合流 + 主编自审 |
| **07:15–07:30** | **Van 选题审核**：成熟候选、预览图、查重结论、推荐理由已备齐，不让 Van 等补资料 | Van、chief | `topic` Van 闸 |
| 07:30 | 主编录入条目决定 → 引擎生成并自动派出写作与配图任务 | chief | 条目决定 |
| 07:30–08:20 | 逐条写作与逐条配图并行；每条完成即交主编逐条审；发布员按已过条目预排版式 | writer、collector、chief、publisher | `write` / `material` |
| 08:20–08:35 | 内容整合：总标题 / 摘要 / 导读收口；必要时定点编辑（≤ 10 分钟） | chief | `fulltext` 主编闸 |
| 08:35–08:50 | 整篇组版（模板已备、条目已预排）；生成 OSS 预览与同版 zip | publisher | `wx_layout` |
| 08:50–09:00 | 主编检查最终完整推文（版式、图文一致、字段清单），通过即送达 Van | chief、notifier | `wx_layout` 主编核版 → 转 Van |
| **09:00–09:15** | **Van 全文终审** | Van | `wx_layout` Van 闸 |
| T = Van 通过时刻 | 引擎自动派草稿保存：保存 + 回读核对 + 必要兼容修复，目标 T+20 分钟内完成 | publisher | `wx_save` |

**两个时点分开计**：09:00 是已排版的完整公众号审核稿送达节点；草稿箱交付从 T 起算。Van 审核等待、系统故障与实际作业耗时分别记录，用户尚未回复不算智能体生产失败。预计失约时在截止前说明具体缺口、处理办法与修正节点，不自动顺延。

**早间审题保留**：不前移到前一晚（Van 2026-09-15 决定，避免遗漏晚间发布的资讯）；不采用沉默通过。

**容量假设（须实测）**：六则逐条写作按每则约 8 分钟估计，写作与逐条审核、预排重叠；实测交不齐时，选项是并行两个写作会话或按 §2 调整数量，不为赶时间降质量。

**小红书接入后**：以 T 为起点，公众号保存回读与小红书改编、选图并行；小红书图文包经主编审、Van 终审后与公众号草稿箱同时送达。接入前另交实测的共同交付时间表。

## 4. 人审决定（Van 日常只有这三处）

| 决定 | 对象 | 引擎记录 |
|---|---|---|
| 选题 | 03 选题方案（含整期组合、缺量说明、效果记录） | `topic` 任务 Van 闸，`decision_type=topic_approve`，逐条 `items_json` |
| 完整推文 | 08 公众号完整审核稿（已套模板、完成排版） | `wx_layout` 任务 Van 闸，`decision_type=fulltext_approve` |
| 小红书图文包 | 12 小红书图文包（接入小红书后） | `xhs_package` 任务 Van 闸 |

「保留」「就这条」= 允许写作与素材整理（`approved_write`）；「再看看」「继续研究」= 只开研究（`approved_research`）。措辞不明时主编只问一次受影响范围。

其余环节（原始资料、机械组包、格式核验、模板复用、后台操作）不再请求 Van 审批；首次模板、Van 主动要求的视觉修改、影响表达的重要改版仍交 Van 确认。保存后台后若需实质修改已批内容或版式，受影响部分交 Van 确认。

## 7. 送达形态

- 09:00 完整公众号审核稿：OSS 上的单页 HTML 预览链接为主——图文内联，展示已套用 CSW 模板与实际版式的完整推文（整篇标题、摘要、封面选图及效果、导语、全部正文与正式配图、头尾图）；同版 zip 留底，群消息同时附 zip。禁止只发 localhost 链接；Markdown 拼成的普通网页、模板引用或图片 zip 都不能代替完整推文预览。
- 草稿保存回读：草稿 ID + 后台截图或摘要 + 回读核对结论（丢图 / 错序 / 样式变化），附内容版本号。
- 小红书（接入后）：文案（标题、导语、长文）+ 按资讯分组的选图包（建议顺序、图文对应、来源记录）；不做封面；本次要求不含后台保存或公开发布。
