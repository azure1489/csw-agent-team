# 情报收集员工作台 · 知识库 MCP 对外方案（远程 HTTP）

> 2026-10-16。用户要求：「需要给非我本机的 codex 客户端使用」，选方案二（HTTPS 接口）。
> 第 10 节已由用户决定（10-16）；代码已实施并提交（cc8501e），**生产未动**。进度见第 13 节。

## 1. 目标与边界

- 让**其他机器上的 codex 客户端**通过公网 HTTPS 查询工作台知识库。不需要 SSH，不需要开新端口。
- 复用现有的 `collector.aworld.ltd`：TLS 证书和 nginx 都是现成的，只加一个路径 `/mcp`。
- **只读**。和本机的 `csw-collector mcp` 用同一套工具实现，只换传输方式。
- 不做：服务端主动推送（SSE 流）、批量请求、写操作、把 `web_search` / `fetch_page` 开放到公网。

## 2. 现状（10-16 实查）

| 项 | 现状 |
|---|---|
| MCP 服务 | `crates/mcpsrv`，自写的最小 JSON-RPC 服务端。`Server::handle_line(&str) -> Option<String>` 与传输方式无关，只接了 stdio（`csw-collector mcp`） |
| 工具 | `kb_search`、`kb_similar_selected`、`memory_lookup`、`kb_magazine_search`、`kb_image_search`、`web_search`、`fetch_page` |
| 关键约束 | 工具返回的 future **刻意不是 `Send`**，因为它借着 `rusqlite::Connection`。axum 的处理函数必须是 `Send`，所以不能把 `Server` 直接放进 `AppState` 调用 |
| 工作台 HTTP | axum，监听 `8090`；`/api/*` 全部要求会话（`require_session`）；`/healthz`、`/metrics` 在 nginx 上返回 403 |
| nginx | `base-nginx` 容器。站点配置由 `csw-task/deploy-collector.sh` 第 267 行起的模板**每次部署重写**，转发到 `172.17.0.1:8090`；`client_max_body_size 64m`；部署脚本自带 `nginx -t` 门禁 |
| 向量服务 | `VectorClient` 可以克隆，克隆出来的共用同一把 GPU 锁（`gpu: Arc<Mutex<()>>`） |
| 审计 | 已有 `audit` 表，记的是人工操作（改档等），会显示在审计页上。MCP 调用量大，**不混进去** |
| 客户端 | codex 0.149 支持 `codex mcp add <name> --url <URL> --bearer-token-env-var <ENV>`（streamable HTTP + Bearer 令牌） |
| 本机实测 | stdio 版握手正常、7 个工具都列出来了；`kb_magazine_search`「snow peak 焚き火台」命中 OUTDOOR GEAR BOOK Vol.05 P.104 等 |

## 3. 总体结构

```
codex（对方机器）
   │  HTTPS  POST /mcp   Authorization: Bearer cswkb_…
   ▼
base-nginx（collector.aworld.ltd，TLS）  location = /mcp → 172.17.0.1:8090
   ▼
csw-collector serve（axum）
   ├─ mcp_router：Origin 校验 → 令牌鉴权 → 限速 → 记审计
   │      │ 把一行 JSON-RPC 发进通道（mpsc），等回复（oneshot）
   │      ▼
   └─ MCP 专职线程（自己的单线程 runtime）
          Server（只装对外允许的工具，按令牌的权限范围过滤）
          ├─ 自己的 rusqlite 连接、向量库句柄、别名表、分词器
          └─ VectorClient：**克隆工作台那份**，共用 GPU 锁
```

- **为什么用专职线程**：`mcpsrv` 一行都不用改；`!Send` 的约束留在线程里，HTTP 处理函数只传字符串。
- **代价**：所有 HTTP 来的 MCP 请求排一个队，顺序处理。一次以图搜图约 1 秒，同时到的其他请求要等。几个客户端用没问题；客户端多了，再把专职线程扩成小池（每个线程各开一个连接），列为后续项。

## 4. 传输层（Streamable HTTP，2025-06-18 版的最小子集）

| 请求 | 处理 |
|---|---|
| `POST /mcp`，内容是带 `id` 的单条 JSON-RPC 请求 | 交给专职线程，回 `200`，`Content-Type: application/json`（规范允许服务端用 JSON 而不是 SSE 回复） |
| `POST /mcp`，内容是通知（没有 `id`） | `202`，空响应体 |
| `POST /mcp`，内容是数组（批量） | `400`。这一版协议已经去掉了批量 |
| `GET /mcp` | `405`：不提供服务端推送流 |
| `DELETE /mcp` | `405`（不维护会话，见下） |
| 不是 JSON、超大 | `400` / `413` |

- **会话**：服务端无状态，`initialize` 时不签发 `Mcp-Session-Id`；客户端带了也忽略。`MCP-Protocol-Version` 头有就记日志，不强制。
- **Origin**：请求带 `Origin` 头、但不是 `https://collector.aworld.ltd` 的，回 403，防止浏览器跨站调用。codex 这类非浏览器客户端不带 `Origin`，不受影响。
- **超时**：单次调用 60 秒，超时回 JSON-RPC 错误，不挂着连接。
- **请求体上限**：8 MB，路由上用 `DefaultBodyLimit` 设置，给 base64 图片留余量。
- **验收门槛**：rmcp 客户端对 `Accept` 头、会话 ID 有没有硬性要求，文档里看不出来，**以本机 codex 0.149 实测为准**（见第 8 节）。实测不过不发版。

## 5. 鉴权、权限、限速、审计

### 5.1 令牌
- 新迁移 `0009_mcp_tokens.sql`：

  ```sql
  CREATE TABLE mcp_tokens (
    id           INTEGER PRIMARY KEY,
    name         TEXT NOT NULL,          -- 给谁用，如「某某的 codex」
    token_sha256 TEXT NOT NULL UNIQUE,   -- 库里只存哈希
    scopes       TEXT NOT NULL,          -- 逗号分隔：magazine,kb,memory
    created_at   TEXT NOT NULL,
    expires_at   TEXT,                   -- NULL = 不过期
    revoked_at   TEXT,
    last_used_at TEXT
  );
  CREATE TABLE mcp_calls (
    id         INTEGER PRIMARY KEY,
    token_id   INTEGER,                  -- 鉴权失败为 NULL
    ip         TEXT NOT NULL DEFAULT '',
    method     TEXT NOT NULL,            -- initialize / tools/list / tools/call / auth_failed
    tool       TEXT NOT NULL DEFAULT '',
    args_brief TEXT NOT NULL DEFAULT '', -- 查询词前 200 字；图片只记字节数与来源，不记内容
    ok         INTEGER NOT NULL,
    ms         INTEGER NOT NULL,
    created_at TEXT NOT NULL
  );
  CREATE INDEX mcp_calls_created ON mcp_calls(created_at DESC);
  ```
- **令牌格式**：`cswkb_` 加 32 位随机串（base62）。明文只在签发时打印一次，之后查不到。
- **命令行**：
  - `csw-collector mcp-token issue <name> --scopes magazine[,kb] [--days 90]`
  - `csw-collector mcp-token list`：只显示 id、名字、权限范围、最近使用时间、是否吊销，不显示令牌。
  - `csw-collector mcp-token revoke <id>`：立即生效，下一次请求就是 401。
- **校验**：取 `Authorization: Bearer …`，算 SHA-256 后查表；没有、已吊销、已过期都回 `401`，带 `WWW-Authenticate: Bearer`。`last_used_at` 最多每分钟写一次，避免每次请求都写库。

### 5.2 权限范围（scope）
| scope | 工具 | 数据 | 敏感度 |
|---|---|---|---|
| `magazine` | `kb_magazine_search`、`kb_image_search` | 杂志译文、商品、裁图 | 低（公司内部资料） |
| `kb` | `kb_search`、`kb_similar_selected` | 已发布条目、范例、成文贴文、03 决定 | 中：含编辑部的选题判断 |
| `memory` | `memory_lookup` | 选题准则卡与案例 | 高：准则卡里是 Van 的原话 |

- **服务端过滤**：`tools/list` 只列令牌有权限的工具；`tools/call` 调用越权工具时，回 `isError` 的工具结果，并记审计。
- **Van 原话一律不出**：HTTP 这份 `KbContext` 的 `send_van_quotes` 恒为 `false`，不管令牌有什么权限。
- **永远不对外**：`web_search`、`fetch_page` 根本不装进 HTTP 那份 `Server`。它们要用模型网关的密钥，而且会替调用方出网。

### 5.3 限速
- 按令牌限速：每分钟 60 次；其中 `kb_image_search` 每分钟 6 次。超出回 `429` 加 `Retry-After`。
- 用内存计数器实现，进程重启就清零，不引新依赖。

### 5.4 审计
- 每次请求写一行 `mcp_calls`，包括鉴权失败的（`token_id` 为空，IP 取 nginx 传来的 `X-Real-IP`）。
- 保留 90 天，由每天的备份任务顺带清理。
- 运维手册写上查询方法：
  `SELECT name, tool, count(*) FROM mcp_calls JOIN mcp_tokens … GROUP BY …`。

## 9. 部署与回滚

**nginx 模板**：在 `location /api/` 前加：

```nginx
location = /mcp {
    proxy_pass http://172.17.0.1:8090;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_read_timeout 120s;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 8m;
}
```

只改 `deploy-collector.sh` 里的模板，**不手改服务器上的 conf**：下次部署会被模板覆盖。

**发版步骤**（每一步都单独征得用户同意）：
1. 先和对端会话 `judgement-ledger-feedback-fixes` 确认 HEAD 里没有它没获同意的提交。
2. 生产库 `sqlite3 .backup` 到 `data/backup/collector-<时间>-pre-mcp-http.db`。
3. `deploy-collector.sh`：发二进制、带迁移 0009，重写 nginx 模板，`nginx -t` 通过后 reload。
4. 发版后验收（第 8 节）。
5. 给第一个客户端签令牌，明文只通过你转交，不进群、不进文档。

**回滚**：
- 工作台退回上一版：迁移 0009 只加了两张表，旧版不读它们，不用回滚迁移。
- nginx 模板去掉 `location = /mcp` 后重新部署；急用时可以直接吊销全部令牌（`mcp-token revoke`），接口立刻全部 401。
