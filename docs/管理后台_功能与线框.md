# 管理后台 · 功能与线框（供页面生成）

> 用途：本文件是「任务流转服务」**管理后台**的完整产品规范，详尽到可直接交给设计/页面生成工具产出页面。
> 数据模型与接口契约见《任务流转服务 · 设计文档》（下称《设计文档》）；本文件聚焦**页面、功能、交互、权限、状态**。
> 后台定位：**人类操作员**用的 Web 控制台（+ HTTP 后台 API），**JWT 登录**，与运行面（agent/skill 用 bearer token）完全分离。后台**定义工作流 / 管理角色成员与 token / 监控运行**，**不操作流程本身**（派工/审核/提交是 agent 经 `csw-task` skill 做的，后台监控只读）。

---

## 0. 设计规范提示（给生成器）

- **整体风格**：简洁、信息密度偏高、以表格和表单为主的后台管理风（类 Linear / Ant Design Pro），亮色主题为主。
- **布局**：左侧固定导航（约 220px）+ 顶栏（约 56px）+ 右侧内容区；内容区最大宽 1200–1440px、卡片化分区。
- **状态色**：
  - 工作流：`draft` 灰、`active` 绿、`archived` 淡灰描边。
  - 运行 run：`active` 蓝、`done` 绿、`paused` 黄、`aborted` 红。
  - 任务 task：`blocked` 灰、`ready` 蓝、`dispatched/in_progress` 蓝、`review` 橙、`passed` 绿、`returned` 红。
  - token：启用 绿、已吊销 灰/删除线、已过期 黄。
- **通用交互**：列表（搜索+筛选+分页+操作列）、详情、表单（行内校验、保存/取消）、危险操作二次确认弹窗、操作后 Toast。
- **空态/加载/错误**：每个列表与详情都需空态插画+引导、骨架屏加载、接口错误提示（含 401 跳登录、403 无权限提示）。
- **响应式**：≥1024px 为主；侧栏可折叠为图标。

## 2. 登录页 `/login`

- **目的**：人类操作员用用户名+密码登录，换取 JWT。
- **数据/接口**：`POST /admin/login {username,password}` → `{access_token, refresh_token, user:{display_name,role}}`；失败 401。
- **线框**：
```
┌───────────────────────────────┐
│        任务流转后台            │
│  ┌─────────────────────────┐  │
│  │ 用户名 [_______________] │  │
│  │ 密码   [_______________] │  │
│  │ [ ] 记住我               │  │
│  │        [   登 录   ]     │  │
│  │  错误：用户名或密码不正确 │  │
│  └─────────────────────────┘  │
└───────────────────────────────┘
```
- **交互**：提交 → 成功存 token（access 内存/refresh httpOnly cookie 或安全存储）→ 跳 /dashboard；失败显示错误。access 过期自动用 refresh 续；refresh 失效跳回 /login。
- **状态**：加载中禁用按钮；锁定/禁用账号提示「账号已禁用，请联系管理员」。

## 3. 仪表盘 `/dashboard`

- **目的**：一眼看清后台与运行健康度。
- **数据/接口**：`GET /admin/overview` → 计数与近期列表。
- **线框**：
```
┌ 概览 ────────────────────────────────────────────────┐
│ [已激活工作流 3] [在跑实例 2] [今日完成 5] [待处理告警 0]│
├ 在跑实例 ───────────────────────┬ 最近激活/改动 ───────┤
│ #10 资讯日更 2026-06-09 ●进行中  │ daily_news v3 已激活  │
│   进度 ③/⑩ 当前:03-公众号内容   │ event_recap v1 草稿   │
│ #11 活动复盘 … ●进行中           │ …                    │
├ 最近审计 ────────────────────────────────────────────┤
│ 10:20 主编bot 触发 daily_news#10 · 09:50 zhang 激活 v3 │
└──────────────────────────────────────────────────────┘
```
- **交互**：卡片点击跳对应列表/详情。
- **状态**：无在跑实例时空态「今日暂无运行实例」。

## 4. 工作流列表 `/workflows`

- **目的**：浏览所有工作流类型及其版本，进入编辑/查看/版本操作。
- **数据/接口**：`GET /admin/workflows?search=&status=` → 列表（按 wf_key 分组、含各版本）。
- **线框**：
```
┌ 工作流 ───────────────── 搜索[____] 状态[全部▼]  [ + 新建工作流 ]┐
│ 名称      │ key        │ 版本 │ 状态    │ 中枢 │ 派工  │ 阶段数│ 操作   │
│ 资讯日更  │ daily_news │ v3   │ ●active │ 主编 │manual │ 10    │ 编辑 ⋮ │
│ 资讯日更  │ daily_news │ v2   │ archived│ 主编 │manual │ 10    │ 查看   │
│ 活动复盘  │ event_recap│ v1   │ ○draft  │ 主编 │ auto  │ 6     │ 编辑 ⋮ │
│                                              分页 ‹ 1/2 ›        │
└──────────────────────────────────────────────────────────────────┘
   ⋮ 菜单：复制为新版本 / 激活 / 归档 / 查看 JSON
```
- **列字段**：name, wf_key, version, status(徽标), hub_role, dispatch_mode, 阶段数, 操作。
- **交互**：
  - `+ 新建工作流` → 新建草稿（key/name/hub/dispatch_mode）→ 进编辑器。
  - `编辑`（仅 draft）→ /workflows/:id/edit；`查看`（active/archived 只读）。
  - `复制为新版本` → `POST /admin/workflows/{id}/clone` 生成 draft 新版本 → 进编辑器。
  - `激活` → 走校验（见 §6）；`归档` → 二次确认。
- **权限**：viewer 仅查看，无 + / 编辑 / ⋮ 写操作。
- **状态**：空态「还没有工作流，点击新建」。

## 5. 工作流编辑器 `/workflows/:id/edit` （核心页）

> 仅 `draft` 可编辑；`active/archived` 进入为只读查看（按钮置灰，顶部提示「已激活，复制为新版本以修改」）。
> 一个页面分多个分区（建议左侧分区锚点导航 or 分 Tab）。所有改动针对该草稿版本，最终「校验并激活」。

### 5.1 基本信息区
```
┌ 基本信息 ─────────────────────────────────────────────┐
│ key[daily_news](创建后只读)  名称[资讯日更]            │
│ 中枢角色[主编▼](仅管理类可选)  派工模式(●manual ○auto) │
│ 可触发[☑主编 ☑调度器 ☐…]                              │
│ 通用约定 common_instructions [富文本/Markdown ……]     │
│ 通用合规项 common_acceptance [富文本/Markdown ……]     │
└────────────────────────────────────────────────────────┘
```
- 数据：workflows（hub_role_code/dispatch_mode/trigger_roles/common_instructions/common_acceptance）。
- 校验：name 必填；hub_role 必须 is_management=1；trigger_roles 至少一项。

### 5.2 阶段区（stages）
```
┌ 阶段（拖动排序）──────────────────────────[ + 加阶段 ]┐
│ ⠿ # │ code      │ 名称        │ 责任角色 │ 产出   │合流│依赖 │ │
│ ⠿ 1 │collect    │01-采集      │情报收集员│资讯包  │ ☐ │ —   │✎│
│ ⠿ 2 │topic      │02-选题      │选题研究员│选题成品│ ☐ │ 1   │✎│
│ ⠿ 3 │wx_content │03-公众号内容│文案      │文章    │ ☐ │ 2   │✎│
│ ⠿ 5 │wx_final   │05-公众号成品│主编      │成品    │ ☑ │ 3,4 │✎│
│ …                                                       │
└─────────────────────────────────────────────────────────┘
```
- 数据：workflow_stages（seq/code/name/role_code/output_type/is_merge）。
- 列：拖动手柄(排序→seq)、code(创建后只读)、name、role_code(下拉 roles)、output_type、is_merge(勾选)、依赖(只读展示，点 ✎ 编辑见 5.3)、行编辑✎。
- 交互：加/删阶段；删阶段需级联清理其依赖与闸；改 role/合流即时生效到草稿。
- 校验：code 在本工作流内唯一；至少 1 个阶段；合流阶段责任角色须为管理类（中枢）。

### 5.3 单阶段详情（点行 ✎ 展开抽屉/弹层）
```
┌ 阶段：03-公众号内容 ───────────────────────────────────┐
│ 依赖上游：[☑02-选题 ☐01-采集 …]  (勾选构成 DAG 边)     │
│ 审核闸：(○用工作流默认闸  ●为本阶段单独配)              │
│   ① [主编▼] [☐人工代录] 名称[主编审]                   │
│   ② [Van▼]  [☑人工代录] 名称[Van审]   [+ 加一道]       │
│ ┌ 作业手册 instructions ─────────────────────────────┐ │
│ │ (Markdown：任务内容——做什么/工具/产出要求)         │ │
│ └─────────────────────────────────────────────────────┘ │
│ ┌ 自检标准 self_check_criteria ──────────────────────┐ │
│ │ (Markdown：交付前自查清单，全过才交)               │ │
│ └─────────────────────────────────────────────────────┘ │
│ ┌ 验收标准 acceptance ───────────────────────────────┐ │
│ │ (Markdown：主编/Van 审核依据，与自检不同)          │ │
│ └─────────────────────────────────────────────────────┘ │
│                              [ 取消 ]   [ 保存阶段 ]    │
└──────────────────────────────────────────────────────────┘
```
- 数据：workflow_stages(instructions/self_check_criteria/acceptance) + workflow_stage_deps + workflow_gates(本阶段覆盖)。
- 三个 Markdown 编辑器：作业手册 / 自检标准 / 验收标准（带预览）。
- 审核闸：默认沿用工作流默认闸；可切「单独配」覆盖（多道，每道选 reviewer_role + 是否人工代录 + 名称）。
- 依赖：多选本工作流其他阶段（不能选自己、不能成环——保存时校验）。

### 5.4 依赖关系预览（DAG，只读可视化）
```
┌ 依赖关系（DAG）─────────────────────────────────┐
│   01─▶02─▶03─▶04─┐                                │
│                  ▼                                │
│                 05─▶06─▶07─▶08─┐                  │
│                                ▼                  │
│                               09─▶10              │
└───────────────────────────────────────────────────┘
```
- 由 stages + deps 实时渲染；高亮入口(无依赖)与终点(无下游)；有环时红色标出。

### 5.5 底部操作条（吸底）
```
[ 放弃修改 ]                 [ 保存草稿 ]   [ 校验 ]   [ 校验并激活 ]
```
- 数据/接口：`PUT /admin/workflows/{id}`（保存草稿，整份提交 stages/deps/gates/文本）；`POST .../validate`；`POST .../activate`。
- 权限：viewer 不可进入此页。

## 6. 校验与激活（弹层）

- **目的**：激活前强制校验，过了才置 active 并归档旧版。
- **数据/接口**：`POST /admin/workflows/{id}/validate` → 检查项结果；`POST /admin/workflows/{id}/activate`。
- **线框**：
```
┌ 校验：资讯日更 v3 ────────────────────────────────┐
│ ✅ DAG 无环                                         │
│ ✅ 单一入口（01-采集）可达所有阶段                  │
│ ✅ 终点（10-小红书发布）可达                        │
│ ✅ 中枢角色「主编」为管理类                         │
│ ✅ 各闸审核角色均存在                               │
│ ✅ 每阶段 instructions/self_check/acceptance 非空   │
│ ⚠️ 05、09 为合流且责任=中枢，将自动派工（提示）     │
│ ❌（如有失败项，列在此并定位到对应阶段）            │
│          [ 取消 ]            [ 确认激活（旧版归档）]│
└─────────────────────────────────────────────────────┘
```
- **交互**：有 ❌ 时禁用「确认激活」，点失败项跳转到对应阶段定位；激活成功 → 该版本 active、同 wf_key 旧 active 自动 archived、Toast 成功、写 admin_audit。

## 7. 角色与成员 `/members`

> 两块：角色（roles）+ 成员/Token（agents + agent_tokens）。

### 7.1 角色
```
┌ 角色 ───────────────────────────────[ + 新建角色 ]┐
│ code      │ 名称       │ 管理 │ 人工 │ 成员数│ 操作 │
│ editor    │ 主编       │ ☑   │ ☐   │ 1     │ 编辑 │
│ van       │ Van        │ ☑   │ ☑   │ 0     │ 编辑 │
│ collector │ 情报收集员 │ ☐   │ ☐   │ 1     │ 编辑 │
└─────────────────────────────────────────────────────┘
```
- 数据/接口：`GET /admin/roles`、`POST /admin/roles`、`PATCH /admin/roles/{code}`。
- 字段：code(创建后只读)、name、is_management、is_human、成员数(派生)。
- 校验：被工作流/agent 引用的角色不可删；改 is_management 影响中枢资格（提示）。

### 7.2 成员（agents）+ Token
```
┌ 成员 ───────────────────────────────[ + 新建成员 ]┐
│ 名称     │ 角色      │ 有效token │ 状态 │ 操作          │
│ 主编bot  │ editor    │ 1 枚      │ 启用 │ 详情/禁用     │
│ 情报bot  │ collector │ 2 枚(轮换)│ 启用 │ 详情/禁用     │
│ scheduler│ (调度器)  │ 1 枚      │ 启用 │ 详情/禁用     │
└─────────────────────────────────────────────────────┘
       │ 点「详情」
       ▼
┌ 成员：主编bot (editor) ──────────────────────────────┐
│ 名称[主编bot]  角色[editor▼]  状态(●启用 ○禁用)      │
│ Token：                              [ + 签发新 token ]│
│  #12 生产    启用  最近使用 10:20  过期 永不 [吊销]   │
│  #9  轮换-Q1 已吊销 …                                  │
└────────────────────────────────────────────────────────┘
   签发弹层：
   ┌ 签发 token：主编bot ───────────────────────────────┐
   │ 备注[生产]   过期[永不▼/30天/90天/自定义]           │
   │                                   [ 签发 ]          │
   │ ⚠ 明文仅显示一次：csw_live_8f3a…d21   [复制]        │
   │   （关闭后服务器只存哈希，无法再查看）              │
   └──────────────────────────────────────────────────────┘
```
- 数据/接口：`GET /admin/agents`、`POST /admin/agents`、`PATCH /admin/agents/{id}`、`POST /admin/agents/{id}/tokens`、`POST /admin/agents/{id}/tokens/{tid}/revoke`。
- 字段：成员 name/role_code/active；token：label/expires_at/状态(启用/已吊销/已过期)/last_used_at。
- 交互：
  - 签发 token → 明文**仅此一次**弹出可复制，之后只存 sha256；轮换 = 先签发新、再吊销旧。
  - 吊销 token → 二次确认（即时失效该 token 的运行面调用）。
  - 禁用成员 → 其所有 token 失效（运行面拒绝）。
- 备注：人工角色（Van，is_human=1）不签发 token（结论由中枢代录），界面隐藏签发入口。
- 权限：viewer 只读；operator 可增改与签发/吊销；roles/agents 删除建议仅 superadmin。

## 8. 后台用户 `/admin-users` （仅 superadmin）

- **目的**：管理后台登录账号。
- **数据/接口**：`GET /admin/users`、`POST /admin/users`、`PATCH /admin/users/{id}`、`POST /admin/users/{id}/reset-password`。
- **线框**：
```
┌ 后台用户 ──────────────────────────[ + 新建用户 ]┐
│ 用户名 │ 名称   │ 角色      │ 状态 │ 最近登录 │ 操作       │
│ zhang  │ 张管理 │ superadmin│ 启用 │ 10:05    │ 编辑/重置密码/禁用│
│ li     │ 李运营 │ operator  │ 启用 │ 09:40    │ …          │
│ guest  │ 访客   │ viewer    │ 禁用 │ —        │ …          │
└────────────────────────────────────────────────────────────┘
```
- 字段：username(唯一,创建后只读)、display_name、role(superadmin/operator/viewer)、status、last_login_at。
- 交互：新建用户设初始密码（强制首次改）；重置密码生成临时密码或发链接；禁用即时失效其 refresh。
- 安全：密码强度校验；不能禁用/降级自己（防自锁）；至少保留一个 superadmin。

## 10. 运行监控 - 实例详情 `/runs/:id` （只读）

- **目的**：看一次运行的全貌：阶段进度、每阶段产出与派工单、审核记录、时间线。
- **数据/接口**：`GET /admin/runs/{id}`（任务图+各阶段状态）、`GET /admin/runs/{id}/timeline`、`GET /admin/tasks/{id}`、`GET /admin/deliverables/{id}`；文件下载经 `/files/{id}`。
- **线框**：

## 12. 设置 `/settings` （仅 superadmin，部分可选）

- **目的**：系统级配置（多数为只读展示 + 少量可改）。
- **内容**：
  - JWT：access TTL、refresh TTL（展示，改需重启/慎重）。
  - 文件：单文件大小上限、允许类型（如 zip）、存储后端（local/OSS）。
  - 触发默认：默认可触发角色。
  - 关于：版本号、数据库路径、健康检查。
- **线框**：分组卡片表单，多数字段只读或带「保存」。

## 13. 全局行为约定

- **鉴权**：除 /login 外所有页面需有效 access JWT；401 自动尝试 refresh，失败跳 /login；403 显示「无权限」占位。
- **危险操作**（激活、归档、吊销 token、禁用用户/成员、删除角色）一律二次确认弹窗，文案明确后果。
- **乐观/悲观**：定义编辑用「保存草稿」显式提交（非自动保存），离开未保存提示。
- **审计**：所有写操作成功后写 `admin_audit`。
- **时间**：统一显示本地时区，存储 RFC3339 UTC。

### 15.5 原型技术 → 目标技术（复刻规则）
- 原型：React18 UMD + Babel + 全局函数 + 内联 style + `styles.css`。**仅作视觉基准**，不照搬。
- 目标 `csw-task-web`：**Vite + TS + React Router + TanStack Query + RHF(zod) + shadcn/ui + Tailwind**；DAG 用 React Flow。
- 令牌落地：`styles.css` 变量 → Tailwind `theme`（颜色/圆角/阴影/字体）或 `:root` CSS 变量；shadcn 组件主题对齐这套 accent 与状态色。
- 数据：原型内 `data.jsx` 是 mock；真实接入《设计文档》§6.1 后台 API（JWT/cookie、CORS、RBAC），mock 仅参考字段形状。
- 复刻硬指标：侧栏 224 / 顶栏 56 / 内容 maxw 1200(1440) / 圆角与阴影按 token / 选中态 accent-weak + 左 3px 条 / 状态徽标按 §0 状态色。

> 一句话：**页面与交互按 §1–§14，视觉与令牌按 §15 + `任务流转后台_设计稿/`，技术按《设计文档》§9。**

### 15.6 实现说明（第三轮 `csw-task-web` 落地差异）

第三轮已落地，整体遵循 §1–§15；少数与 §15.5 的取舍记录于此（线框本体不变，详见 `csw-task/csw-task-web/README.md`）：

- **DAG 用自绘 SVG**（移植设计稿 `dag.jsx` 的分层 + 贝塞尔边 + 环检测），未引入 React Flow——设计稿 DAG 是只读预览、拖动排序发生在阶段表格而非画布，SVG 最忠实且零额外依赖。
- **组件 = 混合策略**：设计稿 ~24 个手写原语移植为 TSX（内联样式 + 设计令牌，像素级），仅 Dialog/Drawer/DropdownMenu 用 Radix（shadcn 底座）补焦点陷阱与可达性；未整体套用 shadcn 默认主题（避免与 accent / 状态色 token 冲突）。
- **激活校验混合**：编辑器即时跑前端 `runChecks`（含 warn / 定位到阶段），「确认激活」先 `PUT` 保存草稿、再调后端 `activate`（后端权威校验 + 归档旧版）。
- **设置页只读**：后端 `settings` 由环境变量驱动，PUT 为 no-op，故 §12 设置页改为只读展示。
