# 资讯日更 · 交付与流转规范（v3）

> 适用范围：资讯日更下所有角色的交付物。流程定义与流程图见《资讯日更 · 全流程》（十三阶段）；审核尺子见《资讯日更 · 验收标准》；业务约定见《资讯日更 · 生产约定》。
> 核心：每份交付物 = 一个「`index.md` 主文档 + 附件」的文件夹，打包成 zip 一步式提交任务流转服务；角色之间传**完整 https 链接**；文件名带责任方，`index.md` 头记溯源。
> 引擎是权威：状态、版本、闸、授权都以引擎为准；群播报由引擎单写。

## 1. 交付形态（文件夹）

交付物是一个文件夹：`index.md` 为固定入口，正文内联；附件放同目录（按类型分子目录：`images/`、`source/`、`html/`、`xiaohongshu/`），`index.md` 用相对链接引用，如 `![](images/封面.jpg)`。

```
资讯日更_文案_20260916_r17_v1/         ← 打包成同名 .zip
├── index.md                       ← 固定入口
└── images/
```

> 角色之间传的不只是素材，还有**编辑判断**（入选理由、看点、近发对照、缺口、图位说明、版本对应关系）。下游优先使用上游给出的判断，不自行推断。

## 2. 提交与流转

1. 文件夹打包成 zip，**一步式提交**任务流转服务（`POST /tasks/{id}/deliverables`，multipart）。
2. 服务端自动命名、按阶段路径归档、版本 +1，返回完整 https 下载链接。
3. 下游在派工单 `upstreams` 里拿到链接（引擎按依赖自动预填，含补件），下载 → 解压 → 以 `index.md` 为入口读。
4. 每一版都留在存储里作留底；被定点编辑取代的首稿标「已被取代」，同样保留。

## 3. 命名规则（服务端派生）

格式：`用途_责任方_日期_任务ID_版本.zip`，`用途` 固定为 **资讯日更**，`任务ID` = `r{run_id}`。
- 责任方：单一角色产出写**角色名**；合流阶段写**产出类型**（03 为「选题方案」、07 为「审核稿」）；补件写「角色名补件」（单独一条版本流）。
- 同一角色同日在不同阶段的产出（情报收集员 01/05、设计师 06/11、发布员 08/09/12/13）文件名可能相同，**靠任务ID + 阶段路径 + header 的 `阶段` 字段区分**；版本号在各阶段内各自从 v1 起算。
- 定点编辑版本与执行者产出共用一条版本流（首稿 v1、协作稿 v2）。

示例：`资讯日更_情报收集员_20260916_r17_v1.zip`、`资讯日更_审核稿_20260916_r17_v2.zip`、`资讯日更_设计师补件_20260916_r17_v1.zip`。

> 派工单是引擎记录（`editor_note` + `upstreams`），不打 zip、不占存储路径；引用写「主编 · r{run_id} 任务#{task_id} 派工单」。

## 4. 存储路径（分阶段归档）

`csw/{用途}/{日期}/{任务ID}/{阶段序号-阶段}/{zip}`，例如 `csw/资讯日更/2026-09-16/r17/04-公众号写作/资讯日更_文案_20260916_r17_v1.zip`。

阶段序号：01-情报逐条 / 02-价值初筛 / 03-选题方案 / 04-公众号写作 / 05-配图与素材核 / 06-版式与模板准备 / 07-完整审核稿 / 08-公众号组版打包 / 09-公众号草稿保存 / 10-小红书改编 / 11-小红书视觉 / 12-小红书组包 / 13-小红书草稿与发布。**路径管排序，文件名管识别。** 链接 = 存储域名 + 路径，写进 `上游来源` 的必须是完整 https 链接。

## 5. 溯源：index.md 元信息头

```yaml
---
任务：资讯日更
类型：情报记录 / 短名单 / 选题方案 / 文章 / 素材包 / 模板 / 审核稿 / 成品 / 发布物 / 小红书文本 / 小红书卡片
交付 Agent：文案
阶段：04-公众号写作
条目：HxO｜折叠木椅（按条目交付时必填；多条逐行列）
版本：v1
时间：2026-09-16 08:05
上游来源：
  - 主编 · r17 任务#{task_id} 派工单
  - 选题方案 · https://…/03-选题方案/资讯日更_选题方案_20260916_r17_v1.zip
状态：待主编审核 / 待 Van 审核 / 已提交（0 闸）/ 已退回（附说明）/ 已通过

```

`阶段` 写带序号的阶段名；`上游来源` 逐条列：上游交付物写「来源方 · 完整 https 链接」，补件写「来源方补件#n · 链接」，派工单写引擎引用——01 也写派工单引用，不写「无」。`状态` 按任务当前闸填写，0 闸阶段写「已提交（0 闸）」。

## 6. 单文件归属

- `source/` 情报原文、链接清单、截图 = 情报收集员（01、05）

## 7. 审核、退回、补件与编辑

### 7.1 闸由阶段声明

引擎不设默认闸，每个阶段显式声明自己的闸（0 闸 = 提交即通过）：

| 阶段 | 闸 |
|---|---|
| 01-情报逐条 | 0 闸（提交即通过） |
| 02-价值初筛 | 0 闸（提交即通过） |
| 03-选题方案 | 主编自审 → Van选题（中枢代录） |
| 04-公众号写作 | 主编审 |
| 05-配图与素材核 | 0 闸（提交即通过） |
| 06-版式与模板准备 | 0 闸（提交即通过） |
| 07-完整审核稿 | 主编定点编辑 → Van全文（中枢代录） |
| 08-公众号组版打包 | 主编核版 |
| 09-公众号草稿保存 | 0 闸（提交即通过） |
| 10-小红书改编 | 主编审 → Van小红书文本（中枢代录） |
| 11-小红书视觉 | 主编审 |
| 12-小红书组包 | 主编核版 |
| 13-小红书草稿与发布 | 0 闸（提交即通过） |

**Van 只在 03、07、10 三处**，由主编代录并附 Van 原话（`source_quote`）与决定类别（`decision_type`）。主编闸通过后，引擎自动 @Van 审同一版本。

### 7.2 退回

任一闸不过 → 退回原角色，**必填改的方向和具体位置**；执行者改后重交，版本自动 +1，新版本从第一道闸重走，原版留底。退回原因在任务详情的 `latest_review` 里自助读取。

### 7.3 主编定点编辑（07 的主编闸）

- 条件：任务在待审、当前闸是主编的闸。首审一次指出全部影响通过的问题，区分必须修改与可选润色，允许一轮明确修订；同类问题第二次仍在时，选择定点编辑、改用已批备选或报告具体缺口。
- 形态：主编提交 `kind=edit` 的版本，写明基于的版本（`edit_of`）与修改摘要（`diff_summary`）；首稿标「已被取代」原样保留；编辑版本直接过主编闸并自动留痕，随后由 Van 审编辑版本。
- 边界：只改有证据支持的局部事实归属、时态、重复、标题导读关联与句子表达；新增事实必须有来源；预算约 10 分钟。
- 验收时留存「首稿 / 协作稿 / 终审稿」三份，协作完成的在复盘里如实标注。

### 7.4 补件

- 挂在**已通过**的任务上（换图、换资产、补事实、追加批准条目），必须指明受影响的产出（`affects_deliverable_id`）。
- 不重开审核、不动已批准版本；引擎把直接下游中已开工的任务标「补件待返工」，未开工的派工时自动带上「补件#n」。
- 已通过的下游需要改时由主编重开。

### 7.5 派工与接单

- 自动派工阶段就绪即派；04、10 手动派工；合流阶段（03、07）自动派给主编。
- 执行者收到派工先在引擎**接单**（已接单 = 在做）；长任务定时心跳；做不了就**报告失败**并写原因，由主编重开或取消。
- 派工单 = 主编意见（`editor_note`）+ 上游链接（`upstreams`，自动预填，可增改）+ 引擎下发的作业手册与自检标准。

### 7.6 平台写与授权

09、13 是平台写操作：本期 run 有对应授权（Van 原话，由主编录入）才会派工与提交；发布授权涵盖同平台草稿；缺授权时停在「待授权」，授权录入后自动续派。只有本地演练授权时不进任何后台，08 / 12 的本地成品即交付。

### 7.7 状态词汇

| 状态 | 含义 |
|---|---|
| 未就绪 blocked | 上游还没通过 |
| 待派工 ready | 具备派工条件（平台写还需授权） |
| 已派工 dispatched | 已正式派工，等执行者接单 |
| 已接单 in_progress | 执行者在做 |
| 待审 review | 等某道闸 |
| 需返工 returned | 被退回，按意见重交 |
| 已交付 passed | 末闸通过 |
| 报告失败 failed | 执行者报告无法完成，等主编处理 |
| 已取消 cancelled | 主编取消 |

「解锁」「可派工」不等于「已派工」。整期进度以引擎进度投影（`GET /runs/{id}/progress`）为准。

### 7.8 群播报

由引擎单写：派工 @执行者、待审 @审核人（Van 闸 @Van 抄送主编）、退回 @执行者抄送主编、阶段通过 / 待派工 / 待授权 / 补件 / 失败 @主编、逾期 @执行者抄送主编（同一次逾期只提醒一次）。角色之间不再手动转述流转，群消息只是提示，被 @ 后回引擎核实。
