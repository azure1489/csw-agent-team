# 资讯日更 · 交付与流转规范

> 适用范围：本任务（资讯日更）下所有 Agent 的交付物。
> 流程：**公众号先行 → 小红书后接**，共十阶段，全程一条**线性链**（无并行分叉）；流程定义与流程图见《资讯日更 · 全流程》（`资讯日更_全流程.md`）。
> 母内容源：**公众号成品是整条内容链的母内容源**；小红书不独立创作，而是对公众号成品的**二次拆解**，一条 = 封面卡 + 内容卡 + 文本。
> 阶段内顺序：每个生产段都是**文案 → 设计师**的先后（设计师要用文案产出的内容才能动手），不是并行。
> 核心：每个 Agent 的交付物 = 一个「`index.md` 主文档 + 附件」的文件夹，打包成 zip 上传 OSS，Agent 之间传**链接**流转，文件名带**责任方**、`index.md` 头记**溯源**。
> 中枢：**主编**是唯一对接 Van 的人，每一步都「审核 → 退回 / 转 Van → Van 通过后重新打包写意见与下一步安排再派工」，**主编自己不编辑内容**。

## 1. 交付形态（文件夹）

交付物是一个文件夹，内含：
- `index.md`：固定入口主文档，正文内容直接内联在里面。
- 附件：图片、HTML、资讯原文等其他文件，放同目录（可按类型分子目录，如 `images/`、`source/`、`html/`、`xiaohongshu/`）。
- `index.md` 用相对链接引用附件，如 `![](images/封面.jpg)`。

```
资讯日更_文案_20260604_r17_v1/         ← 打包成同名 .zip
├── index.md                       ← 固定入口
└── images/01-正文配图.jpg
```

> **内容交付统一原则**
>
> Agent 之间传递的不仅是素材，还包括**编辑判断**。例如：
> - 选题研究员交付：资讯 / 排序 / 入选理由 / 建议角度 / 传播等级
> - 文案交付：标题方案 / 封面推荐 / 正文
> - 小红书文案交付：封面信息 / 卡片文案 / 标题
>
> 后续 Agent 不得自行推断，优先使用上游提供的信息。

## 2. 打包、上传与流转

1. 文件夹打包成同名 zip。
2. zip 上传 OSS，返回一个**完整的 https 链接**。
3. 链接是 Agent 之间流转的东西：下游 Agent 拿到链接 → 下载 zip → 解压 → 以 `index.md` 为入口读正文、按相对链接看附件。
4. 每个 zip 留在 OSS 作留底。

## 3. 命名规则

格式：`用途_责任方_日期_任务ID_版本.zip`，本任务 `用途` 固定为 **资讯日更**，`任务ID` = 运行实例号 `r{run_id}`（同一天多次任务靠它区分、互不覆盖）。
- 责任方：单一 Agent 产出写 **Agent 名**；多方合成产出写**阶段名**（成品）。
- 退回重做递增版本号（v1 / v2 / v3…），每版各打一个 zip、各自留底。
- 同一角色同日在不同阶段各有产出（文案的 03/07、设计师的 04/08、发布员的 06/10、两个成品 05/09），文件名会相同：**靠任务ID + 阶段路径 + header 的 `阶段` 字段区分**，版本号在各阶段内各自从 v1 起算。
- **命名由服务端派生**：经任务流转服务一步式提交时，文件名与存储路径由服务端按本节规则自动生成（版本自动 +1），Agent 不手拼、不算版本。

示例：
- `资讯日更_情报收集员_20260604_r17_v1.zip`
- `资讯日更_成品_20260604_r17_v1.zip`（05 公众号成品 / 09 小红书成品，按路径区分）

> **主编派工单已引擎化，不再打 zip**：派工单是任务流转服务里的一条派工记录（主编意见 `editor_note` + 上游链接 `upstreams`），下游在引擎任务详情里直接读。引用派工单一律写「主编 · r{run_id} 任务#{task_id} 派工单」。文末附录的派工单 `index.md` 范式仅供线下/灾备流转参考。

## 4. OSS 路径（分阶段归档）

`csw/{用途}/{日期}/{任务ID}/{阶段序号-阶段}/{zip}`（`任务ID` = `r{run_id}`，位于日期与阶段之间，同日多次任务各占一目录），例如：

```
csw/资讯日更/2026-06-04/r17/02-选题/资讯日更_选题研究员_20260604_r17_v1.zip
```

阶段序号：**01-采集 / 02-选题 / 03-公众号内容 / 04-公众号视觉 / 05-公众号成品 / 06-公众号发布 / 07-小红书文本 / 08-小红书视觉 / 09-小红书成品 / 10-小红书发布**。**路径管排序，文件名管识别。**
路径由任务流转服务在提交时按上式自动派生（`csw/` 为服务的存储前缀配置）。派工单为引擎记录、不占 OSS 路径；同一阶段目录下只有该阶段 Agent 的各版本产出。

> **链接 = OSS 域名 + 上面的路径。** Agent 之间流转、写进 `index.md` 的 `上游来源` 里的，必须是 OSS 返回的**完整 https 链接**（不能只写路径），例如：
>
> ```
> https://csw-oss.oss-cn-hangzhou.aliyuncs.com/csw/资讯日更/2026-06-04/r17/02-选题/资讯日更_选题研究员_20260604_r17_v1.zip
> ```
>
> 下文 header 里的 `上游来源` 均按此写全。把示例域名 `csw-oss.oss-cn-hangzhou.aliyuncs.com` 换成你实际的 OSS 域名即可。

## 5. 溯源：index.md 元信息头

每个 `index.md` 顶部放一段 YAML 元信息头，作为「谁做的 + 完整链路」的权威记录：

```yaml
---
任务：资讯日更
类型：资讯包 / 选题成品 / 文章 / 封面 / 小红书文本 / 小红书卡片 / 派工单 / 成品 / 发布物
交付 Agent：选题研究员
阶段：02-选题
版本：v1
时间：2026-06-04 13:40
上游来源：主编 · r17 任务#{task_id} 派工单（引擎记录）
状态：待主编审核 / 待 Van 审核 / 已退回（附说明）/ 已通过
自检：（按各阶段自检清单填）
---
```

`阶段` 一律写**带序号的阶段名**（如 `03-公众号内容`、`07-小红书文本`，序号区分公众号段与小红书段）。`上游来源` 逐条列：**上游交付物**写「来源方 · 完整 https 链接」；**主编派工单**（引擎记录，无 zip 链接）写「主编 · r{run_id} 任务#{task_id} 派工单」——01-采集 即此写法，不写「无」。文件名负责「一眼是谁做的」，header 负责「权威记录 + 完整上游链路」，两层并存、不互相替代。

## 6. 单文件归属

多数情况类型即归属：
- `index.md` / 正文文章 / 标题·摘要·导读 / 小红书文本 = **文案**（03、07）
- `images/` 公众号封面 = **设计师**（04）
- `xiaohongshu/` 小红书封面卡 + 内容卡 = **设计师**（08）
- `images/` 配图（02 精选的 15 张，源自采集）+ 5 则资讯排序 = **选题研究员**（02）
- `source/` 资讯原文、链接清单、截图 = **情报收集员**（01）
- `html/` 网页文件 = **发布员**（06）
- 派工单 / 意见 = **主编**（引擎派工记录：`editor_note` + `upstreams`，在任务详情里读）

`images/` 同时放选题研究员的配图（采集来源）和设计师的封面：**封面图归设计师，其余配图归选题研究员**；模糊的（如主编要求补的图）在 `index.md` 文件清单里注明产出方。

## 7. 审核与退回（双闸，主编为枢纽）

**每一阶段都走两道闸，顺序固定：**

1. **主编审** — 对照本阶段验收标准。
   - 不过：主编退回该 Agent，**告知要改的方向和具体位置**（主编不代改）→ Agent 改后**升版本**重打 zip、原版留底 → 再交主编审。
   - 过：主编转交 Van 审。
2. **Van 审** — 由主编代为转交。
   - 不过：主编退回该 Agent 重做（升版本），告知方向和位置。
   - 过：进入下一步。

**Van 通过后，主编出派工单派下一阶段**：在任务流转服务里对下一任务执行派工（dispatch），主编意见、下一步安排写进 `editor_note`，上游交付物的**完整 https 链接**进 `upstreams`（引擎按依赖自动预填已过审产出的链接，可增改——如派 07 时手加 05-公众号成品）；同时在编辑部群 @下一个 Agent 通知。

**任务启动**：当日任务由 Van 向主编下达，主编触发当日实例并出**首个派工单**派给情报收集员（01-采集），当日采集要求写进 `editor_note`；首单无上游交付物。**各阶段 Agent（包括情报收集员）都以引擎里存在自己的派工任务为开工信号，没有派工任务不开工**（群消息只是唤醒提示，以引擎为准）。

**全流程是一条线性链**（无并行分叉），每段 Van 通过后主编派工单转下一阶段；每个生产段内部固定**文案 → 设计师**的先后。两个段衔接点：
- **02-选题过审后** → 派 03-公众号内容（文案），开始公众号生产。
- **06-公众号发布过审后**（公众号成品 = 母内容源）→ 派 07-小红书文本（文案），开始对公众号成品二次拆解。

**状态流转**（写在 `index.md` 的 `状态` 字段）：
`待主编审核` →（主编过）`待 Van 审核` →（Van 过）`已通过` ；任一不过 → `已退回（附说明）`。
