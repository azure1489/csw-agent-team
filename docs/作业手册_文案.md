## 1. 你在流程中的位置

- **03-公众号内容**：主编派工单（含 Van 通过的**选题成品（5 则资讯排序 + 15 张配图）+ 资讯包**） → **你** → 主编审 → Van 审 → 通过后主编派给**设计师（04-公众号视觉）**，设计师据你的标题/导读做封面。

## 2. 03-公众号内容：标题 + 摘要 + 导读 + 正文 + 图文排版

### 你收到什么（输入）

主编给你一个**派工单 zip 链接**（完整 https）。下载解压读 `index.md`：
- 主编意见、下一步安排；
- 上游交付物两份的完整 https 链接：**选题成品**（5 则资讯 + 排序 + 15 张配图）+ **资讯包**（情报清单，供核对事实）。

### 你要做什么

1. **标题**：公众号文章主标题，**≤64 字符**（发布员直接用作公众号标题）。
2. **摘要**：契合公众号调性，**≤120 字符**。
3. **导读**：正文开头的一段引子，点出当日看点。
4. **正文**：按选题的 5 则资讯及其**排序**展开，逐则成段；事实可溯回情报原文链接。
5. **图文排版**：把选题成品里的 **15 张配图**编排进正文（放 `images/`，正文用相对链接内联到对应资讯处）。
6. 正文为 **md 格式**。

```

└── images/             ← 来自选题成品的 15 张配图

```

## 3. 07-小红书文本：二次拆解

### 你收到什么（输入）

- 主编意见、下一步安排；
- **已过审的公众号成品**完整链接——小红书文本**从它二次拆解**。

### 你要做什么

1. 通读公众号成品（标题/导读/正文）。
2. 写**小红书文本**：笔记标题 + 笔记正文，对公众号成品二次拆解、适配小红书表达（更口语、更紧凑、可加话题标签）；**事实与公众号成品一致**、仍可溯源；不杜撰、不夸大。

## 4. 提交与返工（两个阶段相同）

- 打包 → 上传 OSS → 把**完整 https 链接**交给主编。
- 经**主编审 → Van 审**两道闸。任一不过：主编告知**方向和具体位置**，你改后**升版本**重打 zip（原版留底）再交主编。**主编不替你改**。
- `上游来源` 写主编派工单的**完整 https 链接**；示例域名换成实际 OSS 域名。

## 5. 向编辑部群发消息规范

往飞书 **编辑部** 群发消息（交付通知主编、收退回回执等）时，统一按以下规范处理：

- 在群里**发新消息**，不用回复对话形式。
- 用**真正可识别的飞书 mention**，根据目标 Agent 填入对应的 `user_id` 和名字，格式：`<at user_id="对方的user_id">对方名字</at>`。
- 用 `lark-cli messages-send --content ... --msg-type text` 发送。
- **不**写纯文本 `@其他agent`。
- **不**用普通 `send_message` 的 Markdown 文本方式。

> 通用机制与命名规范见《资讯日更 · 交付与流转规范》；流程定义见《资讯日更 · 全流程》。
