# 数据子系统 · 探针记录

> 平台读取能力**先探后用**：两个平台能读到什么，以本页记录的实测结论为准，不以接口名称推断。读不到的字段写「不可得」，不填 0、不由模型补猜。
> 结论同步写进《资讯日更 · 生产约定》变更记录。

## 1. 怎么跑（在数据库所在主机）

```bash
# 公众号：经 mp-helper 的只读接口读取（CSW_SYNC_WX_CMD 为空时生效；mp-helper 与引擎同机）
export CSW_SYNC_WX_MPHELPER_URL=http://172.17.0.1:8088 CSW_SYNC_WX_MPHELPER_KEY=<mp-helper 业务 API Key>
# 或者用适配命令（按 §2 约定输出 JSON；可以 ssh 到持有登录态的 agent 主机执行）
# export CSW_SYNC_WX_CMD="ssh agent-host /opt/csw-sync/wx.sh"
export CSW_SYNC_XHS_CMD="ssh agent-host /opt/csw-sync/xhs.sh"
cd /opt/csw-task && export CSW_CONFIG=/opt/csw-task/config.yaml CSW_DATA_DIR=/opt/csw-task/data
./bin/syncer probe-wx  --known <Van 指定的一篇人工发布 post_id>   # 退出码 0 可行 / 3 部分可行 / 1 不可得
./bin/syncer probe-xhs --known <一条已知笔记 ID>
./bin/syncer account-snapshot --platform xhs --days 30   # 探针可行后：账号区间趋势（原值 + 区间 + 指标定义；读不到退出码 3）
```

探针逐项检查：近 30 天列表（是否含已知人工发布、草稿与已发能否分列）、单篇正文、单篇指标、账号 30 天趋势，并把报告写进 `ledger_sync_runs`（kind=probe）。

## 2. 适配命令约定

每条命令接收子命令与参数，stdout 输出 JSON；读不到时退出码 3 并输出 `{"unavailable":"原因"}`：

| 调用 | 输出 |
|---|---|
| `<cmd> list --since <RFC3339>` | `{"posts":[{"post_id","url","published_at","title","state":"published\|draft","body?","raw?"}]}` |
| `<cmd> get <post_id>` | `{"post":{…同上，含 body}}` |
| `<cmd> metrics <post_id>` | `{"metrics":{平台原始字段，原名原值},"definitions":{字段:平台说明}}`（definitions 可选，有就原样保存为指标定义） |
| `<cmd> account --days <n>` | `{"window_from","window_to","raw":{平台原始字段},"definitions":{…}}` |

## 3. 验收要点

- 公众号：读到至少 1 篇人工发布（Van 指定 post_id）的列表字段、单篇正文、24h 数据；草稿与已发分列，未发稿不进已发库；重复同步不重复入库；合集能拆出其中的单条选题（自动拆条后人工校对一次：`syncer split --manual`）。
- 小红书：笔记列表条数与后台一致（9/14 样本为 42 条，含 07-14 旧条与 09-14 新条，不按文件名推断区间）；单条原始字段齐全；09-14 两条「观看 > 0 而曝光 = 0」原样保留并标 `refresh_pending`；账号 30 天趋势的净涨粉 340 与「新增 394 − 取消 58 = 336」的差值原样保留并标 `definition_pending`（口径待核）。
- 查重接口在没有覆盖证据时只能回答「在已同步记录中未发现」。
- 异常分四类，不未经核查就归因于刷新：`refresh_pending`（可能尚未刷新，待下一龄期复采）、`definition_pending`（口径待核，原值保留）写在快照的异常标记里；`fetch_failed`（采集失败，可重试）、`unavailable`（平台不提供）只记在同步批次的缺口里，不写快照、不填 0。
- 账号级趋势与单篇快照分表保存，各自保留时间区间与指标定义；不把单篇相加冒充账号去重数据。

## 4. 公众号实测（2026-09-15，用 stable_token 直连微信做只读探测）

用 `stable_token` 取调用凭证（与 mp-helper 缓存的 access_token 相互隔离，不影响发布员建草稿），在 mp-helper 所在主机上逐个调用，只读、不写：

| 能力 | 微信接口 | CSW公众号 | 说明 |
|---|---|---|---|
| 已发布列表 | `freepublish/batchget` | 可读，共 40 条 | 只含「发布」的图文；**「群发」的图文不在其中**（9/10 的 MTFV x STEPPA 就不在列表里） |
| 草稿 | `draft/count`、`draft/batchget` | 可读，2 篇 | 可用于 09 保存后回读 |
| 单篇统计（旧） | `getarticletotal`、`getarticlesummary`、`getuserread`、`getusershare` | 47009 已下线 | 微信提示改用新接口 |
| 单篇统计（新） | `getarticletotaldetail` | 可读 | 按发文日期返回当日全部图文，**含群发**；`publish_type` 实测 1 为发布、0 为群发（口径待核）。每篇 `detail_list` 为发文后逐日明细：`read_user`、`read_user_source`（按来源场景）、`share_user`、`read_subscribe_user`、`read_delivery_rate`、`read_avg_activetime`、`zaikan_user`、`like_user`、`praise_money`、`comment_count`、`collection_user`、`read_jump_position` |
| 账号级 | `getusersummary`、`getusercumulate`、`getbizsummary` | 可读 | 用户增减、累计用户、每日阅读汇总 |

mp-helper 里另一个账号 aworld 未认证，以上接口都返回 48001 未授权，不用于日更。

据此实现（2026-09-15）：

- mp-helper 增加只读接口（`GET /api/v1/published`、`/published/:article_id`、`/drafts`、`/drafts/:media_id`、`/datacube/:api`，统计只放行上表四个新接口），原样透传微信返回；仍不做发布、群发、删除。
- csw-task 的 `ledger.MPHelperAdapter` 按两路合并列出内容：
  - 已发布列表的 post_id 用 `article_id`，多图文第 n 篇为 `article_id#n`；
  - 群发从单篇统计按日补齐，post_id 为 `msg:<发文日期>:<msgid>`，没有正文接口，单篇正文标不可得；
  - 草稿 post_id 为 `draft:<media_id>`。
  - 单篇指标取发文日（及此前两日）的 `getarticletotaldetail` 原值，当天的统计次日才有。
  - 账号趋势按 7 天一段取三个账号级接口。
  - 微信返回 48001 或 47009 时记为不可得。
- 待部署后在服务器跑 `syncer probe-wx --known <post_id>`，把结论补到本节。

## 5. 人工导出表格（兜底 / 校验样本）

平台读不到时，可用后台导出的 CSV 导入（xlsx 请先另存为 CSV）：

```bash
./bin/syncer import-csv --platform xhs --kind notes   --file 笔记列表明细表.csv
./bin/syncer import-csv --platform xhs --kind account --file 近30日涨粉数据.csv
```

导出表格是字段与校验样本，不是长期的人工交接流程：正常验收应做到用户发布后无需再提供链接或数据。
