# 数据子系统 · 探针记录

> 平台读取能力**先探后用**：两个平台能读到什么，以本页记录的实测结论为准，不以接口名称推断。读不到的字段写「不可得」，不填 0、不由模型补猜。
> 结论同步写进《资讯日更 · 生产约定》变更记录。

## 1. 怎么跑（在数据库所在主机）

```bash
# 适配命令：包 mp-helper / opencli 的登录态；可以是 ssh 到持有登录态的 agent 主机执行
export CSW_SYNC_WX_CMD="ssh agent-host /opt/csw-sync/wx.sh"
export CSW_SYNC_XHS_CMD="ssh agent-host /opt/csw-sync/xhs.sh"
cd /opt/csw-task && export CSW_CONFIG=/opt/csw-task/config.yaml CSW_DATA_DIR=/opt/csw-task/data
./bin/syncer probe-wx  --known <Van 指定的一篇人工发布 post_id>   # 退出码 0 可行 / 3 部分可行 / 1 不可得
./bin/syncer probe-xhs --known <一条已知笔记 ID>
```

探针逐项检查：近 30 天列表（是否含已知人工发布、草稿与已发能否分列）、单篇正文、单篇指标、账号 30 天趋势，并把报告写进 `ledger_sync_runs`（kind=probe）。

## 2. 适配命令约定

每条命令接收子命令与参数，stdout 输出 JSON；读不到时退出码 3 并输出 `{"unavailable":"原因"}`：

| 调用 | 输出 |
|---|---|
| `<cmd> list --since <RFC3339>` | `{"posts":[{"post_id","url","published_at","title","state":"published\|draft","body?","raw?"}]}` |
| `<cmd> get <post_id>` | `{"post":{…同上，含 body}}` |
| `<cmd> metrics <post_id>` | `{"metrics":{平台原始字段，原名原值}}` |
| `<cmd> account --days <n>` | `{"window_from","window_to","raw":{平台原始字段}}` |

## 3. 验收要点

- 公众号：读到至少 1 篇人工发布（Van 指定 post_id）的列表字段、单篇正文、24h 数据；草稿与已发分列，未发稿不进已发库；重复同步不重复入库；合集能拆出其中的单条选题（自动拆条后人工校对一次：`syncer split --manual`）。
- 小红书：笔记列表条数与后台一致（9/14 样本为 42 条，含 07-14 旧条与 09-14 新条，不按文件名推断区间）；单条原始字段齐全；09-14 两条「观看 > 0 而曝光 = 0」原样保留并标 `pending_refresh`；账号 30 天趋势的净涨粉 340 与「新增 394 − 取消 58 = 336」的差值原样保留并标 `net_mismatch`。
- 查重接口在没有覆盖证据时只能回答「在已同步记录中未发现」。

## 4. 人工导出表格（兜底 / 校验样本）

平台读不到时，可用后台导出的 CSV 导入（xlsx 请先另存为 CSV）：

```bash
./bin/syncer import-csv --platform xhs --kind notes   --file 笔记列表明细表.csv
./bin/syncer import-csv --platform xhs --kind account --file 近30日涨粉数据.csv
```

导出表格是字段与校验样本，不是长期的人工交接流程：正常验收应做到用户发布后无需再提供链接或数据。
