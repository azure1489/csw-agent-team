## 一、它是什么

一个跑在 agent 主机上的常驻 Rust 服务（`csw-collector`），接管资讯日更流程的
**01 情报逐条**、**05 配图与素材核**、**11 小红书选图包**。

它自己轮询任务流转引擎接单、自己干活、自己提交，**不进飞书群、不被 @ 唤醒**。
群里的播报仍由引擎单写——看见「情报收集员已交付」那条消息，是引擎发的，不是它发的。

它带一个工作台网页（`collector.aworld.ltd`），主编在上面看台账、改档、指定深核首批，
Van 在 Van 模式里勾选。**登录转发引擎的后台账号**，没有第二套口令。

```
                    ┌──────────────── agent 主机 ───────────────┐
浏览器 ──https──▶  │ nginx ─▶ csw-collector :8090              │
                    │            │                              │
                    │            ├─▶ SQLite（结构化数据，全部）  │
                    │            ├─▶ LanceDB（只放向量）         │
                    │            ├─▶ codex app-server（深核）    │
                    │            └─▶ 向量服务 127.0.0.1:8022     │
                    └───────────────────┬───────────────────────┘
                                        │
             ┌──────────────────────────┼──────────────────────────┐
             ▼                          ▼                          ▼
   引擎 tasks.aworld.ltd     csw agent-api.campsomewhere.com   csw-subapi（模型）
   （接单 / 登记 / 提交）       （贴文与图片）                  （识别 / 判断）
```

## 二、一天是怎么过的

时间都是**北京时间**。服务内部一律 UTC，界面负责换算。

| 时刻 | 发生什么 | 正常的样子 |
|---|---|---|
| 01:40 | **预取轮**开跑（`kind=prefetch`）。取前 24 小时的窗口，跑采集与判断，**只写本地缓存**，不写引擎、不播报 | 约 03:15 跑完 |
| 03:30 | 向量库备份（每 7 天一次，只留最近一份） | 约 200 MB，一条 `mv` 能恢复 |
| 05:25 | 预热 csw 接口（冷启动第一个请求能等 40 秒） | —— |
| 05:30 | 引擎触发当期 run，派 01 的单。服务接单、建轮、开始十步 | 05:35 前应已 ack |
| 05:50 前 | **首批交付**（深核过的 4–8 条） | 目标 ≤20 分钟 |
| 06:15 前 | 整轮跑完，其余条目以补件追加 | 目标 ≤45 分钟 |
| 07:00 | 01 的时限。到点还没交，服务会主动 `fail` 而不是挂着 | —— |
| 11:00 / 21:00 | 知识库同步两次 | **不许挪到 05:00 前后**——它和正式轮抢同一块 GPU |

**为什么要有预取轮**：一轮从零跑的下限约 95–100 分钟（网关侧约 95 分钟是瓶颈，
GPU 侧约 36 分钟可与之重叠），而目标是首批 20 分钟。预取轮把采集与判断提前做掉，
05:30 只做「按指纹复用 + 补增量 + 深核 + 登记」。

**预取轮是缓存不是前置条件**：它没跑成，整轮照样能从零跑完，只是会迟到。
这种时候服务会如实上报，**不要假装没事**。

## 三、每天早上看三样

```bash
curl -s localhost:8090/healthz | jq        # 一、活着没、盘满没、有没有要人核实的
curl -s localhost:8090/metrics             # 二、计数
journalctl -u csw-collector --since 05:25  # 三、这一轮的日志
```

或者直接开工作台的「今日总览」页，上面三样都有。

**首期有看门狗替你盯**（`csw-task/ops/collector-watchdog/`，每 5 分钟一次）：
05:35 没接到单、05:40 识别 <95%、05:50 首批没交、06:05 十步没走完、
06:20 判断覆盖 <100%、磁盘到线、outbox 有 conflict——各喊一次（**同一件事一天只喊一次**）。
它只 curl `/metrics`，不装 sqlite3 也不拿会话。稳定后停掉。

**`/healthz` 怎么读**：

- `ok: false` 只有一种情况——**本地库读不了**。那时候它什么都做不了，立刻处理。
- `deps[].disk` 到 **88%** 就标 `ok: false`（看板上要看得见），到 **92%** 拒开新轮。
  不是等满了才管：一轮要下一千多张图。
- `outbox_conflicts` **不是 0 就得有人去看**。它表示「写引擎写到一半不确定成没成」，
  服务**不会自动重试**这种（见第五节）。

**`/metrics` 与 `/healthz` 都没有鉴权**，靠反代只 listen 回环来挡。
`/metrics` 挂到公网上等于把轮次数、失败数、磁盘百分比公开出去。〔部署时核对〕

## 四、出事了怎么办

按**症状**查，不按模块查。

### 05:35 了还没 ack

先分清是「没接到单」还是「接了没动」：

```bash
curl -s localhost:8090/api/rounds | jq '.[0]'     # 今天开轮了没（要带会话 cookie）
journalctl -u csw-collector --since 05:25 | grep -i "轮询\|接单\|派单"
```

- **日志里一行都没有** → 进程没起来，或者 `RUST_LOG` 没设（**不设就一行日志都没有**）。
- **日志有轮询但没接到单** → 引擎那边没派，或者派给了**另一行 agent**。
  任务在触发时就钉死到 `ActiveAgentByRole` 返回的那一行 agent 上，
  新建 agent 接不到单——所以切换时必须用**同一个 collector agent 行**再签一枚 token。
- **接了单但步骤不动** → 看是哪一步卡着：`GET /api/rounds/{id}/steps`。

### 一轮超时了

服务在**时限前 5 分钟会主动 `fail`**，写明卡在哪一步，而不是挂着让引擎等到逾期。
看见 `fail` 不必慌，要看它写的原因：

| 原因 | 处置 |
|---|---|
| 预取轮没跑成，从零跑来不及 | 这一期接受迟到；查 01:40 那一轮为什么没跑成 |
| 模型网关 429 / 超时 | 服务自己会在同网关内降级（`gpt-6-astra` → `gpt-5.6-sol`）。整个网关不可用时它只能 `fail`——**Hermes 收集员也依赖同一套，这时候回退没有用** |
| GPU OOM | 批量按 token 预算算，OOM 会自动对半降批重试。连着 OOM 两次要查是不是有别的进程在占卡 |
| csw 取数超时 | 冷启动第一个请求可达 40 秒，单页 50 条比 100 条稳 |

### 磁盘满了

```bash
df -h /opt/csw-collector/data
du -sh /opt/csw-collector/data/*     # blobs 通常是大头
```

- 到 92% 会**拒开新轮**（已经在跑的那轮不打断）。
- 图片 120 天自动清理。急用可以手动删 `data/blobs/` 下的老目录——
  它们是按内容哈希存的，删掉只会让下次重下，不会丢数据。
- 向量库备份只留最近一份，不会越堆越多。

### 判断结果看着不对

**先分清是「模型判错了」还是「材料没给全」**。打开事件详情页（`/ledger/{轮次}/{条目键}`），
它一次给全这一条的全貌：六维各自的依据、三句话、五类对照材料、图片描述、Jev 初评。

- **五类对照材料缺一不判**——缺了会落 `pending_check` 而不是硬判。
  这时候要查的是知识库同步，不是模型。
- **`image_seen=false` 必落待核**。整期待核突然变多，多半是图片下载或识别出了问题，
  不是判断出了问题。
- 确实是判偏了：在台账上**改档**（理由必填），改动另存、原判一个字不动。
  这些改动会进「判断框架与锚点」页的回测，是校准的依据。

### outbox 有 conflict

这是**唯一需要人工核实**的状态。它表示写引擎时收到了
`idempotency_in_progress_or_uncertain`——请求可能成了也可能没成。

**不要换幂等键重发**（那会写重）。正确做法：

1. 去引擎查那一条到底有没有落（`GET /runs/{id}/items` 或 `intake-judgements`）。
2. 落了 → 把这条标 `confirmed`。没落 → 标回 `pending` 让它重发。

〔未验证：这两步现在只能直接改本地库，还没有 CLI 子命令。上线前补一个。
看门狗会在有 conflict 时告警，所以至少不会没人发现。〕

## 五、回退

**回退的前提**：引擎那边的兼容是现成的——02 / 03 优先读判断台账，台账为空就退回
`intake-trace`；迁移只加表加列，对没有台账的 run 自动走旧逻辑。
所以回退**不需要回滚迁移**。

```bash
# 一、停工作台
systemctl stop csw-collector

# 二、把 Hermes 收集员起回来（用户级单元，注意 --user）
systemctl --user enable --now hermes-gateway-collector.service

# 三、确认主网关没被误动
systemctl --user status hermes-gateway.service
```

工作流定义 v9 → v8 只对**下一期**生效：已经触发的那一期在触发时就快照了定义版本。

〔未验证：回退演练还没计时过。目标 ≤5 分钟。〕

**什么时候回退没有用**：csw 接口或模型网关整体故障——Hermes 收集员依赖同一套。
那种情况走 `fail` + 告知主编，不要来回切。

## 六、定时任务

| 名字 | UTC | 北京 | 做什么 |
|---|---|---|---|
| `prefetch` | 17:40 | 01:40 | 预取轮 |
| `kb_sync_1` | 13:00 | 21:00 | 知识库同步 |
| `kb_sync_2` | 03:00 | 11:00 | 知识库同步 |
| `lance_backup` | 03:30 | 11:30 | 向量库备份（每 7 天） |

**都在主循环里跑，不是 systemd timer**——因为它们要和正式轮抢同一块 GPU 与同一个
网关闸门，放进同一个进程才只有一套闸。

**挪时间前先想一件事**：任何一项都不能排在 05:25–06:30 之间。
这个坑踩过一次——`kb_sync_2` 的默认值曾经是北京 05:00，离正式轮只有半小时。

## 七、配置与密钥

优先级 **env > 配置文件 > 内置默认**。

**密钥只从 env 取**，不写配置文件、不进日志（`Secrets` 的 `Debug` 只露长度）：

| 变量 | 给谁用 |
|---|---|
| `CSW_API_KEY` | csw 贴文接口 |
| `SUB2API_API_KEY` | 模型网关（**只用 `csw-subapi.833233.xyz`**） |
| `CSW_ENGINE_TOKEN` | 引擎运行面（接单、登记、提交） |
| `TYPESAFE_API_KEY` | Jev。不填＝Jev 关着，判断退回生成模型 |
| `CSW_COLLECTOR_ALERT_WEBHOOK` | 运维告警群。**谁拿到都能往群里发消息**，不填＝告警关着只进日志 |

`/api/settings` 页只回「已配置 / 缺」，不回值。**缺哪个启动时就会报出来**，
不用等第一次调用才炸。

**`RUST_LOG` 不设就一行日志都没有**——默认过滤全关。看着像进程卡住，其实是没日志。
正常设 `RUST_LOG=info`。
