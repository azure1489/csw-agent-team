# 情报收集员工作台 · 架构与部署分析

日期：2026-09-21｜发出：开发｜状态：分析稿，动工前的底数｜配套：《完整流程》确认稿第 16 版、《设计说明》第 4 版

**一句话**：新东西只有一个 Rust 进程和它托管的工作台，放在 agent 主机上，和已经在那台机上的向量服务同机；引擎主机与 csw-agent 主机不动，各只加一个接口。真正的风险不在架构，在 agent 主机已经很挤，以及三个外部依赖各是单点。

## 2. 架构判断

**放在 agent 主机是对的，但要给它划地盘。** 理由：向量服务就在这台机上，走 `127.0.0.1:8022` 不经 nginx、不经公网；小红书要用这台机上已登录的 Chrome；切换期要和 Hermes 收集员并存、切回也快。代价是这台机已经很挤：可用内存 9 GB，磁盘 85%，GPU 已用 17.8 GB，而且跑着 jellyfin、es、llm-wiki 这些与本项目无关的服务。所以：

- 采集服务以 systemd 单元跑，`MemoryMax=4G`、`CPUWeight` 调低、`LimitNOFILE` 放宽；LanceDB 与图片放独立目录并设保留期，不让它们吃满盘。
- 磁盘先清：/opt/docker 133 GB 里多少是镜像残留，`docker system df` 看一眼；jellyfin 与 es 若不再用，建议迁走或停掉，这是最便宜的扩容。
- GPU 只有一块 P40，向量与重排服务串行；采集服务里对它的调用单线程、按批，夜间做回填，白天只做增量与重排。若以后 llm-wiki 之类也上 GPU，要定分时。

**进程边界**：一个 `csw-collector` 进程管全部（任务驱动、手动开启、采集器、下载与识别、LanceDB、判断编排、深核线程、工作台接口与静态文件、本地 MCP）。codex app-server 是它的子进程，按需起、深核完就停。不拆微服务：数据都在本机 LanceDB，拆了反而要传大对象。

**与引擎的边界**：引擎仍是流程与记录的真相；采集服务只经运行面 HTTP（bearer token）写 items、sweeps、intake-judgements、deliverables、fail，读 my-tasks、tasks/:id、ledger、memory。工作台登录复用引擎的 JWT：采集服务用同一个 HS256 密钥校验，不自己发号；或者把登录请求转发到引擎 `/admin/auth`，两者选一（建议前者，少一跳）。

**与 csw-agent 的边界**：只读，一把收集员 API key；不写 csw 库；补录账号仍由人在 csw 后台做。

**数据放哪**：

| 数据 | 位置 | 大小与增长 | 备份 |
|---|---|---|---|
| 判断台账、条目、采集轮、决定、刊发记录 | 引擎 SQLite | 每天几百行 | `deploy.sh` 迁移前自动备份，照旧 |
| 知识库索引、候选、判断台账副本、向量 | agent 主机 `/opt/csw-collector/data/lancedb` | 起步约 0.2 GB，每天 +8 MB | 可重建（约 2 小时），每周 tar 一份到 OSS 即可 |
| 图片 | `/opt/csw-collector/data/images` | 每天 80–100 MB，一年 30–36 GB | 候选图保留 120 天，参考图永久（约 2 GB）；不备份，OSS 有原图 |
| 线程记录、日志 | `/opt/csw-collector/data/threads`、journald + 滚动文件 | 小 | 保留 90 天 |
| 密钥 | `/opt/csw-collector/collector.env`（0600） | csw API key、引擎 token、sub2api、向量服务、JWT 密钥 | 不入库；换密钥只改这一处 |

## 4. 部署方式

**构建**：Rust 目标是 glibc 2.34 的 CentOS Stream 9。三条路：在 agent 主机上用它自带的 cargo 1.95 构建（最省事，但占它的 CPU 与内存）；在 Mac 上用 `rockylinux:9` 容器构建，产物 glibc 兼容；或 musl 静态链接（LanceDB 依赖 Arrow、protobuf、TLS，静态链接不一定顺）。建议第二条：容器里 `cargo build --release`，产物一个二进制加一个 `web/` 目录，与引擎「本机构建、上传、远端重启」的方式一致。

**上线脚本** `csw-task/deploy-collector.sh`，照抄 `deploy.sh` 的结构：备份旧二进制与 LanceDB 目录清单 → 上传 → `systemctl restart csw-collector` → 等 `/healthz` → 失败自动换回旧二进制。首次另加：装 codex 固定版本（含 bwrap 检查）、建目录、写 `collector.env`、加 nginx 站点 `collector.aworld.ltd`（证书已有）。

**systemd**：`csw-collector.service`（`Restart=always`、`EnvironmentFile`、`WorkingDirectory=/opt/csw-collector`、资源上限）。不需要 timer：任务驱动靠引擎派单，知识库同步用进程内定时（每天两次，触发前一次、晚间一次），夜间向量回填也在进程内排队。

**工作台入口**：`collector.aworld.ltd` → base-nginx（443）→ `127.0.0.1:8090`；静态文件由采集服务托管，`/api/*` 同源。

**切换与回退**（M5 → M6）：并行期采集服务只跑手动轮、不写引擎；切换日改配置开任务驱动、`systemctl stop` Hermes 收集员网关（先确认主网关是不是收集员，它没带 `--profile`）；回退是反过来两条命令，五分钟内。

## 5. 单点与失败面

| 依赖 | 断了会怎样 | 怎么办 |
|---|---|---|
| csw-agent API | 第 2 步取不到贴文，整轮停 | 重试三次后标失败告警，不用旧接口兜底；接口在对方主机，无法自控 |
| 向量与重排服务（本机单 GPU） | 第 2c 向量化与第 4 步召回失败，判断标「对照材料缺」 | 进程内健康检查；失败只影响当轮，不阻塞已判候选；GPU 被别的任务占满时同样表现，要定分时 |
| sub2api | 识别、判断、深核全停 | 重试加熔断；备用模型通道（拍板）；总览告警 |
| 引擎 | 接不到单、写不进结果 | 引擎自己的告警；采集服务缓存未提交结果，恢复后重放（幂等键） |
| codex 子进程 | 深核失败 | 时间盒；条目仍可登记并写明缺口 |
| agent 主机本身 | 全停 | 这是最大的单点：向量服务、Chrome、Hermes 全在上面。短期靠 systemd 自启与监控；中期把无关负载迁走 |
| 内存与磁盘 | OOM 或写满 | `MemoryMax`、保留期、磁盘水位告警（85% 已经到了） |

## 6. 安全面

- 采集服务只持只读的 csw key 与收集员角色的引擎 token；写引擎的动作只有登记与交付；不写 csw 库。
- codex 子进程 `sandbox=read-only`、`approvalPolicy=never`、只读 MCP 白名单、bwrap 已在。
- 工作台在 TLS 后面，JWT 校验，角色沿用 superadmin / operator / viewer / van；写操作全部审计。
- 向量服务只在本机端口，nginx 那一层的对外入口继续要密钥。
- 送往第三方的数据：sub2api（贴文正文与图）、TypeSafe（若启用，正文与图片描述）；Van 的群聊原话是否送出单独拍板。

## 7. 监控

- 采集服务 `/healthz` 与 `/metrics`；每步耗时、失败、队列、向量服务延迟、磁盘与内存水位。
- 告警走两条：流程内的失败经引擎 `fail` 接口由引擎播报到编辑部群；运维告警（磁盘、内存、服务重启）另发开发群，不进编辑部群。
- 43.133.15.38 上已有 Grafana 与 Loki，可以把日志与指标接过去，不必新搭。

## 8. 动工前要定

1. 工作台域名（建议 `collector.aworld.ltd`）与登录方式（复用引擎 JWT 密钥）。
2. agent 主机的清理：jellyfin、es 是否迁走；/opt/docker 镜像清理；是否加盘。
3. codex 固定版本与安装方式；`gpt-6-astra` 对 codex 版本的要求。
4. 备用模型通道。

6. 主网关是不是收集员，切换时停哪一个。
