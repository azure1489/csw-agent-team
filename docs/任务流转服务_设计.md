# 任务流转服务 · 设计文档（通用工作流引擎）

> 目标：用 Go + SQLite 实现一个**通用工作流引擎** Web 服务，把「任意多阶段、多角色、带审核闸的协作流程」变成可编程的状态机，供各 Agent（= 各 skill）通过 HTTP 调用：
> - 每个 Agent **查自己的任务与进度**；
> - **中枢角色**派工（提交任务）、退回任务、审核、代录人工终审结论；
> - 交付物文件由本服务**托管**（上传/下载），并保存可在 Agent 间流转的下载链接。
> 「资讯日更」十阶段流水线 = 本引擎里**第一个 seed 进去的工作流配置**，行为与现行规范一致；语义以《资讯日更 · 全流程 / 交付与流转规范 / 验收标准》为准。

> **实现状态（2026-06）**：后端已落地于 `csw-task/csw-task-svc/`（Go + SQLite，详见其 `README.md`）。
> - **第一轮 · 运行面（完成）**：全表迁移（20 表 + 约束硬化）+ `daily_news` 定义 seed（10 阶段内嵌作业手册/自检/验收，转录自根目录各手册与验收标准）+ 引擎（触发/就绪重算/派工含上游预填/合流自动派/提交守卫/按闸审核）+ 运行面 HTTP API（§6 全部端点）+ `adminctl`（迁移/agent·token/校验）。
> - **第二轮 · 管理后台 API（完成）**：`cmd/adminsrv`（§6.1 + 《管理后台·功能与线框》§1–§14）——JWT 登录（access 内存 + refresh httpOnly cookie 轮换）+ argon2id + RBAC + CORS；工作流定义 CRUD/整份 PUT/校验/激活（归档旧版）/克隆；角色·成员·token 管理；后台用户（防自锁/保 ≥1 superadmin）；只读监控；审计；概览；设置（只读）。`adminctl user` 引导首个 superadmin。
> - 均已通过单测 + HTTP 端到端（含两进程共享 sqlite 的 token 跨进程交叉验证）。
> **待后续轮**：React 前端 `csw-task-web`（§9 + 《管理后台·功能与线框》§15 + `任务流转后台_设计稿/`）。

## 1. 范围

**做**
- **工作流定义**（模板）：阶段、依赖（DAG）、审核闸、中枢角色、派工模式、**各阶段作业手册(instructions)/自检标准(self_check_criteria)/验收标准(acceptance)**，全部数据化、可配。
- **工作流实例**（批次/run）：开跑时按定义快照出任务图，按状态机流转。
- 任务 / 交付物（含派工单）/ 审核 / 事件流水建模与流转。
- 文件上传、下载、内容寻址存储；交付物绑定文件并产出稳定下载链接。
- 每 Agent bearer token 鉴权 + 角色/中枢/管理员权限。
- 服务端编码硬规则：DAG 依赖就绪、N 道闸顺序、版本单调、退回必填方向/位置。

**两个面，严格分开**
- **定义面（后台，离线）**：工作流类型由**独立管理后台（Console/CLI）**预先定义、校验、激活，写入定义表。**agent 运行时 API 不能建/改工作流**——只读、只消费。
- **运行面（agent API）**：**触发**一个已定义工作流类型的实例（run）+ 查任务 / 传产出 / 审核。agent **不直接拼 HTTP**——统一通过配套 **`csw-task` skill**（封装 API + token + 文件上传/下载，见 §6.2）调用。

**不做（本轮）**
- 不做前端 UI（纯 API；人工终审者不直接调 API，结论由中枢代录；人类发起也不直接调 API，由中枢按指示触发）。
- 运行时 API **不含**任何「建/改工作流定义」能力——定义只在管理后台。
- 不做账号自助注册（Agent/token、工作流定义由管理后台维护）。
- 不做消息推送（编辑部群通知仍由各 skill 自行发；服务留 webhook 扩展点）。

**已定决策**
| 项 | 决策 |
|---|---|
| 定义归属 | 工作流定义在**后台**，由**独立管理后台(Console/CLI)**维护；agent 不可定义/修改 |
| 单一事实源 | 工作流定义**内嵌**各阶段作业手册(instructions)+自检标准(self_check_criteria)+验收标准(acceptance)+通用合规项；**派工带作业手册与自检标准、审核带验收标准**。原 md 文档迁入后退役，运行时一律以工作流为准 |
| 触发 | 由**管理类角色（主编，按人类指示）或定时调度器**触发实例；worker 不可触发 |
| 阶段拓扑 | **通用 DAG 依赖边**（串行/并行/扇出/合流统一表达） |
| 审核闸 | **每工作流可配 N 道闸**（每道指定审核角色 + 是否由中枢代录） |
| 派工模式 | **每工作流可选 手动 / 自动**（依赖就绪自动建任务） |
| 存储 | 服务**托管文件**（上传/下载 + 保存下载链接） |
| 人工终审 | 由**中枢代录**结论（无独立 token） |
| 鉴权 | 运行面=每 Agent 一个 bearer token；**后台=JWT 登录**（admin_users，access+refresh），两套独立身份 |

## 2. 概念模型：定义层 / 实例层 / 通用层

```
定义层（模板，可复用、可演进）── 由【管理后台 Console/CLI】维护，agent 只读
  workflows ──< workflow_stages ──< workflow_stage_deps   (DAG 依赖边)
                      └────────────< workflow_gates        (N 道审核闸，默认+覆盖)

   │  agent/调度器【触发】时，按定义版本「快照」
   ▼
实例层（一次批次 = 一个 run）
  runs ──< tasks ──< task_deps        (从 stages/deps 快照，就绪判定只看自己这份)
                └──< task_gates        (从 gates 快照，解析默认+覆盖)
                └──< deliverables ──< deliverable_upstreams
                              │   └─ files（托管 zip）
                              └──< reviews（挂到某道 task_gate）

通用层
  roles / agents（全局角色与鉴权） · events（进度时间线） · idempotency_keys
```

**为什么快照**：工作流定义会演进；run 开跑时把「该版本的阶段/依赖/闸」复制进实例表，之后改模板不影响在跑批次，进度判定只读实例自己的副本。`runs.workflow_ver` 记录来源版本。

**两层「任务」别混**：`tasks` = 阶段生命周期（Agent 查的单位，一 run×stage 一行）；`deliverables` = 该阶段下版本化产物（派工单 + Agent 产出并列）。退回 = 同 task 下版本 +1，原版留底，不新建 task。

## 3. 表结构（SQLite DDL）

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;

-- ───────────── 通用层 ─────────────
-- 角色不写死：纯数据；分「管理(management)/非管理(worker)」两类
CREATE TABLE roles (
  code          TEXT PRIMARY KEY,           -- 任意键，引擎不硬编码具体角色码
  name          TEXT NOT NULL,
  is_management INTEGER NOT NULL DEFAULT 0,  -- 1=管理类（可任中枢/审核/管理工作流定义）；0=非管理（执行者）
  is_human      INTEGER NOT NULL DEFAULT 0   -- 人工终审者(Van)=1（无 token，结论由中枢代录）
);

CREATE TABLE agents (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  role_code  TEXT NOT NULL REFERENCES roles(code),
  name       TEXT NOT NULL,
  active     INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
-- 管理/非管理由 role.is_management 决定，不在 agent 上单设 admin 标志

-- agent 的 bearer token（与 agent 解耦，支持签发/轮换/吊销/一 agent 多枚）
CREATE TABLE agent_tokens (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  agent_id     INTEGER NOT NULL REFERENCES agents(id) ON DELETE CASCADE,
  token_hash   TEXT NOT NULL UNIQUE,         -- sha256(bearer)，明文仅签发时返回一次
  label        TEXT,                          -- 备注（如「生产」「轮换-2026Q2」）
  last_used_at TEXT,
  expires_at   TEXT,                          -- 可空=不过期
  revoked      INTEGER NOT NULL DEFAULT 0,
  created_by   INTEGER REFERENCES admin_users(id),  -- 哪个后台用户签发
  created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_agent_tokens_agent ON agent_tokens(agent_id);

-- ───────────── 定义层 ─────────────
CREATE TABLE workflows (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  wf_key        TEXT NOT NULL,              -- 机器键, e.g. daily_news
  name          TEXT NOT NULL,             -- 资讯日更
  version       INTEGER NOT NULL DEFAULT 1,
  hub_role_code TEXT REFERENCES roles(code),-- 中枢角色（派工/代录人工闸/合流），须为管理类
  dispatch_mode TEXT NOT NULL DEFAULT 'manual', -- manual/auto
  trigger_roles TEXT,                        -- 可触发的角色码 CSV；NULL=默认(管理类 + 调度器)
  common_instructions TEXT,                  -- 交付通用约定（各阶段作业手册的公共部分，可空）
  common_acceptance   TEXT,                  -- 通用合规项（所有阶段审核都附）
  status        TEXT NOT NULL DEFAULT 'draft',-- draft→(管理后台校验)→active→archived；仅 active 可被触发
  created_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  UNIQUE(wf_key, version)
);

CREATE TABLE workflow_stages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  workflow_id INTEGER NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
  seq         INTEGER NOT NULL,            -- 展示/排序
  code        TEXT NOT NULL,               -- collect/topic/...
  name        TEXT NOT NULL,               -- 01-采集
  role_code   TEXT NOT NULL REFERENCES roles(code),
  output_type TEXT,                        -- 资讯包/选题成品/文章/封面/成品/...
  instructions        TEXT,               -- 该阶段作业手册(Markdown)：任务内容——做什么/工具/产出要求
  self_check_criteria TEXT,               -- 该阶段自检标准(Markdown)：agent 交付前自查、全过才交
  acceptance          TEXT,               -- 该阶段验收标准(Markdown)：主编/Van 审核依据（与自检标准不同）
  is_merge    INTEGER NOT NULL DEFAULT 0,  -- 合流（由中枢合成，如 05/09）
  UNIQUE(workflow_id, code),
  UNIQUE(workflow_id, seq)
);

-- DAG 依赖边：stage 需 depends_on 全部通过才就绪
CREATE TABLE workflow_stage_deps (
  workflow_id   INTEGER NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
  stage_id      INTEGER NOT NULL REFERENCES workflow_stages(id) ON DELETE CASCADE,
  depends_on_id INTEGER NOT NULL REFERENCES workflow_stages(id) ON DELETE CASCADE,
  PRIMARY KEY (stage_id, depends_on_id)
);

-- 审核闸：stage_id=NULL 为工作流级默认闸（套用到所有未单独配闸的阶段）
CREATE TABLE workflow_gates (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  workflow_id    INTEGER NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
  stage_id       INTEGER REFERENCES workflow_stages(id) ON DELETE CASCADE, -- NULL=默认
  gate_order     INTEGER NOT NULL,         -- 1,2,...
  reviewer_role  TEXT NOT NULL REFERENCES roles(code),
  relayed_by_hub INTEGER NOT NULL DEFAULT 0, -- 人工闸由中枢代录(Van)
  name           TEXT                      -- 主编审/Van审
  -- 唯一性（同一 scope 内 gate_order 不重）由应用层/部分索引保证
);

-- ───────────── 实例层 ─────────────
CREATE TABLE runs (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  workflow_id  INTEGER NOT NULL REFERENCES workflows(id),
  workflow_ver INTEGER NOT NULL,           -- 快照来源版本
  subject      TEXT NOT NULL,              -- 实例标识：日更=日期，其他=任意键
  title        TEXT,
  status       TEXT NOT NULL DEFAULT 'active', -- active/done/paused/aborted
  created_by   INTEGER REFERENCES agents(id),
  created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  UNIQUE(workflow_id, subject)
);

-- 阶段任务（从 workflow_stages 快照）
CREATE TABLE tasks (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id        INTEGER NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
  stage_code    TEXT NOT NULL,             -- 快照
  stage_name    TEXT NOT NULL,
  seq           INTEGER NOT NULL,
  role_code     TEXT NOT NULL,             -- 责任角色（快照）
  is_merge      INTEGER NOT NULL DEFAULT 0,
  instructions        TEXT,                    -- 快照：作业手册(Markdown，任务内容)→ 派工随单下发给 agent
  self_check_criteria TEXT,                    -- 快照：自检标准(Markdown)→ agent 交付前自查
  acceptance          TEXT,                    -- 快照：验收标准(Markdown，=通用合规项+本阶段)→ reviewer 审核依据
  assignee_id   INTEGER REFERENCES agents(id),  -- 就绪/派工时按 role 解析
  status        TEXT NOT NULL DEFAULT 'blocked',
     -- blocked(依赖未就绪)/ready/dispatched/in_progress/review/passed/returned
  cur_version   INTEGER NOT NULL DEFAULT 0,    -- 指向当前产出版本（闸进度记在 deliverables 上）
  dispatched_at TEXT, started_at TEXT, completed_at TEXT, due_at TEXT,
  created_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  UNIQUE(run_id, stage_code)
);

-- 任务依赖（快照自 workflow_stage_deps；就绪判定只看本表）
CREATE TABLE task_deps (
  task_id       INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  depends_on_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  PRIMARY KEY (task_id, depends_on_id)
);

-- 任务审核闸（快照自 workflow_gates，解析默认+覆盖后落到每个 task）
CREATE TABLE task_gates (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id        INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  gate_order     INTEGER NOT NULL,
  reviewer_role  TEXT NOT NULL,
  relayed_by_hub INTEGER NOT NULL DEFAULT 0,
  name           TEXT,
  UNIQUE(task_id, gate_order)
);

-- 托管文件（内容寻址）
CREATE TABLE files (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  sha256       TEXT NOT NULL,
  filename     TEXT NOT NULL,
  byte_size    INTEGER NOT NULL,
  content_type TEXT,
  storage_path TEXT NOT NULL,            -- data/blobs/<sha[0:2]>/<sha[2:4]>/<sha>
  uploaded_by  INTEGER REFERENCES agents(id),
  created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_files_sha ON files(sha256);

-- 交付物：派工单(is_dispatch=1) + Agent 产出(=0)，均版本化
CREATE TABLE deliverables (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id      INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  is_dispatch  INTEGER NOT NULL DEFAULT 0,
  version      INTEGER NOT NULL,
  doc_type     TEXT NOT NULL,
  producer_id  INTEGER REFERENCES agents(id),
  file_id      INTEGER REFERENCES files(id),
  download_url TEXT,                       -- 可流转稳定链接（本服务 /files/{id} 或外部）
  filename     TEXT, title TEXT, summary TEXT,
  meta_json    TEXT,                        -- index.md YAML 头快照
  self_check   TEXT,                        -- agent 对照 self_check_criteria 的自检申报（结果，非标准）
  editor_note  TEXT,                        -- 派工单：中枢意见 + 下一步安排
  cur_gate         INTEGER NOT NULL DEFAULT 0, -- 本版本已过到第几道闸（0=刚提交未审）
  returned_at_gate INTEGER,                    -- 被退回时卡在第几道闸（未退则空）
  status       TEXT NOT NULL DEFAULT 'submitted', -- submitted/in_review/passed/returned；派工单=issued
  submitted_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  UNIQUE(task_id, is_dispatch, version)
);

CREATE TABLE deliverable_upstreams (
  deliverable_id INTEGER NOT NULL REFERENCES deliverables(id) ON DELETE CASCADE,
  label          TEXT,
  upstream_url   TEXT NOT NULL,
  upstream_id    INTEGER REFERENCES deliverables(id)
);

-- 审核：每条挂到某道 task_gate
CREATE TABLE reviews (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  deliverable_id   INTEGER NOT NULL REFERENCES deliverables(id) ON DELETE CASCADE,
  task_gate_id     INTEGER NOT NULL REFERENCES task_gates(id),
  reviewer_id      INTEGER REFERENCES agents(id),  -- 实际录入人（人工闸=中枢）
  verdict          TEXT NOT NULL,         -- pass/reject
  comment          TEXT,
  return_direction TEXT, return_location TEXT,
  created_at       TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE events (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  run_id         INTEGER REFERENCES runs(id) ON DELETE CASCADE,
  task_id        INTEGER REFERENCES tasks(id) ON DELETE SET NULL,
  deliverable_id INTEGER REFERENCES deliverables(id) ON DELETE SET NULL,
  actor_id       INTEGER REFERENCES agents(id),
  type           TEXT NOT NULL,
     -- run_created/task_ready/dispatched/file_uploaded/submitted/
     -- gate_passed/gate_returned/stage_passed/run_done
  detail_json    TEXT,
  created_at     TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE idempotency_keys (
  key           TEXT PRIMARY KEY,
  agent_id      INTEGER REFERENCES agents(id),
  endpoint      TEXT,
  response_json TEXT,
  created_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

-- ───────────── 后台鉴权层（管理后台人类用户 · JWT）─────────────
-- 与 agents（skill 运行时 token）完全分离：后台是人类操作员，用户名+密码登录、JWT 鉴权
CREATE TABLE admin_users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,                    -- argon2id / bcrypt（不存明文）
  display_name  TEXT,
  role          TEXT NOT NULL DEFAULT 'operator', -- superadmin/operator/viewer（后台 RBAC，独立于工作流角色）
  status        TEXT NOT NULL DEFAULT 'active',   -- active/disabled
  last_login_at TEXT,
  created_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

-- 刷新令牌：access JWT 无状态短期；refresh 存哈希，支持轮换/吊销/登出
CREATE TABLE admin_refresh_tokens (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES admin_users(id) ON DELETE CASCADE,
  token_hash  TEXT NOT NULL UNIQUE,              -- sha256(refresh token)
  expires_at  TEXT NOT NULL,
  revoked     INTEGER NOT NULL DEFAULT 0,
  user_agent  TEXT, ip TEXT,
  created_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_admin_refresh_user ON admin_refresh_tokens(user_id);

-- 后台操作审计（登录/定义增改/激活等；与业务 events 分开）
CREATE TABLE admin_audit (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER REFERENCES admin_users(id),
  action      TEXT NOT NULL,                     -- login/logout/workflow_create/workflow_activate/...
  target      TEXT,                              -- 如 workflow:daily_news@v3
  detail_json TEXT,
  created_at  TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE INDEX idx_tasks_assignee_status ON tasks(assignee_id, status);
CREATE INDEX idx_tasks_run             ON tasks(run_id, seq);
CREATE INDEX idx_deliverables_task     ON deliverables(task_id);
CREATE INDEX idx_reviews_deliverable   ON reviews(deliverable_id);
CREATE INDEX idx_events_run            ON events(run_id, id);

-- ───────────── 约束硬化 ─────────────
-- 审核闸唯一性：默认闸(stage_id 空) 与 覆盖闸(stage_id 非空) 各自 gate_order 不重
CREATE UNIQUE INDEX uq_wf_gates_default  ON workflow_gates(workflow_id, gate_order)           WHERE stage_id IS NULL;
CREATE UNIQUE INDEX uq_wf_gates_override ON workflow_gates(workflow_id, stage_id, gate_order) WHERE stage_id IS NOT NULL;
-- 每个 wf_key 同时只能有一个 active 版本
CREATE UNIQUE INDEX uq_wf_active ON workflows(wf_key) WHERE status='active';
-- 枚举列随列声明 CHECK（防脏值）：
--   workflows.status   CHECK(status IN ('draft','active','archived'))；dispatch_mode IN ('manual','auto')
--   runs.status        CHECK(status IN ('active','done','paused','aborted'))
--   tasks.status       CHECK(status IN ('blocked','ready','dispatched','in_progress','review','passed','returned'))
--   deliverables.status CHECK(status IN ('issued','submitted','in_review','passed','returned'))
--   reviews.verdict    CHECK(verdict IN ('pass','reject'))
--   admin_users.role   CHECK(role IN ('superadmin','operator','viewer'))；status IN ('active','disabled')
-- 版本模型：workflows 每行=一个不可变版本（UNIQUE(wf_key,version)）；编辑=新增版本行、旧版 archived；
--           触发取最新 active；runs.workflow_id 指具体版本行，workflow_ver 作展示冗余。
```

## 4. 资讯日更如何配成一个工作流（seed 示例）

```
roles: 主编(editor) = 管理类; Van(van) = 管理类·人工; 情报收集员/选题研究员/文案/设计师/发布员 = 非管理
workflows: { wf_key: daily_news, name: 资讯日更, hub_role: editor,
             dispatch_mode: manual, trigger_roles: "editor,scheduler" }
  └ 由管理后台配好并 activate；主编（按人类指示）或定时调度器触发当日实例。
workflow_gates（默认闸，stage_id=NULL，套用所有阶段）:
  gate 1 → reviewer=editor, relayed=0, name=主编审
  gate 2 → reviewer=van,    relayed=1, name=Van审   (中枢代录)

内嵌内容来源（md 文档 → 工作流定义）：
  workflows.common_acceptance      ← 《资讯日更·验收标准》§0 通用合规项
  workflows.common_instructions    ← 《交付与流转规范》通用约定（可空，多数已是引擎行为）
  workflow_stages[i].instructions        ← 《作业手册_角色》该阶段「怎么做」部分
  workflow_stages[i].self_check_criteria ← 《作业手册_角色》该阶段「提交前自检」清单
  workflow_stages[i].acceptance          ← 《验收标准》该阶段清单（与自检标准不同，主编/Van 用）

workflow_stages（10 段）+ deps：
  01 collect    collector              （无依赖：入口）
  02 topic      researcher   ← 01
  03 wx_content writer       ← 02
  04 wx_visual  designer     ← 03
  05 wx_final   editor merge ← 03,04   （合流：内容+封面）
  06 wx_publish publisher    ← 05
  07 xhs_text   writer       ← 06
  08 xhs_visual designer     ← 07
  09 xhs_final  editor merge ← 07,08   （合流：文本+卡片）
  10 xhs_publish publisher   ← 09
```

- 串行靠依赖边自然成链（04 依赖 03 → 设计师等文案）；**合流**靠多依赖（05 依赖 03+04）。
- 入口任务（01，无依赖）开跑即 `ready`；manual 模式下中枢出首个派工单派给情报收集员（= 规范的「任务启动单」）。
- 换任何别的流程：另起一个 `workflows` + 它自己的 stages/deps/gates 即可，引擎逻辑不变。

## 5. 状态机 + 引擎逻辑

**task.status**：
```
blocked ──(所有 task_deps 已 passed)──▶ ready
ready ──[manual]中枢派工 / [auto]引擎自动派──▶ dispatched ──Agent提交v1──▶ review
review ──逐道 task_gate 审──▶ (该版本 deliverable.cur_gate 达最后一道且 pass) passed
review ──任一道 gate reject──▶ returned(记 returned_at_gate) ──Agent提交v(n+1)──▶ review（新版本 cur_gate 从 0 起）
任一 task passed → 引擎重算其下游 task 的就绪；auto 模式则自动派发
所有 task passed → run.status=done
```

**审核（统一一个动作，按 gate 推进）**：对某交付物提交 `reviews`，引擎取该版本 `deliverable.cur_gate+1` 这道 `task_gate`——
- 普通闸：调用者 role 必须 = `reviewer_role`；
- 人工闸（`relayed_by_hub=1`，如 Van）：由**中枢角色**代录。
- pass → 该版本 `cur_gate+1`；到最后一道 → task `passed`、deliverable `passed`。
- reject → deliverable `returned` 且记 `returned_at_gate`、task `returned`，**必填 return_direction/location**。

**中枢的两个核心动作（你点名的）**：
- **提交任务（派工）** = `dispatch`：仅对 `ready` 任务；建 `派工单` 交付物（issued）+ task→`dispatched`。派工单 = 引擎自动带上**该阶段作业手册 `instructions` + 自检标准 `self_check_criteria`**（来自定义快照）+ 主编意见/下一步 + 上游链接——agent 拿到即知道「怎么做」和「交付前自查什么」，自查通过才交付。
- **退回任务** = `review(reject)`：task→`returned`，必填方向+位置（中枢不代改）。

> **审核随附验收标准**：审核交付物时，引擎把**该阶段验收标准 `acceptance`**（通用合规项 + 本阶段清单）一并给 reviewer，对照判 pass/reject——agent 交付、reviewer 拿到「怎么验」。
> **自检 ≠ 验收，分开**：agent 交付前对照**自检标准 `self_check_criteria`** 自查、全过才提交，自查申报填进 `deliverables.self_check`；reviewer 用的是**另一份 `acceptance`**。两者各自维护、用途不同。

**中枢（hub_role，run 进行中的协调者）**

### 6.1 管理后台（HTTP 后台 API + 控制台，**非 agent API**，JWT 登录）

后台是**人类操作员**用的（定义工作流 / 管理角色成员 / 监控），与运行面分离、**用 JWT 登录**（`admin_users`），与 agent 的 bearer token 是两套独立身份。

**登录与会话（JWT）**
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/admin/login` | `{username, password}` → 校验 `password_hash` → body 返 `{access_token(JWT,短期), user}`；refresh 经 **`Set-Cookie`（httpOnly+Secure+SameSite）** 下发 |
| POST | `/admin/refresh` | 读 **refresh Cookie** → 新 access（并轮换 refresh、重设 Cookie） |
| POST | `/admin/logout` | 吊销当前 refresh（置 `revoked`）+ 清 Cookie |

- access JWT：无状态、短期（~15min）、HS256 签名（服务密钥），claims=`sub(user_id)/role/exp/iat`；每请求验签、不查库；前端**存内存**。
- refresh：~7d，**httpOnly+Secure Cookie** 承载（前端 JS 读不到，防 XSS 窃取），服务端存 `sha256` 哈希于 `admin_refresh_tokens`，支持轮换/吊销/登出。
- CORS：前端跨域调用需 `AllowCredentials=true` + 指定前端 origin（cookie 才会带）。
- 所有 `/admin/*` 业务接口需 `Authorization: Bearer <access JWT>`；按 `admin_users.role`（superadmin/operator/viewer）做 RBAC。

**定义管理（需登录，operator+）**
- 建/改工作流类型：阶段、依赖边、审核闸、各阶段 instructions/self_check_criteria/acceptance、`hub_role`、`dispatch_mode`、`trigger_roles`、通用约定/合规项。
- 校验并激活：检查 DAG 无环、入口/终点可达、`hub_role` 为管理类、各闸 `reviewer_role` 存在；通过才置 `active`。
- 运行监控（只读）；后台操作写入 `admin_audit`。

**角色 / 成员 / Token 管理（operator+；`admin_users` 仅 superadmin）**
| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/admin/roles` · `PATCH /admin/roles/{code}` | 角色增改（name/is_management/is_human） |
| POST | `/admin/agents` | 建 agent（role + name） |
| GET | `/admin/agents` | 列 agent + 各自 token 状态 |
| PATCH | `/admin/agents/{id}` | 改名/角色、启用/禁用（active） |
| POST | `/admin/agents/{id}/tokens` | **签发新 token**（可带 label/expires）→ **明文仅此一次返回**，库存 sha256 |
| POST | `/admin/agents/{id}/tokens/{tid}/revoke` | **吊销**某 token（轮换=先签发新的再吊销旧的） |
| POST | `/admin/users` …（superadmin） | 管理后台用户：建用户/改角色/禁用/重置密码 |

> 运行时即便是中枢/管理类 agent，也**无法**通过运行面 API 改定义；改流程一律走管理后台（且需人类 JWT 登录）。

### 6.2 skill 层（agent 实际调用方式）

agent 都是 Claude skill，与本服务交互**不直接拼 HTTP**，而是通过配套 **`csw-task` skill**（与 `lark-im`、`opencli`、`mp-helper` 同性质，封装底层 API）。skill 负责：读本 agent 的 bearer token（环境/配置）、拼 base URL、生成 `Idempotency-Key`、multipart 上传/流式下载、解析 JSON、失败重试。

**整条流程的起点**：
```
人类 ─(口头/飞书)─▶ 主编(管理类 agent)
   └ 使用 skill：csw-task trigger daily_news --subject 2026-06-09 --inputs "采集要求…"
       └ skill 内部 POST /api/v1/workflows/daily_news/runs（带主编 token + Idempotency-Key）
           └ 引擎据后台定义快照出 run、入口任务就绪
（或：定时调度器在服务器上跑 `csw-task trigger …` 自动起当日实例）
```

**命令 ↔ 端点映射**：
| skill 命令 | 调用者 | 映射端点 |
|---|---|---|
| `csw-task trigger <wf> --subject --inputs` | 中枢/调度器 | POST `/workflows/{key}/runs` |
| `csw-task inbox` | 中枢 | GET `/me/inbox` |

## 7. 鉴权与权限

- **两套独立身份**：
  - **运行面（agent/skill）**：bearer token（`Authorization: Bearer`）→ 中间件 `sha256` 比对 `agent_tokens`（未吊销、未过期）→ agent → role（含 `is_management`）；命中即更新 `last_used_at`。token 由**后台签发/轮换/吊销**，一个 agent 可有多枚（便于无缝轮换）。
  - **后台（人类操作员）**：**JWT 登录**（`admin_users` 用户名+密码）→ access JWT（**前端存内存**）+ refresh（**httpOnly Cookie**）；所有 `/admin/*` 需有效 access JWT，按 `admin_users.role`(superadmin/operator/viewer) 做 RBAC；前后端分离经 CORS（AllowCredentials）。两者凭证、表、用途均不互通。
- **角色不写死、分两类**：引擎只认 `role.is_management` / 工作流 `hub_role` / 闸 `reviewer_role`，不硬编码任何具体角色码。
- **触发实例**：调用者为**管理类角色**或**调度器服务账号**（worker 不可触发）。
- **派工 / 合流**：调用者 role 必须 = 该工作流 `hub_role`（且 `hub_role` 必为管理类）。
- **审核普通闸**：调用者 role = 闸的 `reviewer_role`；**人工闸（Van）** `relayed_by_hub=1` 由中枢代录、Van 无 token。
- **提交产出**：仅该 task 的 assignee 角色（中枢负责合流阶段）。
- **工作流定义**：**不在运行面**；仅管理后台（独立凭证）可建/改。

| 动作 | 非管理角色 | 中枢(hub·管理) | 调度器 | 管理后台 |
|---|:--:|:--:|:--:|:--:|
| 查我的任务/进度、上传下载文件 | ✓ | ✓ | — | — |
| 提交产出 | ✓(自己 task) | ✓(合流阶段) | — | — |
| 触发实例 | — | ✓ | ✓ | — |
| 派工 / 审核(含代录人工闸) | — | ✓ | — | — |
| 建/改/激活工作流定义 | — | — | — | ✓ |

## 8. 文件存储 · 并发 · 关键规则

**文件**：上传算 sha256 → 落盘 `data/blobs/<分片>/<sha>`（同内容去重），DB 只存元数据；下载链接 `{base}/api/v1/files/{id}` 可流转；`BlobStore` 接口预留换 S3/OSS。限大小 + content_type 白名单。

**并发/事务**：WAL + `busy_timeout=5000` + `foreign_keys=ON` + `synchronous=NORMAL`；写串行（`SetMaxOpenConns(1)` 或单写 goroutine），读并发。派工 / 提交(version+1+状态+event) / 审核(review+翻转+下游重算+event) 各放单事务。

**护栏**：
- **DAG 就绪**：task 的所有 `task_deps` 全 passed 才 `ready`；激活工作流时校验无环、入口/终点可达。
- **N 闸顺序**：审核只作用于该版本 `deliverable.cur_gate+1`，越级 409；**0 闸阶段**提交即 `passed`。
- **版本单调 + 闸重置**：退回后提交 version=cur_version+1（服务端自增），新版本 `cur_gate` 从 0 起重走闸；原派工单不必重发，退回意见存于 `reviews.return_*` + `returned_at_gate`。
- **提交守卫**：仅当 task 在 `dispatched/returned/in_progress` 才能提交新版；`review/passed` 时提交 → 409。
- **退回必填**：reject 必带 return_direction/location。
- **上游自动预填**：派工/自动派时引擎把各依赖任务**已通过产出**的 download_url 预填进派工单上游，中枢可增删改。
- **派工模式**：manual=中枢调 dispatch；auto=就绪即引擎自动建派工单/置 dispatched。
- **中枢自产阶段（合流）**：assignee=hub 的阶段（如 05/09），就绪时引擎**自动出派工单给中枢自己**（含预填上游），中枢直接提交成品，免去「派工给自己」的空动作。
- **幂等**（fail-closed，按键 at-most-once）：带 `Idempotency-Key` 的 POST 在业务前先向 `idempotency_keys` 持久占位（主键冲突判定唯一执行权，跨进程有效），占位绑定请求指纹（agent + 方法 + 路由 + RequestURI + 媒体类型 + 内容摘要，multipart 按各 part 内容归一）。业务 2xx → CAS 写入首次响应，同指纹重试回放、异指纹 409 `idempotency_request_mismatch`；业务非 2xx → 释放占位允许重试；中途崩溃 → 占位保持 pending，同键一律 409 `idempotency_in_progress_or_uncertain`；存储不可用 → 503。旧版无指纹记录按原语义回放。
- **时间**：TEXT RFC3339 UTC。**错误**：HTTP 码 + `{code,message}`（400/403/404/409）。
- **审计**：所有写操作落 `events`（只增），`timeline` 即进度来源。
- **约束硬化**：workflow_gates 默认/覆盖各一条**部分唯一索引**保 gate_order 不重；`UNIQUE(wf_key) WHERE status='active'` 保每类型仅一活跃版本；枚举列加 `CHECK`（详见 §3 DDL 末「约束硬化」）。
- **应用层不变量**（DB 无法强制，引擎事务保证）：① `task_deps` 两端同 run；② `reviews` 的 deliverable 与 task_gate 属同一 task；③ `tasks.cur_version` 与 deliverables 实况一致。
- **迁移**：goose；首版迁移 = 建表 + 约束 + roles seed + 资讯日更工作流 seed。

## 9. 技术选型与项目布局

**技术栈**
- HTTP 框架：**`gin-gonic/gin`**（路由组分隔运行面 `/api/v1` 与后台 `/admin`；中间件链；binding 校验）。
- JWT：**`golang-jwt/jwt` v5** + 自写中间件（配合 `admin_refresh_tokens` 轮换/吊销）。
- 密码哈希：**argon2id**（`golang.org/x/crypto/argon2`）。
- SQLite：**`modernc.org/sqlite`**（纯 Go 免 cgo）+ `database/sql`。
- 迁移：**`goose`**；日志：**`slog`**（gin 中间件桥接）；校验：`go-playground/validator`（gin 内置）；CORS：`gin-contrib/cors`（仅后台）。
- 部署：**两个 binary**（运行面 `cmd/server` + 后台 `cmd/adminsrv`），各自 `gin.Engine`、各自中间件链、端口分开。
- **前后端分离**：后台 `cmd/adminsrv` 只出 **JSON**（不渲染页面、不嵌静态）；前端是**独立 React 工程**（见下「前端」），经 CORS + JWT 调后台 API。

**包结构**（Monorepo；Go 后端遵循 golang-standards/project-layout）
```
csw-task/                              # Monorepo 根
├── csw-task-svc/                      # Go 后端
│   ├── cmd/{server,adminsrv,adminctl}/   # 三入口：运行面 / 后台(纯 JSON) / 可选 CLI
│   ├── internal/
│   │   ├── app/{server,adminsrv}/        # 各自 gin 装配：router + handlers

│   │   ├── files/                        # BlobStore 接口 + 本地内容寻址实现
│   │   ├── auth/                         # agent bearer 校验 + admin JWT(签发/校验/refresh) + argon2id
│   │   ├── middleware/                   # gin：recovery/requestid/logger/agentauth/jwtauth/rbac/idempotency/cors
│   │   └── config/
│   ├── api/openapi/  migrations/  configs/  deployments/  build/  scripts/  test/  docs/
│   └── go.mod  go.sum  Makefile
└── csw-task-web/                      # React 前端（Vite + TS + shadcn/ui + Tailwind）
    ├── src/
    │   ├── api/        # api client（注入 access、401 自动 refresh、withCredentials）+ DTO 类型
    │   ├── auth/       # 登录态 / access(内存) / refresh(httpOnly cookie) / 路由守卫(role)
    │   ├── components/ # 通用：表格/表单/状态徽标/确认弹窗（shadcn 封装）
    │   ├── features/   # workflows(列表+编辑器:阶段/DAG/闸/三段Markdown) · members · admin-users · runs · audit · dashboard
    │   ├── routes/  layout/  main.tsx
    └── index.html  package.json  vite.config.ts  tailwind.config.ts  tsconfig.json
```
- **前后端分离 · Monorepo**：同库两个子工程并列；后端不含前端代码，前端经 CORS+JWT 调 `cmd/adminsrv`。
- **不建 `/pkg`**：应用不对外供库，全部入 `/internal`。
- **运行时数据不进仓库**：sqlite 文件 + `blobs/`（托管 zip）落配置指定的数据目录（如 `/var/lib/csw-task` 或本地 `./data`），`.gitignore`。
- **框架与业务解耦**：`domain/engine/workflow/store/files` 不依赖 gin；gin 仅在 `internal/app/*` 与 `internal/middleware`。
- 运行面与后台**分进程、分凭证**：agent 只连 `cmd/server`（bearer，改不了定义）；定义只能经 `cmd/adminsrv`（JWT 登录）。

**前端（`csw-task-web`，React，前后端分离）**
- 栈：**Vite + TypeScript + React Router + TanStack Query + React Hook Form(zod) + shadcn/ui + Tailwind**；DAG 用 **React Flow**；三段 Markdown 用 Markdown 编辑器。
- 鉴权：登录后 **access JWT 存内存**、**refresh 存 httpOnly+Secure Cookie**（前端不碰 refresh）；api client 在 401 时静默调 `/admin/refresh`（带 cookie）续 access、失败跳登录。
- CORS：`cmd/adminsrv` 用 `gin-contrib/cors` 放行前端 origin 且 `AllowCredentials=true`（cookie 需要）；Cookie 用 `SameSite`/`Secure`。
- 实现规范：页面/字段/交互/权限/状态按《管理后台 · 功能与线框》§1–§14；**视觉与设计令牌按其 §15 + 仓库 `任务流转后台_设计稿/`**（Claude Design 交付的 Linear 风格浅色控制台原型，像素级复刻、不照搬原型结构）。

## 10. 开放问题（实现前待定）

1. ~~角色作用域~~ **已定**：角色不写死、纯数据，分管理/非管理两类（`role.is_management`）；全局共享，按需细分独立 role。
2. ~~upstreams 自动预填~~ **已定**：派工/自动派时引擎自动预填依赖产出的 download_url，中枢可改。
3. ~~工作流定义归属与触发~~ **已定**：定义在后台、由**独立管理后台(Console/CLI)**维护（运行面无定义 API）；实例由**管理类角色(主编，按人类指示)或调度器**触发。
4. **依赖(门禁) vs 内容上游**：个别阶段「触发它的依赖」与「它真正复用的内容」可能不同（如 07 依赖 06-发布物，但内容要 05-成品）。当前靠「中枢可改预填上游」兜底；是否要让阶段定义独立的「内容上游」字段？（建议先用中枢可改，不加字段。）
5. **assignee 解析**：现假设「一角色一 agent」，派工时按 role 取唯一活跃 agent。若一角色多 agent，需分配策略（先到/轮询/手选）。
6. **入口任务**：是否允许多入口（多个无依赖起点）？DAG 已支持，资讯日更为单入口。
7. **超时/通知**：`tasks.due_at` 是否启用、状态翻转是否回调飞书群 webhook？（建议先留扩展点不启用。）
8. **工作流改版与在跑实例**：已用快照隔离；是否需要「把在跑实例迁到新版」的能力？（建议先不做。）
9. **运维**：Agent/token 初始化；工作流定义经管理后台（adminctl）导入/激活。

## 附录 A · 数据交换预演（skill 触发起点 · 资讯日更一整跑）

> 三条数据通道：**状态**走 JSON API（落 SQLite）；**文件**走上传/下载；**Agent 之间只传 `download_url`（链接）**，放在派工单 `upstreams` 里。
> agent 不直接拼 HTTP，统一经 `csw-task` skill（见 §6.2）；下面每步给出「skill 命令 → 底层 HTTP → 响应节选 → DB 变更」。示例 run_id=10、subject=2026-06-09。

### 前置（后台，离线）
管理后台 `adminctl` 已导入并激活 `daily_news` 定义（10 阶段 + 依赖 + 默认双闸 主编/Van）；roles/agents/token 已 seed。

### 步 0 · 触发（主编按人类指示，或调度器）
```
主编 skill：csw-task trigger daily_news --subject 2026-06-09 --inputs "采集6/9露营装备上新"
  └ POST /api/v1/workflows/daily_news/runs   Bearer <主编>  Idempotency-Key:k0
     body: {"subject":"2026-06-09","inputs":{"采集要求":"采集6/9露营装备上新"}}
```
`201 → {"run_id":10,"status":"active","tasks":[{"task_id":101,"stage":"01-采集","status":"ready",...},{102..."blocked"},...]}`
**DB**：`runs`+1；`tasks`+10（101=ready，余 blocked）；`task_deps`、`task_gates`(每 task 两道) 快照；`events`:run_created、task_ready(101)。

### 步 1 · 主编派工 01（入口无上游 → 预填空）
```
主编 skill：csw-task dispatch 101 --note "采集6/9：露营装备上新；IG+小红书+网页；≥5条多图"
  └ POST /tasks/101/dispatch
```
`200 → {…,"instructions":"<01-采集作业手册…>","self_check_criteria":"<01 提交前自检清单…>"}`
**DB**：`deliverables`+1001(派工单,issued)；`tasks`.101→dispatched（带 instructions+self_check_criteria 快照）；`events`:dispatched。
> 派工单自动带 01-采集作业手册 + 自检标准（定义快照）；情报收集员据此开工、交付前据自检标准自查、全过才提交，不再翻 md。

### 步 2 · 情报收集员 查 → 下（无）→ 上传 → 提交
```

csw-task upload 资讯日更_情报收集员_20260609_v1.zip
  └ POST /files (multipart) → 201 {"file_id":5001,"download_url":".../files/5001","sha256":"ab12…"}

  └ POST /tasks/101/deliverables → 201 {"deliverable_id":1002,"version":1,"task_status":"review","cur_gate":0}
```
**DB**：`files`+5001；`deliverables`+1002(资讯包,v1,file=5001,submitted)；`tasks`.101→review,cur_version=1；`events`:file_uploaded、submitted。

### 步 3-4 · 主编双闸
```
csw-task review 1002 --pass --comment "来源齐"          → 闸1(editor) pass，该版本 cur_gate=1
   （审核界面随附 01-采集验收标准：来源平台✓ 链接可达✓ 去重✓ 图清晰充足✓…，主编对照判定）
```

### B.6 后台边界（要点）
- 后台**不出现**派工/审核/提交按钮——属运行面，agent 经 `csw-task` skill 操作。
- 运行监控**只读**：可看产出/派工单/时间线（拉自 events + deliverables），不可操作流程。
- 编辑产出新版本，「校验并激活」后旧版本自动归档（对应版本模型）。
- 形态：先 `adminctl` CLI 提供等价能力（建/校验/激活/列表），后续升级 Web 控制台。
