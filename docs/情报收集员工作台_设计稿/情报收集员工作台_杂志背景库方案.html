1. 已定决策

# 决策 结论
1 类型 新增第五类 magazine_item（杂志背景）。不并入现有四类：它不是 CSW 报过的（不参与查重）、不是 Van 认可的写法、不是她选过的、不带她的原话
2 用途边界 阶段一只进检索（文字检索、以图搜图、品牌页、MCP），不进判断第 4 步的对照材料；阶段二看过命中质量再定是否作为第六组「背景参照」进 judge::materials
3 llm_wiki 刊译台不再导入 llm_wiki，出口改为「上传 OSS + 写清单」
4 OSS 复用 cws-file（oss-cn-guangzhou），前缀 kb/magazine/，公开读（刊物已有版权，仅公司内部使用），返回公开地址，不做签名
5 网络 centos9 不是阿里云 ECS，上传走公网
6 向量 用本项目的 Qwen3-VL-Embedding（agent 主机 127.0.0.1:8022）计算，不在 AutoDL 预算
7 上传范围 裁图原尺寸 + 整页图 2400px 都上传
8 向量范围 只算 has_content=1 && skipped=0 且 category != decor 的裁图；整页图不算
9 回填方式 可让路的空档回填，分两遍：先融合向量，后纯图向量
10 栏目级内容 暂不入库（以后可作为子类型补入栏目摘要与正文）
11 以图搜图索引 先实测暴力扫描延迟，超过约 200 ms 再给 images 表建索引
12 设计稿 先补设计稿，两边前端照设计稿实现
13 品牌别名表 杂志品牌不自动扩充别名表（ZERO、STORM、REI、COAL 这类会全文误命中）；要加走人工、source='kb'
14 数据源 centos9 /opt/goout 全部（174 本 PDF + 2019.12 的 jpg），加进刊译台 import_roots 直接读，只读不写
15 ARCHIVE 合本 跳过（4 本 705 页），单期全部入库后再议
16 导入顺序 由近到远：2026 → 2014，别册穿插在对应年份后
17 刊译台模型 gpt-6.1-sol，走与主编 Hermes 相同的 sub2api 通道（https://csw-subapi.833233.xyz/v1、Responses API），但用刊译台单独的密钥（不与主编共用，避免批量期挤占 05:30 正式轮的按用户并发上限）；密钥只存 ~/.csw-kb/env（本机 + centos9），2026-10-07 已切换，生产 smoke 5/5 通过
18 工作台入库状态回传 不走 HTTP：工作台入库后在清单旁写 ingested.json，刊译台读文件显示
19 book_key 沿用刊译台按文件名派生的键（book_key_of），catalog.csv 只做映射，不改生成规则
20 OSS AccessKey 存 ~/.csw-kb/env，不进 settings 表
21 解析通道与策略 两条通道：MinerU 云端免费额度（每天 1000 页，单本 ≤200 页且 ≤200 MB）与自建 MinerU（AutoDL Pro 实例）。settings parser_strategy：auto（默认，云端优先，额度用完或单本超限自动切自建）/ cloud（只用云端，超限报失败、额度用完留队等次日）/ self（只用自建）。每本在开始解析（上传段）时判一次，判定的通道与原因写进任务（tasks.parser、tasks.route_reason），之后轮询、取结果都按任务自己的通道走，不随设置变化；所以排队中的书次日额度恢复后会自然回到云端。额度按北京日期本地记账（tasks.quota_date 累计页数），云端返回 -60018（当日上限）时当天剩余额度记为 0。auto 下云端提交失败（网络 / 鉴权）不阻塞，当本切自建并记原因。现有调度器的解析段在等待远端时不占用并发名额，云端与自建本来就能同时解析，调度准入不需要改
22 AutoDL 实例 10-08 换为容器实例 Pro（北京 B 区 RTX 5090，uuid pro-791490d33583），开关机由刊译台直接调 AutoDL 开发者 API（决策 23、24）。刊译台改走 api 后端直连公网映射地址（6006 → https://u316109-791490d33583.bjb2.seetacloud.com:8443），nginx 做 Bearer 令牌校验（env MINERU_API_TOKEN），不再 scp + ssh；实测 CentOS → 实例 HTTPS 约 2 MB/s
23 AutoDL 自动开关机 刊译台自己开关实例（10-08 已实现并闭环实测，csw-kb/src/autodl.rs）：api 后端下任务进上传段发现实例关机 → power_on（带 start_command 拉起 nginx + API，约 35 秒在线）；解析段空闲 autodl_idle_off_minutes（默认 15）且开机满 10 分钟 → power_off。不再手动开关
24 页面内开关机 设置 · 解析服务页有「立即开机 / 立即关机 / 刷新状态」，由刊译台后端直接调 AutoDL 开发者 API（power_on / power_off / status），不需要登录服务器或命令行；有自建任务在解析段时拒绝关机。开机后在实例内拉起服务的脚本（AutoDL start_command 参数）作为程序内置默认值，不在页面上暴露

超过 200 MB（21 本，不含合本） 刊译台原先拒收超过 200 MB 的 PDF（MAX_BYTES），2025 年正刊多在 350–449 MB。已定：上限改为 700 MB（2026-10-07 改代码，未部署）；大文件上传 AutoDL 更慢，计入 §2.2 解析段瓶颈

处理顺序 （已定）由近到远：2026 → 2025 → … → 2014，别册穿插在对应年份后。近年的对当下选题更有用，批次中途停也不亏
云端实测（10-08，1 页） file-urls/batch → PUT 预签名地址 200 → 约 15 秒 done → 下载 zip。zip 内：layout.json（pdf_info[].page_size / para_blocks，与自建 *_middle.json 同结构）、*_content_list.json、*_content_list_v2.json、*_model.json、full.md、images/、原 PDF；元数据 _backend=hybrid、_effort=medium、_version_name=3.4.4。当日上限错误码 -60018、任务不存在 -60012。同一封面页云端只切出 2 块（1 文字 + 1 整页图），自建切出 14 块——两路版面结果有差异，2a 验收要用整本（GO OUT 2016.06）对比裁图数与商品覆盖，差异大则 auto 策略需重新评估
解析路由（决策 21、22） 每本开始解析（上传段）时判断：页数 ≤200 且文件 ≤200 MB 且当日云端剩余额度 ≥ 页数 → cloud；否则 → api（AutoDL Pro 实例，HTTPS + Bearer）。当日额度用完时走 AutoDL：实例关着会被刊译台自动开机（决策 23），用完自动关。云端批次：POST /api/v4/file-urls/batch（model_version=vlm、language=japan、is_ocr=true、data_id=book_key）→ PUT 预签名地址 → 轮询 GET /api/v4/extract-results/batch/{batch_id} → 下载 full_zip_url。两点要在演练时核：云端 zip 里是 layout.json（自建 mineru-api 返回的是 middle.json），s3 解包要兼容两种命名、bbox 单位一致；云端 zip 不支持 return_images=false，会带全部图片，体积比自建的 ≈1 MB 大得多，走 CDN 下载应不成问题
超限书的处理 非合本里超 200 页 3 本、超 200 MB 21 本（其中 1 本两项都超），共 23 本走 AutoDL。可选优化：开 upload_downscale 降采样后上传，20 本「只超体积」的书也能走云端（裁图在本机按原 PDF 做，降采样只影响版面检测），AutoDL 只剩 3 本——是否开启看两本演练里降采样对 bbox 的影响
模型代理 4.5 天连续调用，代理曾三次整段 503、且有按用户并发上限；刊译台用单独密钥（决策 17），不挤占主编 05:30 正式轮。10-07 探测时单独密钥首次请求也回了 429 gateway_concurrency_limit，说明网关限额可能按账号而非按密钥——首本批量时在 05:00–07:30 观察主编侧是否受影响，受影响则加时窗把 max_model_tasks 降为 0

3. 架构

  s1–s7 不变                                             kb sync（五路，各报各的）
  s8 上传 OSS ──公网──▶ cws-file/kb/magazine/            ├ sync_magazine：读本机清单 → kb_docs + kb_doc_images + 全文

  读 ingested.json 显示入库状态   ◀──本机文件──  入库后写 {book}/ingested.json
                                                         检索：杂志文字检索 · 以图搜图 · 品牌页 · MCP
                                                         图片展示：OSS 公开地址
  • 契约是清单，工作台不读刊译台的库；反向只有一个 ingested.json（条数、融合 / 纯图向量进度、时间），刊译台读文件，不调工作台 HTTP（免账号与 CSRF）。
  • 清单放在 OSS 公开前缀下，含全文译文与商品表；按决策 4 可接受（内部使用），这里明说。
  • 算向量读本机文件（两服务同机），不从 OSS 下载，不产生流出费。
  • 对象名用图片内容的 blake3：kb/magazine/{h[:2]}/{h}.jpg，与 LanceDB images 表主键同值；重复上传幂等，跨期重复的广告图只存一份。

4. 清单格式 manifest.jsonl

每本一份，位置：本机 {产出目录}/{book_key}/manifest.jsonl，OSS kb/magazine/manifests/{book_key}.jsonl。清单最后写：有清单 = 这一本的图已全部上传。每行一张裁图：

字段 说明
book_key 刊译台文件名派生键，如 goout-16-08日本、GO-OUT-2025.03；整本对账与清理的键
magazine / issue / issue_date 刊名、期号、刊期（如 2016-08-01）
image_id 刊译台 image id（task_id:pdf_index:seq，主键稳定）
pdf_index / printed_page / bbox_pt 页与位置
section_title_zh 所属栏目
category / has_content / skipped 刊译台的图分类与标记
description / md_zh 图片描述、中文译文
products 商品数组（brand、name、price_jpy、tax_included、specs）
image_blake3 / image_url / local_path / width / height 裁图；image_blake3 参与工作台 content_hash（换图触发重算）
page_blake3 / page_url / page_local_path 整页图（2400px）
manifest_version / generated_at 契约版本与生成时间

9. 护栏（必须有单测）

  1. 判断路径（materials / 默认检索）召回不到 magazine_item；且库里塞 10 万条杂志后，四类检索的 top-K 不丢（验证 LanceDB only_if 在当前版本是前过滤）。
  2. 以图搜图命中经 kb_doc_images 能回到条目与 OSS 地址。
  3. kb purge --book 后 kb_docs、kb_fts、kb_doc_images、docs 表向量一致；被其他书引用的 images 向量保留。
  4. 杂志检索对同一本书能返回多条（post_id 为空，不被 dedupe_by_post 合并）。
  5. 重新解析一本书后 sync_magazine 对账删掉旧 ref_id，不残留。
  6. 清单缺失或未写完的书不入库；坏行跳过并计数，不让整份失败。
  7. 回填任务在正式轮开始后不再取新批。
