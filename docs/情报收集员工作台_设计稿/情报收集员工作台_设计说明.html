情报收集员工作台Web 客户端 · 设计说明与流程设计图

把改造方案里的「自定义客户端」做成一个 Web 应用：后端仍是常驻的采集服务，前面加一个工作台，让主编、研究员、Van 和开发在同一张打分台账上看到每天的全部候选、每条的依据与缺口，并把人的决定回收成记忆。引擎仍是唯一真相。界面设计稿另见《情报收集员工作台 · 界面设计稿》。

1. 设计目标

目标 落在哪
每天的候选一条不漏、每条有分有据 打分台账：全量事件、六维度分、依据、三句话、缺口
看图判断 台账与详情里直接看代表性实图与完整图集；读不到图的如实标记
不因口味淘汰，人可以随时捞回 台账默认显示全部，硬性排除也能展开；一键捞回
人的决定沉淀为记忆 Van 与主编在台账上的每次决定，连同当时的维度分一起入库
缺什么说清楚 采集与覆盖页：来源、看图覆盖、失败、待补录账号；待核结转页：缺口与期限
权重和准则可调且可回测 判断框架页：维度定义、锚点、权重版本、用历史决定回测
对开发透明 运行页：模型调用、耗时、费用、失败与重试、版本

2. 用户与场景

谁 什么时候来 主要动作
主编 每天 05:30 后到 07:00 前 看总览与台账；确认首批；捞回、改判；看覆盖与缺口；处理失败
研究员 首批之后 逐条评估入围事件：依据、查重对照、知识库命中、案例；补证或标待核
Van 07:15 前，以及她愿意的任何时候 看排序表直接勾选、否决、暂缓并留一句话；校准准则卡；查范例
开发 随时 运行状态、模型调用与费用、配置与版本、回放历史窗口

Van 的决定仍经引擎的 03 闸生效；工作台上的勾选先记为「Van 选择」并进入记忆库，主编据此提交选题方案。

3. 系统位置

  • 采集服务（Rust，agent 主机）：采集媒体信息、合并、对照材料、逐条判断、深核、登记、交付；内嵌 LanceDB 存知识库索引、候选与判断台账副本、图片；向量与重排调自部署的 Qwen3-VL 服务；同时提供工作台需要的本地接口（台账、线程记录、运行状态）。
  • 工作台前端（React + Vite + Tailwind，与管理后台同栈）：由采集服务托管静态文件；登录复用管理后台的用户与 JWT，角色沿用 superadmin / operator / viewer，另加「van」视图。
  • 引擎：任务、条目、采集轮、判断台账、交付物、刊发记录、决定、选题记忆的真相；工作台经采集服务代理读写。
  • 管理后台不变：定义、成员、监控。工作台不复制它的功能，只在需要时跳转。

4. 每日流程与工作台的对应

流程步 工作台上看到什么
A 取全量 总览的「采集进度」；采集与覆盖页的采集轮、来源状态
B 硬事实与事件合并 台账里合并后的事件，展开可见合并了哪几条贴文；窗口外的在「硬性排除」分组
C 查重 事件卡上的查重标记：重复无新增 / 同品牌有新增 / 不相干，附对照旧文
D 打分 台账的六维度分、综合分、依据、三句话、缺口、看图标记
E 深核 详情页的证据链接、原始披露时间、比较参照核实、完整图集
F 登记与交付 事件的引擎条目状态、首批提交状态、补件记录

5. 一个事件的状态

状态 含义 谁改
已合并 贴文合并成事件，尚未打分 代码
已打分 有六维度分与依据 模型
硬性排除 窗口外 / 与正式已发布同一事实且无新增 / 与近期被否同一事实同角度 代码或模型，可捞回
待核 缺资料、缺图或读不到图，写明缺口 模型或人
入围 进入深核 排序或人
已登记 已成引擎条目 代码
Van 选择 / Van 否决 / Van 暂缓 她在台账上的标记，附原话 Van
结转 / 关闭 待核转入后续期次，或到期关闭并写明原因 代码

6. 页面清单与内容

6.1 今日总览

  • 顶部：期次、窗口（前一天到当天）、当前阶段、距首批时限倒计时。
  • 四张数字卡：贴文全量（取到 / 库内计数是否一致）、事件数（合并后）、已打分（应为 100%）、看到实图的比例。
  • 进度条：取数 → 合并 → 查重 → 打分 → 深核 → 首批提交，各步耗时。
  • 告警：来源失败、读不到图的事件数、模型调用失败与重试、超时。
  • 快捷入口：入围前 10、待核、硬性排除里高分的（提醒主编看一眼）。

6.2 打分台账（核心页）

  • 列表行：缩略图 1–2 张 · 品牌｜一句话标题 · 账号与发布时间 · 综合分 · 六维度迷你条 · 类型 · 优先/降低命中标签 · 查重标记 · 三句话状态（已答 / 缺资料 / 角度未成立 / 价值不足） · 缺口数 · 状态 · 来源（系统 / Van 链接） · 操作。
  • 左侧筛选：状态、类型、查重结果、三句话状态、来源、账号、维度阈值、只看有图。
  • 顶部工具：权重版本切换（改权重即时重排，不重跑模型）、排序字段、分组（按状态 / 按类型）、导出。
  • 展开行：六维度依据各一句、三句话全文、缺口、合并的贴文清单、知识库命中、案例命中、查重对照。
  • 操作：加入首批 / 登记条目 / 标待核 / 捞回 / 人工改判（记录人与理由）。
  • Van 模式：只显示品牌、标题、图、三句话与综合分；每行三个按钮「采用 / 否决 / 暂缓」和一格原话；她的标记即时写入记忆库并在主编视图上显示。
  • 默认排序：综合分；硬性排除折叠在底部分组，随时展开。

6.3 事件详情

  • 左：完整图集（懒加载）、所有合并贴文的原文与账号信息、原始披露时间与转载时间。
  • 中：六维度分与依据、外观与设计观察、三句话、优先/降低命中、缺口清单。
  • 右：查重对照（旧文标题、日期、发布状态、是否有新增信息）、知识库命中（相似旧文、品牌历史）、案例命中（Van 的原话）、深核结果（证据链接、核实的事实、比较参照是否准确）。
  • 底：审计——每次模型调用的阶段、耗时、token、模型版本、准则版本、权重版本；人工操作记录。

6.4 采集与覆盖

  • 采集轮表：来源、工具、时间窗、接口返回、去重后、窗口内、已打分、看到图、失败原因。
  • 来源台账：必扫来源的状态、最近成功时间；Van 补充的来源标为普通来源。
  • 待补录账号清单：出现在选题里却不在册的账号，各自依据（哪篇推文 / 哪天指定），一键导出。
  • 图片：下载成功率、读不到图的事件与原因。

6.5 待核结转

  • 列表：事件、缺口类型（缺发售日期 / 缺官方来源 / 图不足 / 读不到图）、首次出现期次、剩余期数、上次重评结果。
  • 操作：补证后重评、人工关闭并写原因。

6.6 刊发知识库

  • 检索：全文检索 + 品牌别名；结果带发布状态标（正式已发布 / 参考范文 / 未发布稿件）。
  • 品牌页：该品牌的历史报道时间线、角度、近 30 / 90 天是否发过。
  • 同步状态：最近同步时间、覆盖到哪一天、缺口清单、失败记录。
  • 范例：十篇正面范例与逐条拆解（选题对象、切口、读者价值、比较参照、编辑判断），标注哪些是待核推断。

6.7 选题记忆

  • 准则卡：每条规则 · 身份（具体案例 / 模型推断 / 本人确认） · 原话与日期 · 对象与适用条件 · 状态。
  • 案例库：候选摘要、结论、原话、关联的贴文与期次。
  • 覆盖清单：回收了哪些会话库、时段，哪些读不到。
  • Van 校准模式：逐条「对 / 不对 / 改成……」，提交后规则升级为「本人确认」。
  • 写作表达一线在此只显示入口，内容交主编与文案页面。

6.8 判断框架与权重

  • 六个维度的定义与每级锚点（引用范例或被否案例）。
  • 权重版本表：版本、权重、生效期次、谁改的、为什么。
  • 回测：用历史上 Van 的决定，看当前权重下这些条目的排名分布；重复打分一致性。

6.9 指标

  • Van 的三项：自主发现情况（采用条目里系统先于她发现的比例）、第一轮推荐质量（首轮推荐数 / 采用数 / 补选轮次）、她的实际投入（审题用时、补链接次数、补充说明次数）。
  • 技术指标：审阅覆盖、看图覆盖、来源覆盖、召回、01 用时。
  • 按期次折线，可选区间。

6.10 运行与设置

  • 服务状态：采集服务、Codex App Server、本地 MCP、csw MCP 连接；版本固定情况。
  • 模型调用：按阶段的次数、耗时、token、费用；失败与重试；线程记录下载。
  • 设置：来源台账维护、并行数、缩略图张数、待核结转期限、权重版本切换（改动写审计）。
  • 回放：选一个历史窗口重跑取数与打分，用于调参与验收。

7. 数据来源与接口

页面数据 来源
贴文、媒体 csw 新接口 posts/window（经采集服务）；图片走 OSS 缩略参数
事件、结论档、逐维依据、缺口、对照结论 引擎 intake_judgements（真相）+ 采集服务 LanceDB（进行中的）
采集轮、来源台账、条目、交付物 引擎既有接口
知识库检索、相似已选贴文 采集服务 /kb/*（LanceDB 向量 + 全文 + Qwen3-VL 重排）
刊发记录、决定、记忆、准则 引擎 /ledger/*、/memory/*、/rubric/*
线程记录、模型调用、服务状态 采集服务本地接口
Van 与主编的标记 写引擎（条目决定、反馈记录），同步进记忆库

工作台不直接连 csw 后端与模型服务；所有外部访问都经采集服务。

8. 权限

角色 能做
viewer 只读全部页面
operator（主编、研究员） 台账操作、待核处理、来源维护、回放
superadmin（开发） 以上加设置、权重版本、服务操作
van Van 模式的台账、准则校准、范例与指标；不显示运行与设置

所有写操作记录操作者与时间，可在事件详情底部与审计里看到。

9. 技术要点

  • 采集服务 csw-task/csw-collector/：Rust（axum + LanceDB + reqwest），单个静态二进制，systemd 常驻；Codex App Server 协议与客户端直接用 codex 仓库的 crate，MCP 用官方 rmcp；LanceDB 单进程写入，采集服务独占数据目录。
  • 前端 csw-task/csw-collector-web/：React 18 + Vite + TypeScript + Tailwind，与管理后台同栈；表格虚拟滚动（一天几百条）；按档分组与排序在前端完成；图片懒加载。
  • 采集服务提供 /ui/* 静态托管与 /api/* 本地接口；JWT 校验复用管理后台的密钥。
  • 台账的每一次人工操作都是幂等写引擎，带 Idempotency-Key。
  • 手机宽度可用：台账在窄屏下按卡片排列，Van 模式优先适配手机。

10. 需要拍板

  1. 工作台由采集服务托管、复用管理后台登录——还是并入管理后台成为一组新页面。
  2. Van 在台账上的勾选是否直接等同于 03 闸的决定，还是只作「Van 选择」由主编提交。
  3. 第一期只做哪些页面：建议总览、打分台账、事件详情、采集与覆盖、待核结转五页先上，其余随知识库与记忆建设推进。
