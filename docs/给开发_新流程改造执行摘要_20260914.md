## 先改六件事

1. **修运行故障与接续。** 查明压缩402对应的实际调用；交件、补件、人审批准进入可靠队列，及时触发主编或下游。报告显示真实任务与产物，不以网关running、任务解锁或定时播报代替工作。
2. **拆开条目与整期状态。** 批准一条选题即可推动该条写作；整期数量不足继续记缺口。取消对原始资料、机械包装的例行Van审批，公众号常规人审保留选题与全文两类。
3. **将选题判断前移。** 研究员收到原文与视觉预览就判断价值；主编送审前亲自看图、近期发布及整期组合。先筛掉不值得写的题，再投入完整配图与补证。
4. **调整主编和交付岗位。** 文案写首稿，主编有有限定点编辑权；一轮修订仍失败就改变处理方式。publisher按批准模板组版和打包，chief审结果；机械字段、引用与通知由程序处理。
5. **同步真实发布与选择反馈。** 开发先回填近期人工及智能体发布的内容，拆出合集内各条资讯，再做最小自动同步。用户不再手工发链接；显示同步覆盖和缺口。正常选题决定直接沉淀，不再让用户额外打分。
6. **核实#63报告和动作边界。** 回放15:24记录，区分解锁、真实派工和实际执行。只允许本地演练的任务，上游通过后不得自动进入公众号后台。当前没有实际后台保存或发布证据，先核事实。

## 九个角色怎样调整

| 角色 | 主要变化 |
|---|---|
| chief | 保留选题与最终质量责任；增加有证据的定点编辑权；到件及时处理；减少亲自组包和维护多套状态 |
| collector | 先提供可判断的原文和预览，逐条衔接；只为高潜力候选补齐关键事实和最终配图 |
| researcher | 提前看图、查近期文章、筛选审美和差异价值；降低机械评分与“资料齐即好题”的权重 |
| deepwriter | 专注公众号；首稿和协作修改分开留存；判断增加使用条件，避免补字数和技术术语堆积 |
| designer | 维护已批头尾图、品牌资产与模板；原图排版和真正生成任务分开；补件触发组版接续 |
| publisher | 承担模板组版、完整包、平台操作与回读；对不确定保存先查询，避免重复草稿 |
| xhswriter | 正式承接小红书改编，替代日更07的重复分工；不让公众号后台状态阻塞文字改编 |
| reviewer | 在确有事实或素材使用问题时并行介入，明确到句图；不新增整期无差别串行审核 |
| analyst | 维护发布、选择反馈和双平台表现；把发现接到具体岗位动作，追踪执行版本和复查结果；不作为日更发送前的审批岗 |

角色文件、共享规范和引擎条件要一起更新。已有的正确内容要求无需重复叠加；日常与演练的限制要分开，过期的冻结任务不得污染下一期。

## 数据复盘必须推动下一次运营

自动同步解决“发过什么”，数据复盘还要做到“发现问题→chief决定→岗位执行→复查结果→更新或撤回经验”。完整机制已加入主方案第7.4至7.10节。

- 公众号重点看实际可得的阅读来源、打开表现、阅读深度、分享与持续关注；小红书重点看曝光到阅读、收藏分享、搜索长尾和关注贡献。开发先核实账号字段与权限，不能承诺所有指标都能自动取得。
- 建议保留发布后24小时、72小时、7天快照，小红书等长尾内容增加30天；比较同平台、同类型、同龄内容，区分自然与付费，缺数据不当作零。
- 合集整篇阅读量不能自动归到每则选题；两平台不同计量不能直接相加或混排。账号净增也不能随意归因给某篇内容。
- 每周最多推进两项明确改动，记录数据依据、负责人、内容版本、截止及复查指标；封面交designer、表达交平台作者、选题交researcher／chief、分发与格式交publisher。
- 每项结果标为支持、不支持或证据不足，适用规则有平台和内容边界。高流量不能覆盖事实要求、CSW定位和Van明确审美选择。
- 验收至少完成一个真实的“发现—任务—修改—复查”周期；只交报表或只派工不算闭环。数据分析不新增晨间审批、不恢复已暂停的监测任务。
