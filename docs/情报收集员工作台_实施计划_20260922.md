## 关键设计决定

1. **工作区** `csw-task/csw-collector/`（Cargo workspace，edition 2024）：`core`（类型、配置 env > 文件 > 默认、rusqlite 本地库、录制回放层）、`engineapi`、`harvest`、`kb`、`judge`、`deepcheck`、`deliver`、`mcpsrv`、`collector`（bin：axum + CLI `serve | run --manual | replay | kb sync | kb import | mcp | p5`）。**结构化数据全在 SQLite，LanceDB 只放向量**（2.2 万向量不建 ANN 索引；写入经单写者任务成批 append，optimize / prune 只在夜间；每轮记 `kb_snapshot` 表版本）。「上一轮台账」留在 SQLite，不进参考库，避免系统自己的判断被当成口味证据。
2. **全文与品牌命中**：主路是「别名表 + 代码精确匹配产出 brand_keys」（品牌名多为拉丁文、假名、两字中文，分词器都切不稳）；辅路全文在阶段 0 实测后二选一——默认按总方案用 LanceDB 内置 jieba，若命中率不达标或踩到 #9016，则换 SQLite FTS5（unicode61）+ `jieba-rs` 预分词（别名作自定义词典），检索接口不变。
3. **codex 客户端自写薄 stdio 客户端**（推翻总方案 §11.1 / 开发版 §7.7 的 path 依赖：`codex-app-server-protocol` 会拖进 500+ crate，版本 `0.0.0` 锁不住，本地 main 与生产 0.155.1 不同点）：`tokio::process` + NDJSON + `HashMap<id, oneshot>` + `mpsc`，只为用到的 6–8 个类型写 serde 结构，其余 `Value` 兜底。
4. **登录用 BFF 会话**：浏览器 → 采集服务 `/api/auth/login` → 转发引擎 `/admin/login`；引擎的 access 与 refresh token **只留在服务端会话表**，浏览器只拿不透明会话 cookie（HttpOnly、Secure、SameSite=Lax）；服务端按需向引擎 refresh，角色取自 `/admin/me`；写接口加 CSRF 校验。Van 模式 = 配置里列出的 viewer 用户名映射为 van 角色，勾选只写本地。
5. **时间预算靠「预取缓存 + 优先流水线」**。GPU 串行是瓶颈：向量化约 9 分钟 + rerank 12–18 分钟 + 识别 5–7 + 判断 3–5 + 深核 10 ≈ 40–50 分钟，周一约三倍，不处理必超时。① **预取轮**（`kind=prefetch`，每天 01:40，贴文库入库后）跑第 2–5 步，只写本地缓存、不写引擎、不群播报。它是缓存不是前置条件：没有缓存整轮也能从零跑完，只是慢。② 05:30 接单后的正式一轮**重新取一次窗口**（约 2 秒，采集轮计数以这次为准），各单元按 `inputs_hash`（正文、描述版本、对照材料、准则版本、作业标准哈希、模型与提示词版本）命中即复用，只补增量、深核与登记——派单仍是流程起点。③ rerank 只排文本、每条 ≤24 段，同 post_id 直判已报的跳过；GPU 设优先级队列，05:25–06:30 暂停知识库回填；05:25 预热 csw-agent。④ 判断按 Jev 初评优先级流式推进，凑够 4 条推荐就开始深核，首批先交，其余判完以补件追加。
6. **本地状态（可重跑、可续跑、写引擎幂等）**：`rounds`（kind = task / manual / prefetch / replay；trigger = dispatch / returned / supplement / manual；run_id、task_id、target_version、parent_round_id、方案与准则版本、kb_snapshot、instructions_hash、UTC 窗口；`UNIQUE(task_id, target_version, trigger)` 防重复开轮）、`round_steps`（attempt、status = pending / running / succeeded / partial / failed / skipped / stale / interrupted、input_hash、counts_json；重跑一步 = 新 attempt 且下游置 stale；重启时 running → interrupted 再续跑未完成单元）、`candidates`、`round_candidates`、`media`、`media_descriptions`、`embeddings_log`（LanceDB 重建依据）、`events`、`materials`、`judgements`（带 inputs_hash）、`judgement_overrides`（人工改档另存）、`deepchecks`、`model_calls`、`engine_outbox`（seq、kind、body_sha、depends_on、idem_key、status = pending / sending / confirmed / conflict / dead）、`deliverables_local`、`task_mirror`、`sessions`、`van_marks`、`plan_versions`、`audit`。引擎状态对应：dispatched → 建轮并 ack；in_progress → 步 1–7，每 2 分钟 ack；review → awaiting_review 只轮询；returned → 开新轮（挂 parent）；passed → supplement 轮，每期合并一次；failed / cancelled → 停心跳、打断深核。
7. **提交幂等**：zip **只构建一次**，字节、sha、幂等键、表单字段先落 `deliverables_local` 与 outbox 再发，重试只发已落盘文件；遇 `idempotency_in_progress_or_uncertain` 不换键，先查任务状态对账。确定性生成作第二道防线（路径字节序、固定 mtime 与权限、JPEG 用 Stored、文本固定 Deflate 级别、JSONL 键序固定、`index.md` 不写当前时间）。zip 上限 48 MiB。写入顺序 items → sweeps → judgements 分批 → intake-check → submit。
8. **Jev 与模型降级**：Jev `JEV_ENABLED` + 密钥存在才启用，不可用时窄判断退回生成模型、初评跳过并在台账标注；生成模型在同网关内 `gpt-6-astra` → `gpt-5.6-sol` 降级；网关整体不可用则 `fail` 上报（第二条模型通道由你另定，见文末）。每日 token 预算熔断。
9. **时区**：内部全部 UTC；csw 库 UTC、引擎窗口 `+08:00`、周一回溯到上周五；`start` / `end` 日期语义写死并做属性测试；「上次运行之后」的水位在回退的日子也要推进；界面显示北京时间。
10. **构建**：`cargo zigbuild --release --target x86_64-unknown-linux-gnu.2.34`，rustls 选 `ring`（避开 aws-lc-rs 的 cmake / nasm）；不过则 B：agent 主机 `systemd-run --scope -p MemoryMax=6G -p CPUWeight=20 cargo build --release -j 4`（须同意）；C：你提供一台临时 x86_64 主机。
11. **高风险项实现但默认关闭**：小红书采集器（与 Hermes 共用登录态 Chrome → 主机级文件锁、验证码熔断、不进 05:30 关键路径）；外部命令 / HTTP / MCP 自定义采集器（总开关、仅 superadmin 登记、固定目录、不经 shell、清空环境变量）；网页采集器（解析后钉 IP，封内网、`127.0.0.1:8022/8090`、云元数据地址）；`mcpsrv` 的 `fetch_page` / `xhs_search` 不进深核白名单，给 Hermes 的挂载默认关；P5 做成离线 CLI，`immutable=1` 只读打开会话库，每次运行单独征得同意。
