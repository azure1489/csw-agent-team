# CSW 选题交付改进方案

状态：2026-09-16失败复盘后的编辑作业改进方案；不是已验证成功的方法，不是新派工或试验授权。不重开r42，不修改引擎工作流/SLA/定时任务/Van审核窗口。原6主2备、默认窗口与两审不变；正式流转以csw-task及引擎任务为准。

## 1. 前置已发与未采用基线
owner=主编维护、采集/研究使用。开工使用同一份已发条目索引、昨日未采用理由及有效反馈；每条记录品牌/型号/已讲角度/全文链接或本地文本。合集拆为条目，与单发关联，不重复计数；最新缺文明确标注，不能要求Van逐次主动补全才排重。

## 2. 首批先校准判断，不先深挖少数对象
owner=采集首批供原文+时间+预览，主编立即校准。首批成形就读，而非研究整包做完才看。主编同时看拟采用和少量边界淘汰，判断是来源不足还是价值尺度错误。提供正例与反例：岩谷的小改动有摆放/拆洗意义，普通蓄光不能凭昼夜反差自动合格；日本品牌优先不是地域唯一门槛。无需人人填长篇点击/收藏假设来包装弱题。

## 3. 两道轻量检查后才投入深研究
owner=researcher，editor验收。A价值：是什么、变化/设计/文化看点是什么、CSW读者为何看；据现有官方原文和预览判断。B资格：新披露或转发、具体型号历史、已发/未采用对照、时间窗。A和B都成立再深入。关键事实不明标待核，不计成熟备选；只有确定归属而非秒级精度影响入窗时，不把秒级时间作为额外硬门槛。核心时间冲突不得忽略。

## 4. 每次补证必须能改变采用决定
owner=主编指定问题，研究员回答。派单仅写清一个会改变选题结论的核心问题、精确来源、预算/截止与停止条件；同一问题最多一轮定点补证。第二次仍无核心依据就停止该对象，不让补图/规格/历史归属无限占用采集。因价值低否决的题不通过换文案拯救。只是格式、来源归属或交件时间校正，不启动完整重审。

## 5. 用一个条目表追交付，控制整期关键路径
owner=主编。操作来源仍为引擎+content-calendar.md，不另建平行日历。分列线索、待核、成熟主选、成熟备选、Van获批，另记淘汰原因；首批提交与全部补采完成分开记录。各角色首批交齐就接续，但不得假称引擎支持未发生的自动派工。主编在原检查点主动看实物；缺量时先判失败原因，明确新增来源/改变方法及其证据，再决定是否值得下一轮，禁止无新增证据地滚动延时。需要改窗口/数量/交付安排时一次清楚提出决定、建议、影响，不以已拒减量反复询问。

## 6. 外部交付与验证
交付给Van的是实际图、可读题卡、主选/备选排序、具体增量/查重和真实缺口，不是ZIP路径、审计条数或任务版本。内部过程细节留文件/引擎；关键失败和必要决定及时说明，不能用少汇报隐藏延迟。
下一次经正常授权的生产，用既有验收评价：6主2备合格方案是否按约交付；重复/旧闻/低价值是否仍到Van才发现；同类返工是否下降；Van是否还需追问推动。记录采集至成熟方案的作业时间、主编处理等待、技术阻塞、Van审核等待，不能合并后归咎于人审。
