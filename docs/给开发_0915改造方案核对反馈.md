## 三、太模糊，需要明确的口径

### 3.1 “6主2备”是可调整的过渡方案

### 3.2 晨间选题缺量，必须交代原因和解决办法

“保留缺口”不足以说明接下来怎样完成工作。主编应在晨间送选题时一并说明，提前发现则提前处理：

- **差多少：** 主选、备选分别已有多少合格项，还缺多少。
- **为什么缺：** 区分当期有价值资讯偏少、采集漏项、近期已经发布、审美或内容价值不符，以及证据或图片不足；用实际候选说明，不能笼统归为“素材不足”。
- **怎样解决：** 提出具体补查来源或方向、责任人、完成时间，以及能否在现有窗口和质量要求内补齐；不要只要求Van放宽标准或亲自找题。
- **补不齐怎么办：** 交出已查范围、剩余缺口和明确建议，由Van决定是否接受当期减量或其他例外。未获确认不得自行扩大时间窗口或降低选题标准。已批准条目继续生产。

本期处理后，记录实际原因与处理结果，用于改进下一期的采集覆盖、去重和编辑筛选，不能每天重复汇报同一种缺量。

### 3.8 “批准后继续推进”和“主编可直接编辑”要有明确执行边界

Van的要求是：已批准工作自行接续，不因主编忙、通知失败或另一条选题未定而整期停住。开发应给出派工、接单、超时恢复的具体时限，不能以30分钟扫描替代正常接续，也不能再靠Van催促。

主编可定点修改反复未解决的问题，但修改后仍须检查最终全文与图文一致性，再送Van。不能把“直接进入Van审核”理解为跳过最后检查；反复返工时应改变处理方式或交代实际证据缺口，不按同一种方式无限退回。

### 3.9 首期就要改善选题，不等第2—3周才生效

**Van的首要诉求是尽快选得更准、减少补选和人工判断负担。** §8将发布同步、反馈记忆主要排到W2—W3，可以作为完整系统的开发批次，但必须另列首期能够实际使用的版本及交付时间，不能将业务效果一并后移。网页的首期可用条件和验收标准应据此补充。

首期选题提交前，至少落实以下四项：

| 首期必须做到 | 实际交付与执行 |
|---|---|
| 知道近期已发布什么 | 整理包含Van人工发布内容的近期发布记录，合集拆到具体资讯，保留品牌、产品、角度、日期和链接；研究员、主编在推荐前实际查重。列明覆盖范围与缺口，不能将记录缺失当成从未发布 |
| 用上已有审美与编辑判断 | 从已授权历史反馈中优先整理与本期选题有关的明确要求、采用／打回案例及对应图片。研究员看实际图片，主编结合具体变化、CSW价值及历史意见作取舍；不能只靠品牌、品类或热度判断，也不能把某一次否决推成永久禁选 |
| 交成熟的选题方案 | 送Van前完成来源与时间核验、图片查看、近期去重及主编筛选，说明具体变化和推荐理由。缺量按§3.2提出实际解决办法，已批内容继续，不让Van现场补做研究 |
| 新反馈及时进入下一轮 | 本期Van的选择与否决理由，连同对象、原话和图片，供下一次相关筛选使用。相同原因反复被打回时，主编调整判断与交接方法，不能只记录“已学习” |

**过渡方式由开发和团队落实：** 首期可以先复用共享资料、现有文件或简单可检索记录，不必等待完整数据库、自动导入器或全部历史回收完成。团队负责整理、维护和下发；不能将重复上传发布链接、整理偏好或手动导出重新变成Van的日常工作。完整自动同步与记忆系统继续按明确日期建设，过渡方式不能无限期取代自动化目标。

**从首期开始记录效果：**

- 首轮主选推荐数与Van实际采用数；备选另记，结合采用比例和实际条数判断，不能靠少报选题提高比例。
- 补选轮次，以及因已发布、审美不符、变化不足、证据不足等原因被打回的条目。
- 从采集启动到成熟选题送审的耗时、Van实际审题用时；可观测的回复等待单列，不能直接当作Van正在审题的时间。

优先利用可追溯的旧流程或近期演练记录作对照；没有可靠旧数据就如实说明，从首期建立基线，不编造改善比例，也不要求Van重新整理历史报表。第一期用于观察即时效果，连续几期判断改善是否稳定。**按时交出一份Van大多不想采用的清单，不能算选题优化成功。**

请开发与主编在回改中明确：首期使用哪份发布记录、哪份有效反馈与图片案例，谁负责准备和维护，何时可以在实际选题任务中调用，以及首期结果如何核对。若暂时只能跑通流转、尚不能改善选题，应明确报告这个差距和最短补齐时间，不能将其称为已满足首期优化目标。

两平台获取能力探针按§9.2的24小时建议前置，统一§8将探针放到W2—W3的冲突。通知接续、补件和定点编辑未上线时，需给出能够执行且经过验证的过渡办法。完整建设约3—4周的工期由开发按工作量核实，但不能让非首期必需的流程管理工具挤占选题改进与主线修复。各批次均写明实际日历日期。
