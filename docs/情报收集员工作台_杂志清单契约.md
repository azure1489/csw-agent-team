# 杂志清单契约（刊译台 → 情报收集员工作台）

> 契约版本 **1**（2026-10-08）。本文在两个仓库各存一份，**内容必须一致**：
> csw-kb `docs/09-杂志清单契约.md` · csw-agent-team `docs/情报收集员工作台_杂志清单契约.md`。
> 改契约 = 两边同时改 + `manifest_version` 加 1 + 工作台兼容旧版本至少一个发布周期。
> 方案出处：csw-agent-team `docs/情报收集员工作台_杂志背景库方案_20261007.md` §3、§4、§2.3。

## 1. 三个文件

| 文件 | 写方 | 读方 | 位置 |
|---|---|---|---|
| `manifest.jsonl` | 刊译台 s8 | 工作台 `sync_magazine` | 本机 `{output_dir}/{book_key}/manifest.jsonl`；OSS `kb/magazine/manifests/{book_key}.jsonl`（同内容，备查） |
| `ingested.json` | 工作台（入库后） | 刊译台（显示入库状态） | 本机 `{output_dir}/{book_key}/ingested.json` |
| `catalog.csv` | 人工维护（脚本生成初稿） | 刊译台 s8（填刊名 / 期号 / 刊期） | 仓库 csw-kb `catalog/goout.csv`；生产 `/data/kanyitai/catalog.csv` |

生产 `output_dir` = `/data/kanyitai/output`。两服务同在 centos9，**只走本机文件**：工作台不读刊译台的库，刊译台不调工作台 HTTP。

## 2. `manifest.jsonl`

### 2.1 写入规则

- **最后写**：裁图与整页图全部上传 OSS 成功后才写清单。**有清单 = 这一本的图已全部可用**。
- 原子写：先写 `manifest.jsonl.part`，`fsync` 后 `rename`；OSS 那份在本机写完后上传。
- 重新生成（重跑、换图、补译）整份覆盖，`generated_at` 更新。工作台按本对账：清单里没有的该书条目删除。
- UTF-8，每行一个 JSON 对象，**一行一张裁图**（含 `skipped` / 无译文的图，由工作台按字段决定是否建 doc）。行序：`pdf_index`、`seq_in_page` 升序。

### 2.2 字段

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| `manifest_version` | int | ✓ | 当前 `1` |
| `generated_at` | string | ✓ | 清单生成时间，RFC 3339 UTC（如 `2026-10-08T11:31:19Z`） |
| `book_key` | string | ✓ | 刊译台按文件名派生的键（`book_key_of`），如 `GO-OUT-2025.03`、`goout-16-08日本`；整本对账与清理的键 |
| `magazine` | string | ✓ | 刊名 / 系列，来自 catalog `series`（如 `GO OUT`、`GO OUT LIVIN'`） |
| `issue` | string | ✓ | 期号，来自 catalog `issue`（`2025.03` / `Vol.17`） |
| `issue_date` | string \| null | ✓ | 刊期 `YYYY-MM-DD`（正刊为当月 1 日）；别册未补时为 `null`，不阻塞入库 |
| `image_id` | string | ✓ | 刊译台 `images.id`：`{task_id}:{pdf_index}:{seq_in_page}`。同一次解析内稳定；**重新解析一本书 task_id 会变**，所以工作台以 `book_key` 对账 |
| `pdf_index` | int | ✓ | PDF 页序（0 起） |
| `seq_in_page` | int | ✓ | 页内裁图序（0 起） |
| `printed_page` | int \| null | ✓ | 印刷页码（读不到为 `null`） |
| `bbox_pt` | [number; 4] | ✓ | `[x0, y0, x1, y1]`，MinerU 版面坐标（原样取自 `images.bbox_pt`） |
| `page_size` | [number; 2] | ✓ | `bbox_pt` 所在坐标系的页面宽高（MinerU `page_size`），用于换算到整页图像素 |
| `section_title_zh` | string \| null | ✓ | 所属栏目中文名 |
| `category` | string \| null | ✓ | 刊译台图分类：`product` / `decor` / `ambience` / `infographic`，未分类 `null` |
| `has_content` | bool | ✓ | 刊译台判定图上有可提取内容 |
| `skipped` | bool | ✓ | 刊译台判定跳过（过小、装饰等） |
| `description` | string \| null | ✓ | 图片描述（中文） |
| `md_zh` | string \| null | ✓ | 该图对应的中文译文（Markdown）；`null` = 无译文，工作台不建 doc |
| `products` | array | ✓ | 商品数组，可为空；元素见 2.3 |
| `image_blake3` | string | ✓ | 裁图 JPEG 字节的 blake3（64 位小写十六进制）；参与工作台 `content_hash`，换图即触发重算 |
| `image_url` | string | ✓ | 裁图公开地址 `{oss_public_base}/kb/magazine/{h[0..2]}/{h}.jpg`（`h` = `image_blake3`） |
| `local_path` | string | ✓ | 裁图在 centos9 上的绝对路径（工作台算向量读它，不从 OSS 下载） |
| `width` / `height` | int | ✓ | 裁图像素宽高 |
| `page_blake3` | string | ✓ | 整页图（长边 `oss_page_long_side`，默认 2400px）JPEG 的 blake3 |
| `page_url` | string | ✓ | 整页图公开地址，规则同 `image_url` |
| `page_local_path` | string | ✓ | 整页图本机绝对路径 |

对象名用内容 blake3：同图重复上传幂等，跨期重复的广告图只存一份；与工作台 LanceDB `images` 表主键同值。

### 2.3 `products[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `brand` | string \| null | 品牌（原文） |
| `name` | string \| null | 商品名 |
| `price_jpy` | int \| null | 日元价格 |
| `tax_included` | bool \| null | 是否含税 |
| `specs` | string \| null | 规格 / 说明（中文） |

## 3. `ingested.json`

工作台每次处理完一本清单后**整份覆盖**（先写 `.part` 再 `rename`）。刊译台只读，不存在显示「待入库」。

| 字段 | 类型 | 说明 |
|---|---|---|
| `manifest_generated_at` | string | 本次入库所依据清单的 `generated_at`；与当前清单不一致 = 清单已更新、待重新入库 |
| `ingested_at` | string | 入库完成时间（RFC 3339 UTC） |
| `docs` | int | 本书在 `kb_docs`（`kind=magazine_item`）的条数 |
| `images_total` | int | 清单行数 |
| `fused_done` / `pure_done` | int | 融合向量 / 纯图向量已算条数（回填任务进行中会小于应算数） |
| `fused_target` / `pure_target` | int | 应算条数 |
| `deleted` | int | 本次对账删除的旧条目数 |
| `errors` | string[] | 本书入库中的错误摘要（最多 20 条），无错为空数组 |
| `tool_version` | string | 工作台版本 |

回填向量是后台任务，`fused_done` / `pure_done` 会在回填过程中多次更新本文件。

## 4. `catalog.csv`

`book_key` → 刊名、期号、刊期与处理决定。生成：`scripts/build_catalog.py <盘点 TSV> catalog/goout.csv`（盘点在 centos9 上对 `/opt/goout` 只读执行 `find` + `pdfinfo`）。`book_key` 与 `book_key_of` 同规则，单测 `book_key_matches_catalog` 逐行校验。

| 列 | 说明 |
|---|---|
| `order` | 处理顺序：由近到远，别册跟在对应年份的正刊后；无年份的别册排最后 |
| `book_key` | 同上；已处理的两本沿用旧键 `GoOut-16-07日本`、`goout-16-08日本` |
| `series` | 刊名 / 系列 → 清单 `magazine` |
| `kind` | `正刊` / `别册` / `合本` / `精选集` |
| `issue` | 期号 → 清单 `issue` |
| `issue_date` | `YYYY-MM-DD` 或空 → 清单 `issue_date`（空写 `null`） |
| `year` | 年份（GOLF OUT 等文件名带年份的别册有；正刊同 `issue_date`） |
| `pages` / `bytes` | 页数、字节数（盘点时） |
| `action` | `导入` / `跳过（合本）` / `已处理，沿用产出` / `待合成 PDF` |
| `channel_hint` | 按云端单本上限（200 页 / 200MB）预估的解析通道，仅供参考；实际在开始解析时判定 |
| `path` | 源 PDF 绝对路径（`/opt/goout/...` 只读；2019.12 合成到 `/data/magazines/`） |
| `note` | 备注（刊期待补、合本、精选集待定） |

别册刊期补齐后直接改 CSV 的 `issue_date`，重新生成该书清单即可（不需重新解析）。
