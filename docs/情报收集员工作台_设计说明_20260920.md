# 情报收集员工作台 · 设计说明（Web 客户端）

日期：2026-09-20，9/21 按流程确认稿第 14 版重写｜发出：开发｜状态：设计稿，征求意见｜配套：《情报收集员改造方案（概要版 / 开发版）》、流程设计图页、界面设计稿页

**一句话**：情报收集员从 Hermes agent 换成工作台——后端是一台常驻的 Rust 采集服务（内嵌 LanceDB），前面加一个 Web 工作台，让主编、研究员、Van 和开发在同一张判断台账上看到每天的全部候选、每条的结论档与逐维依据、对照材料与缺口，并把人的决定回收成记忆。流程可由引擎派单驱动，也可在工作台手动开启；引擎仍是唯一真相，工作台读引擎、写引擎，不另存一套流程状态。

---

## 1. 设计目标

| 目标 | 落在哪 |
|---|---|
| 整条流程看得见 | 每页顶部的流程带：0 派单或手动开启 → 1 开工 → 2 采集媒体信息 → 3 合并 → 4 对照材料 → 5 逐条判断 → 6 深核 → 7 登记与交付 → 8 首批校准 → 9 补件，每步状态、计数、耗时，可点开看产物与重跑 |
| 每天的候选一条不漏、每条都判 | 判断台账：窗口内全部图文贴文，每条一个结论档（推荐 / 备选 / 不推荐 / 待核）、六维度逐项判定与依据、三句话、对照结论、热度与标签、缺口 |
| 看图判断 | 每张图在采集时就有描述与用途判断；台账与详情直接看实图与图集；读不到图的如实标记 |
| 判断有据：知识库、已选记录、Van 框架三样必备 | 对照材料按五类分组展示：正式已发布、范例、生成过文章的贴文、03 决定、上一轮台账 |
| 不因口味淘汰，人可以随时捞回 | 台账按档分组，不推荐照样显示，硬性排除也能展开；一键捞回 |
| 人的决定沉淀为记忆 | Van 与主编在台账上的每次决定，连同当时的判断结论一起入库 |
| 缺什么说清楚 | 采集与覆盖页：采集方案、采集器、来源、过滤掉的视频贴文、识别覆盖、失败、待补录账号；待核结转页：缺口与期限 |
| 准则可调、可回测 | 判断框架页：维度定义、锚点（引用范例与被否案例）、案例；回测看 Van 的决定落在哪一档。不设权重 |
| 对开发透明 | 运行页：采集方案、服务状态（LanceDB、向量服务、Codex）、模型调用、耗时、费用、失败与重试、版本 |

## 2. 用户与场景

| 谁 | 什么时候来 | 主要动作 |
|---|---|---|
| 主编 | 每天 05:30 后到 07:00 前 | 看总览与台账；确认首批；捞回、改判；看覆盖与缺口；处理失败 |
| 研究员 | 首批之后 | 逐条评估推荐与备选档：逐维依据、对照材料五类、案例；补证或标待核 |
| Van | 07:15 前，以及她愿意的任何时候 | 看排序表直接勾选、否决、暂缓并留一句话；校准准则卡；查范例 |
| 开发 | 随时 | 运行状态、模型调用与费用、配置与版本、回放历史窗口 |

Van 的决定仍经引擎的 03 闸生效；工作台上的勾选先记为「Van 选择」并进入记忆库，主编据此提交选题方案。

## 3. 系统位置

<!-- FIG:system -->

- **采集服务**（Rust，agent 主机）：采集媒体信息、合并、对照材料、逐条判断、深核、登记、交付；内嵌 LanceDB 存知识库索引、候选与判断台账副本、图片；向量与重排调自部署的 Qwen3-VL 服务；同时提供工作台需要的本地接口（台账、线程记录、运行状态）。
- **工作台前端**（React + Vite + Tailwind，与管理后台同栈）：由采集服务托管静态文件；登录复用管理后台的用户与 JWT，角色沿用 superadmin / operator / viewer，另加「van」视图。
- **引擎**：任务、条目、采集轮、判断台账、交付物、刊发记录、决定、选题记忆的真相；工作台经采集服务代理读写。
- **管理后台**不变：定义、成员、监控。工作台不复制它的功能，只在需要时跳转。

## 4. 每日流程与工作台的对应

<!-- FIG:flow -->

| 流程步 | 工作台上看到什么 |
|---|---|
| 0 入口：引擎派单，或人在工作台手动开启 | 总览出现新一轮：任务驱动显示期次、任务号、派工单、作业标准与首批时限；手动开启显示发起人、采集方案、窗口、是否关联任务 |
| 1 开工 | 流程带全部步置「待开始」；作业标准可读；开工方式标明 |
| 2 采集媒体信息（只取图文；取候选、下载图片、识别、向量化一体） | 采集与覆盖页：跑了哪些采集器、各自数量与耗时、过滤掉的视频贴文数、下载成功率、识别进度与未识别清单；候选卡上每张图下一行描述 |
| 3 合并与窗口（按首次入库时间） | 台账里合并后的事件，展开可见合并了哪几条贴文；窗口外与「昨日已判」分组 |
| 4 对照材料（五类，缺一不判） | 事件卡的对照结论：同一事实无新增 / 同品牌有新增 / 不相干；展开看五类材料各命中什么、知识库同步到哪天 |
| 5 逐条判断（每条都判） | 台账按档分组：推荐 / 备选 / 不推荐 / 待核；六维度逐项判定与依据、三句话、热度与标签、缺口、看图标记 |
| 6 深核（推荐 + 待核，首批限 4–8 条、10 分钟） | 详情页的证据链接、原始披露时间、比较参照核实、完整图集；线程记录 |
| 7 登记与交付（有任务才写引擎） | 条目状态、校验结果、交付物链接；手动开启未关联任务的标「本地」并给「关联到任务」入口 |
| 8 首批校准 · 9 返工或补件 | 闸状态、退回原因；补件清单（每期合并一次） |
| 05 / 11 逐条任务 | 同一工作台接单，走「条目取单条」方案：任务清单与进度、每条的原图、描述与核验结果 |

## 5. 一条候选的状态

<!-- FIG:state -->

| 状态 | 含义 | 谁改 |
|---|---|---|
| 已采集 | 贴文取到，图片已下载、已识别、已向量化 | 代码 |
| 已合并 | 候选合并成事件，窗口按首次入库时间判定 | 代码（模型判同一事件可选） |
| 有对照材料 | 五类材料备齐；缺一样标「对照材料缺」并告警，不进判断 | 代码 |
| 推荐 / 备选 / 不推荐 / 待核 | 结论档，附六维度逐项判定与依据；不推荐照样保留 | 模型；人可改档 |
| 硬性排除 | 窗口外 / 与 03 否决的同一事实同角度 | 代码，可捞回 |
| 深核中 | 推荐与待核进深核，首批有时间盒 | 代码或人 |
| 已登记 | 已成引擎条目 | 代码 |
| Van 选择 / Van 否决 / Van 暂缓 | 她在台账上的标记，附原话；经主编代录成 03 决定后转为参考 | Van |
| 结转 / 关闭 | 待核转入后续期次，或到期关闭并写明原因 | 代码 |

## 6. 页面清单与内容

### 6.1 今日总览

- 顶部流程带：开工方式（任务驱动 / 手动）、期次或发起人、窗口、距首批时限倒计时；十格：0 派单或手动开启 → 1 开工 → 2 采集媒体信息 → 3 合并 → 4 对照材料 → 5 逐条判断 → 6 深核 → 7 登记与交付 → 8 主编校准 → 9 补件，每格状态、计数、耗时，点开看产物、失败清单与重跑按钮。多轮并行时（05 逐条任务、手动轮）显示轮次列表。
- 四张数字卡：**贴文全量**（取到 / 库内计数是否一致）、**只图文**（过滤掉含视频的数量）、**图片识别**（已识别 / 应识别）、**已判断**（应为 100%）。
- 告警：必扫采集器失败、对照材料缺、未识别的图、模型调用失败与重试、向量服务不可用、超时。
- 快捷入口：推荐档、待核、不推荐档里热度高的（提醒主编看一眼）、「手动开启一轮」。

### 6.2 判断台账（核心页）

- **列表行**：缩略图 1–2 张 · 品牌｜一句话标题 · 账号与发布时间 · **结论档** · 六维度逐项判定（成立 / 不成立 / 不明的小格） · **热度**（点赞、评论及相对该账号常态的倍数） · **csw 标签与话题** · 类型 · 对照结论 · 三句话状态 · 缺口数 · 状态 · 来源（系统 / Van 链接） · 操作。
- **左侧筛选**：档、类型、对照结论、三句话状态、来源、账号、标签、只看有图。
- **顶部工具**：分组（按档 / 按类型 / 按账号）、排序（档 → 成立维度数 → 热度 → 时间，由代码算）、导出。没有权重、没有综合分。
- **展开行**：六维度依据各一句、三句话全文、热度与标签、缺口、合并的贴文清单、**对照材料按五类分组**（正式已发布命中、范例命中、生成过文章的相似贴文、03 决定里的相似案例与原话、上一轮台账）。
- **操作**：加入首批 / 登记条目 / 标待核 / 捞回 / 改档（记录人与理由）。
- **Van 模式**：只显示品牌、标题、图、三句话与结论档；每行三个按钮「采用 / 否决 / 暂缓」和一格原话；她的标记即时写入记忆库并在主编视图上显示。
- **默认分组**：按档；不推荐照样列出；硬性排除折叠在底部分组，随时展开。

### 6.3 事件详情

- 左：完整图集，每张图下一行描述与用途判断（产品图 / 细节图 / 使用场景 / 海报或文字图 …，可否作配图）；所有合并贴文的原文、译文、账号、粉丝、点赞、评论、标签、话题；原始披露时间与转载时间。
- 中：结论档；六维度逐项判定与依据；三句话；热度与标签；缺口清单。
- 右：对照材料五类分组（正式已发布：旧文标题、日期、角度、是否有新增；范例：像哪一条；生成过文章的贴文：相似的选过并成文的；03 决定：相似案例与原话，含否决；上一轮台账）；深核结果（证据链接、核实的事实、比较参照是否准确）。
- 底：审计——每次模型调用的阶段、耗时、token、模型版本、准则版本；人工操作记录。

### 6.4 采集与覆盖

- 采集方案：本轮用的方案（日更采集 / 条目取单条 / 自定义）与采集器清单；每个采集器一行：来源、取到、只图文、图片、已识别、耗时、结果与失败原因。
- 来源台账：必扫来源的状态、最近成功时间；Van 补充的来源标为普通来源。
- 待补录账号清单：出现在选题里却不在册的账号，各自依据（哪篇推文 / 哪天指定），一键导出。
- 图片：下载成功率、未识别的图与原因、可重试。

### 6.5 待核结转

- 列表：事件、缺口类型（缺发售日期 / 缺官方来源 / 图不足 / 读不到图）、首次出现期次、剩余期数、上次重评结果。
- 操作：补证后重评、人工关闭并写原因。

### 6.6 知识库

- 检索：LanceDB 向量 + 全文（jieba）混合召回，Qwen3-VL 重排；输入文字或一张图；结果按五类参考分组，每条带发布状态、日期、出处、原话。
- 品牌页：该品牌的历史报道时间线、角度、近 30 / 90 天是否发过；她选过并成文的同品牌贴文。
- 同步状态：刊发记录同步到哪一天、生成过文章的贴文同步时间、索引里的向量数、向量服务状态、失败记录。
- 范例：十篇（41 条、225 图）的逐条拆解与每张图的说明，标注哪些是待核推断。

### 6.7 选题记忆

- 准则卡：每条规则 · 身份（具体案例 / 模型推断 / 本人确认） · 原话与日期 · 对象与适用条件 · 状态。
- 案例库：候选摘要、结论、原话、关联的贴文与期次。
- 覆盖清单：回收了哪些会话库、时段，哪些读不到。
- **Van 校准模式**：逐条「对 / 不对 / 改成……」，提交后规则升级为「本人确认」。
- 写作表达一线在此只显示入口，内容交主编与文案页面。

### 6.8 判断框架与锚点

- 核心问题「这件事有没有足够具体的变化，值得 CSW 帮读者解释一次」；六个维度的定义与「成立 / 不成立 / 不明」的锚点，引用范例条目与被否案例。
- 优先七类与降低七类；csw 标签到优先 / 降低提示的映射（如营业时间、选品 → 降低）。
- 版本表：准则与锚点的版本、生效期次、谁改的、为什么。不设权重。
- 回测：用历史上 Van 的决定，看当前准则下这些条目落在哪一档（采用的应多在推荐 / 备选，否决的应多在不推荐）；重复判断一致性。

### 6.9 指标

- Van 的三项：自主发现情况（采用条目里系统先于她发现的比例）、第一轮推荐质量（首轮推荐数 / 采用数 / 补选轮次）、她的实际投入（审题用时、补链接次数、补充说明次数）。
- 技术指标：审阅覆盖、看图覆盖、来源覆盖、召回、01 用时。
- 按期次折线，可选区间。

### 6.10 运行与设置

- 服务状态：采集服务、LanceDB（向量数、目录大小、最近写入）、Qwen3-VL 向量与重排服务、Codex App Server、csw 后端连接；版本固定情况。
- 模型调用：按阶段（识别、判断、深核）的次数、耗时、token、费用；失败与重试；线程记录下载。
- 采集方案：日更采集 / 条目取单条 / 自定义方案的采集器清单、顺序、参数、必扫与启停；改动存版本、写审计。
- 手动开启：选方案、窗口、参数、是否关联已接单任务，点开始；发起人与参数写审计。
- 设置：来源台账维护、并行数、待核结转期限、首批深核条数与时间盒（改动写审计）。
- 回放：选一个历史窗口重跑采集与判断，可指定知识库版本，用于调准则与验收。

## 7. 数据来源与接口

| 页面数据 | 来源 |
|---|---|
| 贴文、媒体 | csw 新接口 `posts/window`（经采集服务）；图片走 OSS 缩略参数 |
| 事件、结论档、逐维依据、缺口、对照结论 | 引擎 `intake_judgements`（真相）+ 采集服务 LanceDB（进行中的） |
| 采集轮、来源台账、条目、交付物 | 引擎既有接口 |
| 知识库检索、相似已选贴文 | 采集服务 `/kb/*`（LanceDB 向量 + 全文 + Qwen3-VL 重排） |
| 刊发记录、决定、记忆、准则 | 引擎 `/ledger/*`、`/memory/*`、`/rubric/*` |
| 线程记录、模型调用、服务状态 | 采集服务本地接口 |
| Van 与主编的标记 | 写引擎（条目决定、反馈记录），同步进记忆库 |

工作台不直接连 csw 后端与模型服务；所有外部访问都经采集服务。

## 8. 权限

| 角色 | 能做 |
|---|---|
| viewer | 只读全部页面 |
| operator（主编、研究员） | 台账操作、改档、待核处理、来源维护、手动开启一轮、回放 |
| superadmin（开发） | 以上加采集方案、准则版本、设置、服务操作 |
| van | Van 模式的台账、准则校准、范例与指标；只给链接，不开轮；不显示运行与设置 |

所有写操作记录操作者与时间，可在事件详情底部与审计里看到。

## 9. 技术要点

- 采集服务 `csw-task/csw-collector/`：**Rust**（axum + LanceDB + reqwest），单个静态二进制，systemd 常驻；Codex App Server 协议与客户端直接用 codex 仓库的 crate，MCP 用官方 rmcp；LanceDB 单进程写入，采集服务独占数据目录。
- 前端 `csw-task/csw-collector-web/`：React 18 + Vite + TypeScript + Tailwind，与管理后台同栈；表格虚拟滚动（一天几百条）；按档分组与排序在前端完成；图片懒加载。
- 采集服务提供 `/ui/*` 静态托管与 `/api/*` 本地接口；JWT 校验复用管理后台的密钥。
- 台账的每一次人工操作都是幂等写引擎，带 `Idempotency-Key`。
- 手机宽度可用：台账在窄屏下按卡片排列，Van 模式优先适配手机。

## 10. 需要拍板

1. 工作台由采集服务托管、复用管理后台登录——还是并入管理后台成为一组新页面。
2. Van 在台账上的勾选是否直接等同于 03 闸的决定，还是只作「Van 选择」由主编提交。
3. 第一期只做哪些页面：建议总览（含流程带）、判断台账、事件详情、采集与覆盖、待核结转、运行与设置（采集方案与手动开启）六页先上，其余随知识库与记忆建设推进。
4. 手动开启的权限：operator 与 superadmin 可开，Van 模式只给链接不开轮；手动轮结果关联任务时一律以补件提交。
